## 3. 全レーン共通の型（SNS_VIDEO_PLAN.md「シリーズに共通の型」の要約）

1. **冒頭3秒は問いだけ**。答えを先に言わない
2. テロップは **問い → ①②③の手順見出し → 太字の答え** の3層。無音で筋が追えること
3. **締めは「実際に使ってみて」にする。**（2026-08-12・ユーザー判断で差し替え）
   **チャンネル登録を頼むのをやめ、アプリを触ってもらう誘い**に変えた。
   ナレーション「**じっさいに自分でも、さわってみてほしいのだ**」／
   テロップ「**自分でも触ってみて**」。
   **既存の「無料・インストール不要」は残す。**

   > **なぜ変えたか（経緯）**: 2026-08-04 の実数では
   > 28日で視聴8,646回に対し**チャンネル登録は +7（0.08%）**と低く、
   > 「締めがアプリ誘導だけで登録を頼んでいない」と読んで**登録を頼む一言**を足していた
   > （V65 以降）。だが**目的はアプリの利用**であって登録者数ではない。
   > 登録は「また見てくれる人」を増やす間接の手だが、
   > **1.7%（視聴8,646→セッション146）という入口の細さに直接効くのは、
   > 締めでアプリを触ってもらうこと**——という判断で戻した。
   > **在庫15本（V71〜V86）は全部この形で撮り直した**（2026-08-12）。
   > **投稿ずみの V65〜V70 は登録を頼む形のまま**なので、効果を比べる材料になる。
3b. **最後に次回予告を1行**
4. `meta/<ID>.json` に **`series`** を必ず入れる（mux が投稿導線のチェックリストを自動で出す）
5. シリーズのハッシュタグを**各媒体の先頭**に。**X だけは `x.text` の末尾に手書き**

7. 尺は **30〜45秒**を狙う（20〜40秒が最も視聴維持率が高いという市場調査に寄せる）

## 4. 手順（詰まりやすい所だけ。詳細は V6.md §5 / V11.md §5）

1. **ナレーションを先に作る**（`narration/<ID>.json` → `python video-scripts/narrate.py …`）。
   **出力される読み仮名を必ず確認**。既知の誤読:
   環→たまき／主鎖→しゅくさり／エチル基→エチルもと／カルボキシ基→カルボキシもと／
   **鏡像→カガミゾオ**（2026-08-01・V31）／**置換基→チカンモト**・**塩→シオ**（同・V19）／
   **ベンゼン環→ベンゼンタマキ**・**六角形→ロッカッケー**（同・V32/V40）／
   **濃硝酸→コショオサン**・**濃硫酸→コリュウサン**（同・V40）。
   **「置換基」はひらがな `ちかんき` もダメ**（`チ'/カ'ンキ` と2語に割れる）。**カタカナ「チカンキ」**が正解。
   **「◯◯基」は全部「モト」と読まれる**と思ってよい（メチル基→メチルモト・エチル基→エチルモト。
   2026-08-02・V10 で確認）。**カタカナで「メチルキ」「エチルキ」**と書けば正しく読む＝
   「基」を含む語は一律この形にする。**テロップは漢字の「基」のまま**でよい。
   **誤読するものは仮名で書く**（`きょうぞう`・`ナトリウムえん`・`そくさ`・`ふせい` など）。
   **「けん化」は正しく読むが音が「喧嘩」と同じ**なので、テロップに漢字を必ず出すこと。
   **3桁の数字は漢数字でも2語に割れる**——「180度」も「百八十度」も `ヒャク'/ハチジュウ'ド`＝
   「百、八十度」に聞こえる。**ひらがなで `ひゃくはちじゅう度`** と書くと1語になる
   （2026-08-02・V51。2桁の「九十度」は漢数字のままで正しく読む）。
   **助詞を直付けすると語が割れることがある**——「かんのうき**は**」は `カンノ'/ウ_キハ'` と
   途中で切れて聞こえた（単体の「かんのうき」は正しく読む）。**仮名化では直らない型**で、
   **助詞を変える**と直る（「かんのうき**が**」でよくなった。2026-08-02・V33）。
   **位置番号は正式名称どおりに読ませる**（`2-プロパノール` ＝ **にープロパノール**）。
   「に」が短くて埋もれるからといって **「にばん」などと補ってはいけない**——
   **命名法にない読みになる**（2026-08-01 の検品指摘。V22 で実際に踏んだ）。
   聞き取りにくさは**テロップに数字を出して補う**
2. **各行の秒数から `wait` を逆算する**。
   `wait =（その行の秒数＋0.6）−（アクションの実測コスト合計＋1.13）`

   | アクション | 実測コスト（等速） |
   |---|---|
   | `button`（右パネル内＝シートを開く） | 1.34s |
   | `summon`（シートが開いている状態から） | 1.01〜1.09s |
   | `summon`（シートが閉じている＝直前が `frame`） | 1.46s |
   | `reactionButton`（シート開＋クリック＋モーフィング） | 1.52s |
   | `frame`（シートを閉じる＋構図） | **0.27s**（シートが既に閉じているとき。開いていれば +0.35s） |
   | `#btn-clear-all` | 0.46s |
   | **ステップ間の固定オーバーヘッド** | **1.13s** |

   **この表は初期値であって正解ではない。** 実測すると回によって 0.4〜0.75秒/ステップ小さいことがある
   （2026-08-01・V22）。**設計値のまま組むと最後で数秒ずれる**ので、
   **1回撮って `--events` から詰め直す前提**で使うこと

   作図が多い回は `--speed` を上げる（wait も速度で割られるので「静止させたい秒数 × 速度」を ms で書く）

   **`frame` の縦の見え幅は `width × 3/4` ではない。実測で `width × 約1.59`**
   （SVG が 4:3 より縦長で meet 合わせになるため。2026-08-01・fg レーン）。
   **縦の構図は計算で決めず、「名称チップに分子が被らないか」をフレームで見て決める**
2b. **【作図の回は必ず】下見を先に通す** → `node tools/record/probe.mjs --demo=<id>`
   台本のアクションだけを無音・無録画で流し、**結末の原子・結合・名称・分子式**を数秒で刷り出す。
   **クリックした座標に原子は落ちない**（ほぼ毎回 28px か 42px の斜めへスナップする）ので、
   **`clickBond` の中点は落ちたあとの座標で引き直す**（外れると黙って1手抜ける。許容 14px）。
   **分子式が合っていても構造が違うことがある**（V82 はアミドのつもりがエーテルだった）ので、
   **結合まで目で読む**こと。ライブラリに登録する回は `--emit` で `target` をそのまま吐かせる
   ＝ **登録する図と動画で描く図が必ず一致する**（手で座標を写さない）。
   2026-08-12 の9本（V76〜V84）は、この順にしたので**収録を1本も無駄にしていない**。
2c. **【自由な場所にモジュールを置く回だけ】収録の経路でも下見する。**
   **同じ台本が `?mode=free` と `?rec=` で 42px（グリッド1つぶん）ずれる**
   （`frame` で構図を寄せてから、近くに原子が無い場所へモジュールを置いたとき。
   2026-08-12・V85 ニコチンで踏んだ。ORDER_drawing_hit_areas.md §2e）。
   **下見が通ったのに収録だけ違う**という、いちばん気づきにくい形の失敗になる。
   原子を既存原子のそばに置く操作は影響を受けないので、**ふつうの回は 2b だけでよい**。
2d. **置く操作で終わるステップは、必ず選択ツールへ戻してカーソルを図の外へ出す**
   （`#btn-tool-select` ＋ `hover`）。**モジュールや原子のツールを持ったままだと、
   青いガイド（プレビュー）がその後の待ち時間じゅう出っぱなしになる**
   （2026-08-12 のユーザー検品で、在庫のほぼ全本に同じ指摘が出た）。
   §8 の「反応後のオレンジのハイライト」と同じ型だが、**こちらは置く操作のたびに起きる**。
   ⚠ **`hover` の行き先は「空き地」ではなく「既存の原子の上」**（7h）。
   自由配置が入ってから、空き地はどこでも灰色のゴーストが出るようになった。
3. **収録** → `node tools/record/record.mjs --demo=<id> --format=short --base=http://localhost:<自分のポート>/assembler/`
3b. **撮ったら `node tools/record/timing.js <ID> <demo-id>` でずれを実測して `wait` を直し、もう一度撮る。**
   `wait` の見積もり（行の秒数 × 2000 −操作コスト）は**手数の多い回ほどずれが積もる**——
   実測すると1ステップ 0.1〜0.2秒で、6ステップで 0.7〜0.9秒の食い違いになっていた
   （ユーザー検品「全体的にナレーションとアニメーションがずれている」）。
   **events.json には本物の時刻が入っている**ので、そこから引き直せば見積もりに頼らずに済む。
   **2回撮れば ±0.3秒に収まる**（1回目で直し値を出し、2回目で確定）。
4. **`--events` の時刻とナレーションの累積秒を突き合わせる**。
   テロップは**声より 0.1〜0.4秒あと**に出るのが正解（早いと答えを先に見せてしまう）
5. **書き出し** → `mux.mjs … --trim=auto --lead=0.3 --size=1080x1920`。
   **`--lead=0.3` を付ける**（既定 1.5 だと最初のテロップが1.5秒遅れてフックを捨てる）
6. **完成 mp4 のフレームを抜いて目視する**（`ffmpeg -ss <秒> -i <mp4> -frames:v 1 out.png`)。
   ffmpeg は `python -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"` で場所が出る
7. **`reactionButton` の直後には必ず `frame` を置く**（置かないとシートが開いたままで生成物が隠れる）
7b. **最後のカードは音より長く出す。** `mux --trim=auto` は**「音の終わり＋1秒」で切る**ので、
   最終ステップの `wait` を音ぴったりにすると**次回予告が早く消える**（2026-08-01・V22 で0.6秒消えた）。
   **さらに `--events` から計算した位置は、焼き上がった動画より 0.5〜1.0秒うしろを指す**
   （2026-08-01・V19 で判明。`--trim=auto` の頭出しが行き過ぎるため）。
   **計算上ぴったりでも実物では尻が切れる**ので、**最終ステップの `wait` は1.5秒ぶん多めに取り、
   焼き上がった mp4 の末尾フレームを必ず目視する**こと
7c. ~~既存の原子に隣接しない位置には原子を置けない~~ → **置けるようになった**（自由配置・要望D）。
   離れた空き地をクリックすると**新しい分子として**始まる。おかげで
   **1画面に分子をいくつも並べられる**（下の 7f）。⚠ 代わりに**空き地はどこでも
   「ここに置けます」の対象**になったので、カーソルの逃がし先が問題になる（7h）
7d. **`#btn-clear-all` は `fitCanvasToTarget()` を呼んで構図を壊す**。直後に `frame` を置き直す。
   `undo` は viewBox を触らない
7e. **「全体表示」（`#btn-reset-view`）は自由モードでは効かない。** 中身は
   `fitCanvasToTarget()` ＝ **お題に合わせる**関数で、お題の無い自由モードでは何も起きない。
   呼び出した分子や反応の生成物が画面から出たままになる
   （2026-08-12 ユーザー検品「右側のエタノールが見切れている」「生成した CHI₃ が見切れている」）。
   **自由モードの構図は `frame` で決める**。`cx`/`cy` を省くと**いま置いてある分子ぜんぶの中心**に寄る:
   `{"type":"frame","width":540}`。幅は実測から決める（`tools/record/probe.mjs` で原子の座標が出る）
7f. **分子を並べて見せるときは、画面の下 55% に収める。** 収録モードの名称チップ
   （`.rec-short #mobile-name-chip`）は**画面の上から 23% に固定**で出るうえ、
   分子が3つ4つあると「① … ＋ ② … ＋ ③ …」と**3〜5行に伸びて**いちばん上の分子にかぶる。
   目安（810×1440 で撮る場合）: 被写体は画面 y=520〜1200px の帯に入れる。
   逆にこのチップは**並べた分子の名前を全部読み上げてくれる**ので、
   異性体シリーズでは「並べる」こと自体が答え合わせになる（V90 で採用）
7g. **並べる行の `y` は 42（`GRID_SIZE`）の倍数にする。** キャンバスが空のときの1原子目だけは
   格子へスナップするので、`y=150` と書くと分子ぜんぶが `y=168` に落ちる。
   `clickBond` の中点は台本の数字で書くから最大 21px ずれ、許容 14px を超えて
   **二重結合が1本だけ黙って抜ける**（2026-08-12・V90 の①が 2-メチルブタンになっていた）
7h. **カーソルの逃がし先は「既存の原子の上」にする。** 7c のとおり空き地はどこでも
   置ける＝**灰色のゴーストが出たまま**になる（原子から 130px 離しても出る）。
   `handleMouseMove` でオーバーレイを消す枝に入るのは**原子の 18px 以内**だけなので、
   `{"type":"hover","x":<原子のx>,"y":<原子のy>}` と原子の座標そのものを書く（2026-08-12）
8. **反応のあとのオレンジのハイライトは、全消去でも呼び出しでも消えない**（2026-08-01・V19 で判明）。
   `clearUIOverlay()` が呼ばれるまで座標そのままで残るので、次の分子の上に**前の反応のハイライトが
   貼りついたまま写る**。`#btn-clear-all` の直後に `hover` を1つ置くと、
   選択ツールが `select` のときプレビューを描かずにオーバーレイだけ消える（実測コスト 0.79秒）。
   **1本の動画で反応を実行したあと別の分子を出す回は、必ずこれを入れる**

### 公開前の必須チェック: 構造式が誤読されないか

**名称チップが正しくても図が正しいとは限らない。** 名称は結合から計算されるので、
配置が壊れていても正しい名前が出る（2026-08-01 に V6・V18 でこれを踏んだ。V18.md §3）。
**キャンバスに目的の分子を出した状態で、実機のコンソールで次を流し、空配列であることを確かめる**:

```js
const m = window.game.userMolecule, byId = Object.fromEntries(m.atoms.map(a=>[a.id,a]));
const heavy = m.atoms.filter(a=>a.element!=='H'), bad=[];
for (const b of m.bonds) { const p=byId[b.atomId1], q=byId[b.atomId2];
  for (const a of heavy) { if(a.id===p.id||a.id===q.id) continue;
    const L2=(q.x-p.x)**2+(q.y-p.y)**2; if(!L2) continue;
    const t=((a.x-p.x)*(q.x-p.x)+(a.y-p.y)*(q.y-p.y))/L2; if(t<=0.02||t>=0.98) continue;
    if (Math.hypot(a.x-(p.x+t*(q.x-p.x)), a.y-(p.y+t*(q.y-p.y))) < 16)
      bad.push(`${p.element}-${q.element} が ${a.element}(${a.x},${a.y}) を貫通`); } }
bad
```

## 5. レーンごとのネタ（実現可能性つき。◎＝実機確認済 ○＝機能は実在・未実測 △＝要検証）

### isomer（異性体・V20番台）

**数え上げは C₇H₁₆ で打ち止め済み**。同じ型を続けず、視点を変えること。

**「N種類」と言ったら N 個ぜんぶ描く**（2026-08-12 ユーザー検品「まとめている部分は3つ並べる」）。
1つだけ描いて「あと2つある」で済ませると、いちばん見たい所を飛ばすことになる。
**並べ方は2通り**——ⓐ **画面に同時に並べる**（自由配置。名称チップが「① … ＋ ② … ＋ ③ …」と
全部の名前を出すので、答え合わせがそのまま絵になる。構図は §4 の 7f・7g）／
ⓑ **同じ骨格で違いだけ差し替える**（`undo` → 別の結合を `clickBond`。V96 方式）。
枝の位置だけが違う異性体は**ⓑ で骨格を使い回せる**（C₅H₁₀ のメチルブテン3種は
二重結合の場所を変えるだけで全部出る）。手数が増えるぶんはステップ内 `speed` で早送りする。

- **C₄H₈は何種類？** アルケン4＋シクロアルカン2。「鎖だけ数えると足りない」＝不飽和度の入口 ○
- **同じ？違う？** 同じ違うクイズ（`#btn-quiz-same` / `#btn-quiz-diff`）。**出題ストック無限・制作最速**。
  当たれば独立シリーズに切り出す価値あり ◎
- **o / m / p** 位置異性体。p-ジクロロベンゼン等が収録済み ○
- **C₃H₈O は3種類** V9 の縮小版。25秒級の差し込み用 ◎
- **名前が言えれば描ける** 命名クイズ（`#btn-naming`）。枝の位置の付け方 ○

## 6. コミットの作法（この作業ツリーは並行セッションと共有している）

- **必ずパス限定コミット**: `git commit -F <メッセージファイル> -- <パス>`。
  新規ファイルがある回は `git add <新規ファイルのみ> && git commit -F … -- <パス>` と**1コマンドで連結**
- **`git commit -a` と `git commit --amend` は使わない**（`--amend` は HEAD が自分のものである保証がない。
  2026-08-01 に実際に他セッションのコミットメッセージを壊した）
- 1修正=1コミット。メッセージ本文に**何をどう検証したか**を書く
- **`demos-*.json` と `video-scripts/**` しか触らないなら `?v=` は据え置き**でよい。
  アプリのコード（js/css/html）に手を入れたら版を上げて `node tools/verify-release.js assembler` を通す
- コミット前に **test.html 全テスト合格**を確認する

**検品で出た指摘は `video-scripts/REVIEW_2026-08-01.md` にまとめてある。**
自分のレーンの項目に着手する前に必ず読むこと。

## 7. 承認を求められにくい書き方（2026-08-01）

`.claude/settings.json` に**動画レーンが叩くコマンドの許可リスト**を置いた（4つの worktree すべてに効く）。
承認が出るかどうかは**コマンドの見た目**で決まるので、次の書き方を守ると止まらずに進む。

- **同じ形のコマンドを使う**。許可してあるのは
  `node tools/record/record.mjs …` / `node tools/record/mux.mjs …` / `node tools/frames.js …` /
  `node tools/videos.js` / `python video-scripts/narrate.py …` /
  読み取り系の git（status・log・diff・show・branch・worktree list）/ `git add` `git commit` `git merge`
- **フレームの目視は `node tools/frames.js <mp4> --steps`** を使う。
  ffmpeg を長い1行で直接叩くと形が毎回変わり、そのたびに承認になる
- **JSON やテキストの編集に `python -c` や heredoc を使わない**。**Edit / Write ツールを使う**。
  シェル経由の書き換えは任意コード実行なので許可リストに載せられない（載せると許可の意味が薄れる）
- **禁止（deny に入れてある。プロンプトすら出ずに落ちる）**:
  `git commit --amend` / `git commit -a` / `git reset --hard` / `git checkout --ours|--theirs` / `rm -rf`。
  いずれもこのリポジトリで**実際に事故が起きた操作**（--amend は他セッションのコミットを壊した）
- **`git push` は許可リストに入れていない**。公開に直結するので毎回聞かれるのが正しい

### ⚠ `state` に手で座標を書くと、ライブラリの直しが届かない（2026-08-03・V31 で発生）

**`state` を積むデモは `compounds.json` / `stages.json` を一切見ない。**
そのため**アプリ側で構造式を直しても、その回だけ古い図のまま残る**。

実例: C-4b でアミノ酸の主鎖を一直線に直した（v345）が、V31 のデモは手書きの `state` で
**アミノ基が斜め**（N 328,270 / α炭素 358,300）のままだった。**ユーザーの検品で見つかった。**
ライブラリ側は N (316,300) ＝ 水平で正しかった。

**対策**: `state` を書くときは**必ずライブラリの座標をそのまま写す**。
手で置き直すのは、間隔を広げるなど**平行移動だけ**にする（V32 が採った形）。
**結合の向きを変えたくなったら、それはライブラリ側を直す話**なのでアプリ改修へ回す。
