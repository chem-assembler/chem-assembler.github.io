## 3. 全レーン共通の型（SNS_VIDEO_PLAN.md「シリーズに共通の型」の要約）

1. **冒頭3秒は問いだけ**。答えを先に言わない
2. テロップは **問い → ①②③の手順見出し → 太字の答え** の3層。無音で筋が追えること
3. **最後に次回予告を1行**
4. `meta/<ID>.json` に **`series`** を必ず入れる（mux が投稿導線のチェックリストを自動で出す）
5. シリーズのハッシュタグを**各媒体の先頭**に。**X だけは `x.text` の末尾に手書き**
6. 前作とは固定コメント／スレッドでつなぐ
7. 尺は **30〜45秒**を狙う（20〜40秒が最も視聴維持率が高いという市場調査に寄せる）

## 4. 手順（詰まりやすい所だけ。詳細は V6.md §5 / V11.md §5）

1. **ナレーションを先に作る**（`narration/<ID>.json` → `python video-scripts/narrate.py …`）。
   **出力される読み仮名を必ず確認**。既知の誤読: 環→たまき／主鎖→しゅくさり／エチル基→エチルもと／
   カルボキシ基→カルボキシもと。**誤読するものは仮名で書く**
2. **各行の秒数から `wait` を逆算する**。
   `wait =（その行の秒数＋0.6）−（アクションの実測コスト合計＋1.13）`

   | アクション | 実測コスト（等速） |
   |---|---|
   | `button`（右パネル内＝シートを開く） | 1.34s |
   | `summon`（シートが開いている状態から） | 1.01〜1.09s |
   | `summon`（シートが閉じている＝直前が `frame`） | 1.46s |
   | `reactionButton`（シート開＋クリック＋モーフィング） | 1.52s |
   | `frame`（シートを閉じる＋構図） | 0.66s |
   | `#btn-clear-all` | 0.46s |
   | **ステップ間の固定オーバーヘッド** | **1.13s** |

   作図が多い回は `--speed` を上げる（wait も速度で割られるので「静止させたい秒数 × 速度」を ms で書く）
3. **収録** → `node tools/record/record.mjs --demo=<id> --format=short --base=http://localhost:<自分のポート>/assembler/`
4. **`--events` の時刻とナレーションの累積秒を突き合わせる**。
   テロップは**声より 0.1〜0.4秒あと**に出るのが正解（早いと答えを先に見せてしまう）
5. **書き出し** → `mux.mjs … --trim=auto --lead=0.3 --size=1080x1920`。
   **`--lead=0.3` を付ける**（既定 1.5 だと最初のテロップが1.5秒遅れてフックを捨てる）
6. **完成 mp4 のフレームを抜いて目視する**（`ffmpeg -ss <秒> -i <mp4> -frames:v 1 out.png`)。
   ffmpeg は `python -c "import imageio_ffmpeg;print(imageio_ffmpeg.get_ffmpeg_exe())"` で場所が出る
7. **`reactionButton` の直後には必ず `frame` を置く**（置かないとシートが開いたままで生成物が隠れる）

### 公開前の必須チェック: 構造式が誤読されないか

**名称チップが正しくても図が正しいとは限らない。** 名称は結合から計算されるので、
配置が壊れていても正しい名前が出る（2026-08-01 に V6・V18 でこれを踏んだ。V18.md §3）。
**キャンバスに目的の分子を出した状態で、実機のコンソールで次を流し、空配列であることを確かめる**:

```js
const m = window.game.userMolecule, byId = Object.fromEntries(m.atoms.map(a=>[a.id,a]));
const heavy = m.atoms.filter(a=>a.element!=='H'), bad=[];
for (const b of m.bonds) { const p=byId[b.atomId1], q=byId[b.atomId2];
  for (const a of heavy) { if(a.id===p.id||a.id===q.id) continue;
    const L2=(q.x-p.x)**2+(q.y-p.y)**2; if(!L2) continue;
    const t=((a.x-p.x)*(q.x-p.x)+(a.y-p.y)*(q.y-p.y))/L2; if(t<=0.02||t>=0.98) continue;
    if (Math.hypot(a.x-(p.x+t*(q.x-p.x)), a.y-(p.y+t*(q.y-p.y))) < 16)
      bad.push(`${p.element}-${q.element} が ${a.element}(${a.x},${a.y}) を貫通`); } }
bad
```

## 6. コミットの作法（この作業ツリーは並行セッションと共有している）

- **必ずパス限定コミット**: `git commit -F <メッセージファイル> -- <パス>`。
  新規ファイルがある回は `git add <新規ファイルのみ> && git commit -F … -- <パス>` と**1コマンドで連結**
- **`git commit -a` と `git commit --amend` は使わない**（`--amend` は HEAD が自分のものである保証がない。
  2026-08-01 に実際に他セッションのコミットメッセージを壊した）
- 1修正=1コミット。メッセージ本文に**何をどう検証したか**を書く
- **`demos-*.json` と `video-scripts/**` しか触らないなら `?v=` は据え置き**でよい。
  アプリのコード（js/css/html）に手を入れたら版を上げて `node tools/verify-release.js assembler` を通す
- コミット前に **test.html 全テスト合格**を確認する
