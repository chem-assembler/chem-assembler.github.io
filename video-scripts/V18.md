## 3. 一度は公開を止めた作図バグと、その解決（2026-08-01）

### 何が起きていたか

**反応が生成した原子を 42px 刻みで置くのに対し、母体の分子は 80px 刻みで描かれていたため、
新しい原子が既存の結合線の上に乗っていた。** 結果、結合線が非結合の原子を貫通し、
**構造式が別の物質に見えた**。当時の実測値:

```
原子: C(360,300) C(440,300) O(440,220) C(322,300) C(402,300) O(482,300)   ＋ 水 O(546,210)
結合: C(360)-C(440) / C(440)=O(440,220) / C(322)-C(402) / C(402)-O(482) / O(482)-C(440)
```

**結合は正しかった**（CH₃-C(=O)-O-CH₂-CH₃ ＝ 酢酸エチル。名称チップも「酢酸エチル」）。
壊れていたのは**配置**で、y=300 上に x=322, 360, 402, 440, 482 の5原子が並ぶのに、
結合は隣どうしではなく飛び越してつながっていた（`C(360)-C(440)` が C(402) を貫通、など）。
**画面には「C-C-C-C(=O)-O」＝酪酸（ブタン酸）に見える図**が出ていた。

同じ原因で **V6 の最後の答えの画（酢酸）も壊れていた**。2つの酸素が両方とも C(440) の右の
同一直線上にあり（+42 と +80）、C=O の二重線が -OH の酸素を貫通していた。

呼び出しただけの分子は compounds.json の配置をそのまま使うので無傷だった（**V11 は影響なし**）。

### どう直ったか

**`b86b9c1 fix(reactor): 反応の生成物を母体と同じ刻みで置く（v341）`**。
分子が実際に描かれている結合長の中央値を返す `bondStep()` を足し、reactor.js の配置系を
すべてこれに合わせた（クリアランスも同じ刻みから求める）。

**v342 で実機再検証・貫通ゼロ**（§4 のチェックを実行し `[]`）。結合長は全て 80px。

| 酢酸エチル | y=300 に5原子が一直線・3本が貫通 | C(360,300) C(440,300) O(440,220) ＋ C(280,380) C(360,380) O(440,380) の**2段のL字**・貫通ゼロ |
| 水（副生成物） | O(546,210) | O(640,240) |

## 4. 検算のしかた（今後の反応回で必ずやる）

生成物の図が信用できるかは、**結合線と非結合原子の距離**を測れば機械的に分かる。
実機のコンソールで次を流す（`< 16` は原子の半径 17 に合わせた閾値）:

```js
const m = window.game.userMolecule, byId = Object.fromEntries(m.atoms.map(a=>[a.id,a]));
const heavy = m.atoms.filter(a=>a.element!=='H'), bad=[];
for (const b of m.bonds) { const p=byId[b.atomId1], q=byId[b.atomId2];
  for (const a of heavy) { if(a.id===p.id||a.id===q.id) continue;
    const L2=(q.x-p.x)**2+(q.y-p.y)**2; if(!L2) continue;
    const t=((a.x-p.x)*(q.x-p.x)+(a.y-p.y)*(q.y-p.y))/L2; if(t<=0.02||t>=0.98) continue;
    if (Math.hypot(a.x-(p.x+t*(q.x-p.x)), a.y-(p.y+t*(q.y-p.y))) < 16)
      bad.push(`${p.element}-${q.element} が ${a.element}(${a.x},${a.y}) を貫通`); } }
bad
```

**名称チップが正しくても図が正しいとは限らない**。名称は結合から計算されるので、
配置が壊れていても正しい名前が出る。**この回はそれで危うく公開しかけた。**
