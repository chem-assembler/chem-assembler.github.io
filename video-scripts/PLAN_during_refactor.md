# アプリ改修中の並列作業計画（2026-08-01）

改修セッションが `REVIEW_2026-08-01.md` の C 群を進めている間、動画レーンが**手戻りなく**進める範囲。

## 前提: 改修の影響を受けるのは「収録した映像」だけ

| 工程 | 改修の影響 |
|---|---|
| 台本（`V*.md`） | **なし** |
| ナレーション原稿・音声（`narration/`・`audio/`） | **なし** |
| 投稿文（`meta/`） | **なし** |
| デモ台本（`demos-*.json`） | 座標を書く回だけ影響 |
| **収録（record）** | **あり** ← ここだけ |
| 書き出し（mux） | 収録し直せば済む |

**したがって「収録以外を全部先に済ませる」が最も安全な並列策**。改修が終わったら
収録と mux だけ（1本あたり10〜15分）で完成する。

## 既存デモの依存（実測）

```
呼び出し(summon) → compounds.json の座標変更（C-4b/C-6）の影響を受ける
反応実行          → reactor 改修（C-1/C-2/A-1）の影響を受ける
二重結合を作る    → 結合角 120°（C-4）の影響を受ける
```

| 影響なし（純粋な単結合の作図のみ） | 影響あり |
|---|---|
| V2・V4・V14・V9・V16・V17・V13 | **呼び出し**: V31・V6・V11・V18・V19・V10 |
| | **反応実行**: V6・V18・V19・V12 |
| | **二重結合**: V1・V20・V21・**V30**（C=O を drag で作る） |
| | **立体パズル**: V15（C-5 でボタン仕様が変わる） |

## 収録を再開したらやること（改修後の順番）

1. **compounds.json の座標が変わったら、呼び出しを使う回は `frame` の値を実測し直す**
   （V18.md §3 と同じ手順。座標が変われば構図がずれる）
2. **反応実行の回は貫通チェックを必ず流す**（LANES.md §4）。過去に事故が起きている箇所
3. **V15 は挙動の確認結果しだい**。テロップと食い違うなら台本から作り直す
4. 収録順は **V30 → V32 → V40 → V50 → V15**（影響の小さい順）
