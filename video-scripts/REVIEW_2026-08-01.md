## A. 化学の誤り（最優先）

### A-1. V19 けん化の生成物が違う

**ナレーションが「水酸化ナトリウムを加える」と言いながら、生成物を「酢酸とエタノール」と言っている。**
NaOH を加えるのがけん化なら、できるのは**酢酸ナトリウム**（カルボン酸の塩）。油脂も同じで、
**脂肪酸ではなく脂肪酸ナトリウム（＝石けん）**が出る。

- アプリの反応ルールは **`hydrolysis_ester`＝「けん化・加水分解（エステル + H₂O）」**で、
  実際に出る生成物は**酢酸（酸のまま）**。つまり**アプリは加水分解を計算していて、けん化ではない**
- 直し方は2つ。**どちらを採るか要判断**
  - ~~(a) 台本だけ直す~~
  - **(b) アプリに塩を持たせる ← 採用（2026-08-01 ユーザー判断）**。
    反応ルールを分け、**けん化は `R-COONa` を生成する**。油脂なら脂肪酸ナトリウム＝石けんそのもの。
    アプリはイオン・対イオンを持たないので**設計から**（P12-4）。
    **V19 の再収録はアプリ改修の完了待ち**
- **V19 は再収録が必要**。現状は保留中なので投稿には影響していない

**✅ アプリ側は対応済み（v353・2026-08-01）。台本の直しと再収録が残っている。**

反応ルールを2つに分けた。**イオンや電荷はモデルに持ち込まず**、教科書が `CH₃COONa` と
線で書くのに合わせて `-COO-Na` を単結合1本で表す（正準コード・同型判定・価標検査・
自動水素・異性体列挙のどれにも手を入れずに済む選び方）。

| ルール | 表示 | 生成物 |
|---|---|---|
| `hydrolysis_ester` | 加水分解（エステル + H₂O, 酸を触媒に加熱） | 酢酸 ＋ エタノール |
| `saponification` | けん化（エステル + NaOH, 加熱）→ カルボン酸の塩 | **酢酸ナトリウム** ＋ エタノール |

- 名称ライブラリに **酢酸ナトリウム／パルミチン酸ナトリウム（セッケン）／
  ステアリン酸ナトリウム（セッケン）** を追加した
- 官能基の分類に **カルボン酸の塩（-COONa）** が出る
- **油脂も登録した（v358）。** `トリステアリン（油脂・ステアリン酸のグリセリド）` を呼び出して
  **けん化を3回**押すと、セッケン3分子＋グリセリンになる。
  けん化は1回でエステル結合を1つ切るので途中にジ体・モノ体が必ず映る。
  **`ジステアリン酸グリセリド` と `モノステアリン酸グリセリド` も登録済み**なので、
  どの段階でも名称チップが出る（登録が無いと途中2ステップが「（該当なし）」になる）
- V19 の収録で使える手順:
  `トリステアリン` を呼び出す → けん化 → けん化 → けん化。
  最終の分子式は C₅₇H₁₁₃Na₃O₉（油脂 + 3NaOH の物質収支と一致）

## C. アプリの仕様確認・改修（別セッション）

### C-1. 反応の操作フロー（V18 の指摘から。**いちばん大きい要望**）

やりたい形:

1. **1つの分子を選ぶ → 反応の種類と相手を選ぶ → 2つの分子が並ぶ（選んだ分子が左）→ 反応する**
2. **2つの分子を選ぶ → 反応を選ぶ → 2つの分子が整列して反応する**

いまは呼び出した順に置かれるだけで、**反応の前に整列しない**。
`CH₃COOH + HOCH₂CH₃ → CH₃COOCH₂CH₃` のように**式の並びと画面の並びを一致させたい**。

**✅ 対応済み（v347〜v350・2026-08-01）。**

- **整列して反応する**: エステル化と分子間脱水を「①2分子が並ぶ（450ms・結合は反応前のまま）
  → ②結合ができる（400ms）」の2段モーフィングにした（`morphStages: 'joinFirst'`）。
  環化・開環の2段と違いクリック待ちを挟まないので収録の流れは止まらない
- **式の並びと画面の並び**: C-2 の 180°回転で `CH₃COOCH₂CH₃` が横一線に出るようになった
- **選択の導線**: 反応カードの「🎯 反応させる分子を選ぶ」を押すと、キャンバスのタップが
  分子選択になる（青い破線の枠と ①② の番号が付く）。**1つ選ぶ**とその分子が関わる反応だけ、
  **2つ選ぶ**とその2分子だけで完結する反応だけに絞られる
- **選んだ分子が左**: 先に選んだ分子は動かさない。アルコールを先に選んだときだけ
  エステル化の動かす側を酸に入れ替える（できる結合は同じなので化学は変わらない）

**収録で使うときの注意**: 選択モードのトグルは `#btn-reaction-select`。
デモから叩くなら「ボタン → 分子の原子を `click` → 反応ボタン」の順になる。

### C-2b. 芳香族置換の位置が毎回変わる（2026-08-01・reaction レーンが実測）

**同じ手順を10回繰り返すと、置換基が生える向きが2通りに揺れる**
（ニトロ化 6:4／スルホン化 6:4／塩素化 8:2）。

- 原因は**原子IDが乱数**であること。`aromaticSites()` が `mol.bonds` 走査の `Set` 挿入順の
  先頭を選ぶため、**呼び出すたびに選ばれる環の頂点が変わる**
- **化学的には正しい**（ベンゼンの6頂点は等価）。問題は**絵が毎回変わること**で、
  収録のたびに構図が動くため **`frame` に `cx`/`cy` を書けない**（V40 は全ステップ自動中心で逃がした）
- **C-2（生成物の配置を整える）の作業対象そのもの**。位置の決め方に順序を入れれば再現性が出る

**✅ 対応済み（v355・2026-08-01）。** 原因は原子IDが乱数であることと、`addBond` が結合の端点を
**IDで正規化**していること。そのため `mol.bonds` を走査したときの `b.atomId1` がどちらの頂点に
なるかが呼び出しごとに変わっていた。2か所を座標基準に直した。

1. `aromaticSites` … 候補の順を **x が大きい順、同じなら y が小さい順**に。右の頂点から
   置換基を伸ばすのは、ライブラリの一置換体（ヒドロキノン等）の作図に合わせたもの
2. `vinylBonds` … 頭-尾の「頭」が、置換基の数が同じとき a1（＝IDで決まる）になっていた。
   対称な C=C（ブタジエン等）で頭と尾が毎回入れ替わり、**重合の架橋が本来より少ない本数で
   止まることがあった**。RX13 が散発的に落ちていた原因でもある

**ベンゼンのニトロ化・スルホン化・塩素化を各20回で、選ばれる頂点は毎回 (440,300) の1通り**
（対応前は 11:9 に割れていた）。生成物の座標も10回とも完全一致。
**`frame` に `cx`/`cy` を書けるようになった**ので、V40 は自動中心で逃がさなくてよい。

**直交（90°）ではなく 120° にしたい。**

1. **座標から読める C=C の幾何が変わった** … 「2-ブテン」「ブテン二酸（マレイン酸／フマル酸）」は

2. **結合が別の重原子を貫通した** … メタクリル酸メチルで実際に起きた

ライブラリ全143件を1つずつ呼び出して検証: **名称が変わった化合物 0件・貫通 0件**、
環外 C=C を持つ19件のうち幾何が確定しているものはすべて 120°、未確定の2件は 180° のまま。

### C-5. 立体タイムアタックの回転ボタン（V15）

**「90度回転で分子が変形しないボタンがない」**という指摘。
実装されているボタンは次のとおり:

```
btn-ta-rot90cw / btn-ta-rot90ccw / btn-ta-rot180 / btn-ta-swap
btn-ta-cycle-cw / btn-ta-cycle-ccw / btn-ta-reset / btn-ta-next
```

**✅ 対応済み（v343・2026-08-01）。操作を3つに絞った。**

**アプリ側の確認の結果（実機 D-アラニンで `StereoQuiz.relationOf` を実測）**:

| 操作 | お題との関係 |
|---|---|
| 改修前の「⟳ 90°回す＋左右入れ替え」 | **same（立体異性体は変わらない）** |
| 純粋な90°回転だけ | enantiomer |
| 左右入れ替えだけ（上下固定） | enantiomer |

つまり**改修前も 90°ボタンは鏡像に入れ替えていなかった**。フィッシャー投影では純粋な
90°回転が奇置換＝鏡像になるため、左右入れ替えを重ねて偶に戻してある（quiz.js の
`fischerOpRotate90`）。**縦が奥・横が手前**という投影のきまりから来るもので、
「回すと左右の枝が入れ替わって見える」のは絵の都合ではない。

**確定した仕様（2026-08-01 ユーザー）＝ 実装済み**:

- パズルの操作は **⟲ 反時計回りに回す ／ ⟳ 時計回りに回す ／ ⇄ 鏡像の入れ替え** の3つだけ
- 回転は**立体異性体を変えない**（回転後に左右の枝の位置が入れ替わる）
- 鏡像の入れ替えは**上を固定**して左右を入れ替える（`fischerOpSwap` は
  `trySwap('left','right')` を先に試すので、もともとこの形）
- **180°回転（＝回転2回）と巡回（軸選択つき）は外した**。フィッシャー投影練習モードは据え置き

> **V15 は再収録が必要。** ボタン名が変わり、ナレーションの「百八十度、それから九十度」が
> 実機と食い違うため。**台本の説明そのもの（回しても分子は変わらない）は正しい**ので、
> 直すのは操作の並びと読み上げだけでよい。

### C-5b. 「回す」の中身を、人が紙の上でやる操作に合わせる（2026-08-01・ユーザー指示）

**ユーザーの意図**:
「パズルとしては90度回そうとする。**だがフィッシャーなので、そのまま全部がローテするわけではない**。
人間は一番上の枝に着目するはずなので、**cw なら左の枝を上に持ってくることを優先する。
すると枝の位置が入れ替わる**。これを基本操作にしたい。」

**いまの実装（`quiz.js`）**:

```js
fischerOpRotate90 → rotateTargetInPlane(target, turns, /* mirrorX */ true)
```

**90°回転 ＋ 左右反転**の合成になっている。回転（奇置換）と鏡映（奇置換）を重ねているので
**結果として立体は保たれる**——立体レーンが「回しても `canonicalStereoCode` が変わらない」と
測ったのはこれが理由。**数学的には辻褄が合っているが、紙の上で人がやる操作ではない**。
図が左右に反転するので、何が起きたのか読み取れない。

**やりたい操作はすでにコードにある**: `fischerOpCycle(game, target, centerIndex, fixedSlot, dir)`
＝ **1つの枝を固定して残り3つを巡回させる（3巡回＝偶置換）**。
コメントにも「くさび図の cycleOthers を2Dの作図データの上で行う版」とある。
**これは教科書が認めるフィッシャー投影の操作そのもの**（配置が変わらない）。

**依頼したいこと**:

1. **`⟳ 時計回りに回す` / `⟲ 反時計回りに回す` の中身を `fischerOpCycle` に差し替える**
   （`rotateTargetInPlane` の鏡映つき回転をやめる）
2. **cw は「左の枝が上に来る」向き**にする。固定する枝は**下（縦の主鎖の下側）**が自然
   （L→U, U→R, R→L）。ccw はその逆
3. ハンドラ `applyCycle` とボタンID `btn-ta-cycle-cw/ccw` は**コードに残っている**
   （`index.html` からボタンだけが消えている）。作り直す必要はない

**なぜこれが正しいか**: 素朴な90°回転（4巡回＝奇置換）は**フィッシャー投影では禁止**で、
やると鏡像異性体になる。1つ固定して3つ巡回（偶置換）は**許される操作**。
**許される操作だけをボタンとして提供すれば、パズルを解く経験がそのまま教科書の規則になる。**

**⚠ 動画への影響**: **V15 は再収録が必要**（操作の見た目が変わるため）。
差し替え後は V15 の「回しても分子は変わらない。これがフィッシャー投影のきまり」が
**正しい説明になる**（許される回し方だけを提供するので）。
V50 の予告「90°回すと別の分子」も、**「素朴に全体を回すとダメ。だからこう回す」**という
形で生きる。
