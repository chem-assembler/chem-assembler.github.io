## 0. 先に結論

| 何を作りたいか | 成否 | 詰まるところ |
|---|---|---|
| 長い脂肪鎖（カプサイシン） | **✅ 描ける** | 14本連続で伸ばせた（C₂₀H₃₄）。ただし横一直線だと **x=1029 まで伸びて構図から外れる** |
| 環と環を単結合でつなぐ（ニコチン） | **✅ 描ける** | ただし**2つめの環を置ける窓が 70〜100px しかない**（下記2） |
| 4環の縮合（ステロイド核＝コレステロール） | **✅ 描ける** | 六員環×3＋五員環を順に縮合して 17原子。**素直に通った** |
| 環をまたぐ橋（モルヒネ・テトロドトキシン） | **✅ 作れる** | 結合ツールのドラッグで環の対角どうしを結べた |
| 環にぶら下がった鎖の先に枝（リモネン） | **⚠ 実質むり** | **有効な的が 10px 幅 × 5方位中2方位**（下記3） |

**→ アプリの表現力は足りている。足りていないのは「狙ったところに置ける」ことだけ。**

## 1. 無言で失敗するのが最大の問題

`game.js` の配置ロジックは、近傍原子が見つからないと `isValid: false` を返して
**クリックを黙って捨てる**。エラーもトーストも出ない。

- 描いている本人には「押したのに何も起きない」としか見えない
- **どちらに外したのか（近すぎ／遠すぎ／別の原子に取られた）が分からない**ので、直しようがない

**要望A（最優先）**: 置けなかったクリックに**理由を出す**。
「近すぎます」「遠すぎます」「◯◯に取られました」の3つが言い分けられれば足りる。
トーストでも、押した点にゴーストを一瞬出すだけでもよい。

## 2. 数字（実測値。すべて `--speed` 無関係の素の判定）

`game.js` の定数:

```
GRID_SIZE     = 42     ← 標準の結合長
SNAP_RADIUS   = 45     ← 既存原子への吸着半径
MIN_CLEARANCE = 27.3   ← BOND_LENGTH * 0.65。近すぎる判定
ベンゼン環炭素の置換基 = 頂点から 27.97px（BOND_LENGTH * 0.666）
```

### 2a. 結合長 42 に対して吸着半径 45 ＝ 的が「置きたい場所」の外周にしかない

**次の原子を置きたい場所（42px 先）を押すと、吸着半径 45px のふちを押していることになる。**
3px 外せば無反応。実測でも 46px で `×` に変わった。

**要望B**: `SNAP_RADIUS` を結合長より**明確に大きく**する（60〜70px 程度）。
遠すぎる側は「近傍原子なし」で弾けばよいので、広げても誤爆は増えにくい。

### 2b. ベンゼンの置換基だけ 28px、それ以外は 42px

鎖を伸ばすと **1本目だけ 28px、2本目以降は 42px** になる。

```
1本目 → (483,294) 前から 28px      ← ベンゼン環炭素の置換基は 0.666 倍
2本目 → (525,294) 前から 42px
3本目 → (567,294) 前から 42px      （以下 14本目まで 42px）
```

台本を書く側は**この1本目だけを覚えていないと必ず外す**（実際に外した）。
見た目の理由（環に近づけたい）は分かるが、**同じ操作の距離が場所で変わるのは直感に反する**。

**要望C**: 置換基の距離を 42px にそろえるか、そろえないなら
**押した点から出る位置をゴーストで見せる**（外す前に分かる）。

### 2c. 別分子として環を置ける窓が 70〜100px しかない

ベンゼンの右頂点(455,294)から N px 離して五員環モジュールを置いた結果:

```
 42px: 置けなかった   ← MIN_CLEARANCE で弾かれる
 60px: 置けなかった
 70px: 置けた（別分子として）
 80px: 置けた
 90px: 置けた
100px: 置けた
120px: 置けなかった   ← SNAP_RADIUS を超えて「近傍原子なし」
160px: 置けなかった
200px: 置けなかった
```

**幅 30px の帯を狙わないと2つめの環が置けない。** ニコチンやインジゴのように
「環と環を単結合でつなぐ」分子は、**まずこの帯を当てるところから始まる**。

**要望D**: **空いているところにはどこでも置けてよい**はずだ。
既存分子から遠い＝別分子を作る意図が明らかなので、`isValid: false` にする理由がない。
（キャンバス上限の内側であること、他の原子と重ならないことだけ見ればよい）

### 2d. 「環→鎖→枝」は有効な的が 10px × 2方位しかない（リモネンが組めない原因）

シクロヘキサンの頂点(456,273)から鎖を1本出し、その**先端(493,252)に枝を足す**ときの実測:

| 先端からの距離 | → | ↓ | ↑ | ↘ | ↗ |
|---|---|---|---|---|---|
| 20px | **削** | 削 | 削 | 削 | 削 |
| 26px | **削** | 削 | 削 | 削 | 削 |
| 32px | **○** | △環 | △環 | △環 | **○** |
| 38px | **○** | △環 | △環 | △環 | **○** |
| 42px | **○** | △環 | △環 | △環 | **○** |
| 46px | × | △環 | △環 | △環 | × |
| 50px | × | △環 | △環 | △環 | × |

○＝先端に枝が生えた／△環＝**環の炭素(456,273)に取られた**／×＝無反応／**削＝先端の原子が消えた**

**3つ問題がある**:

1. **26px 以内を押すと、足すつもりが先端の原子が消える**。
   足す操作と消す操作が**同じ場所で切り替わる**のは事故のもと（実際に4回踏んだ）
2. **5方位のうち3方位が環の炭素に横取りされる。** 先端のほうがカーソルに近いのに、
   `secondBranchPoints` の候補点が環側にあるぶん環が勝つ
3. **成功する帯は 32〜42px の 10px 幅だけ**

**要望E**: **いちばん近い原子が勝つ**ようにする（現状は「候補点まで含めた最短距離」で
遠い原子が勝つことがある）。せめて**同点に近いときは、指の直下にある原子を優先する**。

**要望F**: 「原子を消す」を**同じタップから切り離す**（消去ツールに寄せる／長押しにする）。
少なくとも **足す操作の成功帯（32〜42px）と消える帯（〜26px）のあいだに、
何も起きない緩衝帯を置く**。


## 2e. 【追加・2026-08-12】同じ台本が、収録レイアウトだと 42px ずれる

**いちばん厄介な1件。** まったく同じ手順が、

| 開き方 | 五員環モジュールの落ちる先 |
|---|---|
| `?mode=free`（ふつうに開く） | 頂点が **(546,258)** |
| `?rec=…`（収録レイアウト） | 頂点が **(546,216)** ＝ **グリッド1つぶん(42px)上** |

**再現条件**: `frame` で構図を寄せてから、**近くに原子が無い場所**へモジュールを置く。
`frame` を入れない場合は両者とも同じ位置に落ちた ＝ **構図の viewBox が効いている**。
原子を既存原子のそばに置く操作は影響を受けない（吸着先が決まるため）。

**何が起きたか**: V85（ニコチン）の台本が、下見では ニコチン C₁₀H₁₄N₂、
収録では **C₉H₁₄N₂（環が閉じない4原子）** になった。
下見が通ったのに収録が違う、という**いちばん気づきにくい形の失敗**。

**要望G**: **モジュールの落ちる位置を viewBox に依存させない。**
配置は SVG 論理座標だけで決まるべきで、画面の見え方（ズーム・要素の寸法）で変わってはいけない。

**→ 決着（2026-08-12・v1150）。** 原因は `getScreenCTM()` の**逆行列**が返す 5.7e-14 の丸め誤差で、
**誤差の向きが画面レイアウトで変わる**こと。`y=273` は 42 の倍数のちょうど半分なので、
その 1ulp が `Math.round` の分かれ目に乗って 42px 反転していた（`?rec=` はヘッダーを隠すぶん
SVG の上端が 110px → 66px へ動く）。丸める前に 1e-6 論理px より下の桁を落とす `snapToGrid()` に
寄せて解決。二分の記録と前後表は `DESIGN_hit_areas.md` §9。

**台本の作法**（残る注意）: **半格子（42 の倍数 ±21。273・21・63…）を狙わない。**
向きは固定したので下見と収録は必ず一致するが、分かれ目の上にいると
「1つ隣の格子を狙ったつもり」が読み取りにくいのは変わらない。
（`build-nicotine` は `(546,273)` → `(546,252)` に寄せた。他の台本に半格子の自由配置は無い）


## 2f. 【追加・2026-08-12】残る2本（インジゴ・コレステロール）は、どちらも既出の要望で止まっている

**新しい制限は出なかった。** 上の 2c・2d がそのまま効いて、2本とも組み上がらない。

### コレステロール ← **要望E・F**（2d と同じ）

**ステロイド核（4環17原子）も -OH も2本のメチル基も C5=C6 も通った。**
止まるのは**側鎖のたった1本のメチル基**——C17 から出した C20 に枝を足すところ。

```
atom c U from (605,365) 40px → (618,325)          ← C20 は置ける
✗ atom c ["L","R","LU","LD","RD"] from (618,325)  ← C21（メチル）はどの向きでも通らない
```

C20 は**環にぶら下がった鎖の先**なので、2d で測った「10px 幅 × 5方位中2方位」の的になる。
しかも環D の原子が近いぶん、**その2方位も取られて 0 になる**。
`C₂₆H₄₄O` まで組めて、**あと炭素1個**で `C₂₇H₄₆O` に届かない。

**→ リモネンとまったく同じ理由で止まっている。** この1点を直せば**2本まとめて通る**。

### インジゴ ← **要望D**（2c と同じ）

左右対称の2つの単位を **C2=C2' でつなぐ**分子。片方の単位は組める
（ベンゼンの右辺に五員環を縮合でき、C2 にあたる頂点が (493,336) に出る）。

止まるのは**2つめの単位を置く位置**。左右対称に並べると
2つめのベンゼンの中心は**1つめから 119〜122px** になるが、
**モジュールを置ける窓は 70〜100px** なので**置けない**。
窓に収まる 95px あたりに寄せると、こんどは2つの C2 が 18px まで近づいて重なる。

**→ 要望D（空いているところにはどこでも置ける）が入れば、そのまま組める。**

## 2g. 【追加・2026-08-12】伸長した結合線が、既存の原子の下をくぐる（ユーザー報告・再現ずみ）

**要望A〜G とは別の穴。** ユーザーの手順そのままで再現した:

1. 六員環の1つの炭素にメチル基を付ける
2. そのメチル基から**下へ**伸ばしてエチル基にする
3. **同じ環炭素**（枝の付け根）に、もう1本メチル基を付ける（右向き）

```
新しい結合: (456,273)-(505,273)  長さ 48px  ← 42px から**伸長されている**
その線から 5.6px の位置に C(477,279) が居る   ← 原子の丸は半径10px ＝ 線の上に乗る
```

**原因**: `MIN_CLEARANCE`（27.3px）は**原子どうしの距離しか見ていない**。
置き場所が詰まると結合を最大 84px まで延ばして逃がすが、
**延ばした線が既存の原子の下を通るかは誰も見ていない**。

**この検査は他の経路には既にある**:
- `reactor.js` … 生成物の配置で「結合線が無関係な原子を貫通しない」ことまで見る（strict）
- `game.js:3542` … 整形モードで「結合が別の重原子を貫通した」ら座標を戻す
- **手描きの配置だけ無い**

自動水素も同じ穴にある（**モデルに存在せず描かれているだけ**なので、
`MIN_CLEARANCE` の対象外。登録図は `verify-compounds.js` が 11.5px の近接を報告しているが、
手描きには相当する見張りが無い）。

**測り方**: 重原子と、その原子を端点に持たない結合線との距離（点と線分の距離）。
素の格子では最小 21px（= 42·sin30°）なので、**21px を明確に下回ったら異常**。

⚠ 総当たり（側鎖3通り × 全周24方向 × 距離3通り）では**出ない**。
**伸長が起きる配置**でだけ出るので、再現には「詰まった場所へ足す」手順が要る。

## 2h. 【決定・2026-08-12】個々の原子のドラッグを廃止し、ベンゼンの特別扱いをやめる（案B-2）

**ユーザー判断。** きっかけは「**ベンゼン環の原子だけドラッグできて変な感じがする**」。

### 調べて分かったこと

- 個々の原子のドラッグは**設計された機能ではなく、ジェスチャの割り当ての余り**だった。
  普通の原子はタップが「消す／置き換える」で埋まっているので、
  **タップが空いている原子（ロック原子・ベンゼン環の原子）にだけドラッグが残っていた**
- 動かすと**六角形が1頂点だけ歪む**（環ごとではない）。
  間隔を空けるなら**結合線のドラッグ（伸縮）**、どかすなら **Shift＋ドラッグ（分子ごと）**が
  本来の道具で、どちらも別に用意されている
- **ベンゼンの炭素を消しても問題は起きない**（実測）:

  ```
  消す前  C₆H₆  「ベンゼン」        官能基: ベンゼン環（芳香族）
  消した後 C₅H₈ 「1,3-ペンタジエン」 官能基: C=C二重結合 ×2 ／ 価標エラーなし
  ```

  ケクレ構造で持っているので素直にペンタジエンになる。**守っていた理由はモデルの安全ではなく
  「うっかり環を壊さない」というUXの都合**で、しかも**消しゴムツールでは既に消せる**（守り切れていない）
- 消したあと、**残った原子に「ベンゼン印」（`benzeneCenter` / `benzeneAngle`）が付いたまま**になる。
  この印が付いた原子は置換基を **42px ではなく 27.97px・環の外向き**に置く特別扱いを受けるので、
  **もうペンタジエンなのに置換基だけベンゼンの作法で付く**

### やること（順序つき）

1. **個々の原子のドラッグを廃止**（ベンゼン・ロック原子とも）
2. **ベンゼンの特別扱いをやめる** — 同元素タップで他の原子と同じく消える
3. **消したあとに残る「ベンゼン印」を落とす**（環でなくなったら印も外す）
4. **`ZD1`・`ZD2` を Shift＋ドラッグ側へ移し替える**。
   ⚠ **0.0px の完全重複を作らない罠は必ず残すこと**（v736 の実事故の再発防止で置かれたもの）

### 決定の理由

例外を1つ減らすのではなく**ゼロにする**。残る規則は2行:

> **原子は同元素タップで消える。個々の原子は動かせない**（分子ごとに動かすか、結合を伸ばす）

事故の心配は v1131 で下がっている ＝ **タップで消えるのは原子の絵から 18px 以内だけ**（旧 28px）。

**着手は `?rec=` の 42px ずれ（要望G）が片づいてから**（同じ `game.js` を触るため）。
