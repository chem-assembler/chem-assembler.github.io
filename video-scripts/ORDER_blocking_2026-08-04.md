## C-9. 「⚗ 分析中」の琥珀枠が ① に固定される

### 症状

分子を複数並べたとき、**枠が必ず先頭の分子に付く**。**「◯◯はどれ？」と問う回で、
冒頭のコマから答えが漏れる**。

| 回 | 冒頭のテロップ | 正解 | 枠 | |
|---|---|---|---|---|
| **V32** | 3つとも -OH。**アルコールはどれ？** | **①** | ① | **答えが丸見え** |
| **V33** | 官能基がいちばん多いのはどれ？ | ③ | ① | **誤答を指す** |
| **V34** | 仲間はずれはどれ？ | ③ | ① | **誤答を指す** |
| V31 | この3つ、共通点は？ | — | ① | 実害なし（投稿済み） |

### 原因

`renderFocusFrame()` の対象が `listed[0]` ＝ **原子配列の先頭で固定**。
利用者が選んだわけではないのに、常にどれか1つが強調される。

### 提案（どちらでもよい）

1. **収録モード（`.recording` / `?rec=`）では描かない** … 動画側だけ直る。最小
2. **利用者が明示的に分子を選ぶまで描かない**（既定を「どれも選ばれていない」にする）
   … **学習アプリとしてもこちらが正しい**と考える。3分子を並べて「どれ？」と
   考えている生徒に、アプリが勝手に1つを指すのは学習の邪魔になる

**2 を推す。** 1 は動画の都合だけの回避で、アプリ本来の問題は残る。

### 動画レーン側では回避できない理由

## C-7. 反応で作る C=O が炭素鎖と一直線に出る

### 症状

**ライブラリの図はすべて正しい**（＝O は炭素鎖に垂直）。**反応で生成した分子だけが従っていない。**

| 化合物 | ＝O の向き | 出どころ |
|---|---|---|
| 酢酸・アセトアルデヒド・アセトン・安息香酸 | **縦（正しい）** | stages.json |
| 酢酸エチル・安息香酸メチル | **縦（正しい）** | compounds.json |
| **酸化で生成した酢酸** | **横（鎖と一直線）** | reactor.js |

実測（2026-08-04・`?rec=reaction-oxidation` を最後まで流して確認）:

```
酢酸  C(440,300)=O(520,300)   ← 鎖の延長線上
```

エステル化（V18）の生成物は既存原子の組み替えなので正しく縦に出る。
**新しく O を置く反応（酸化など）だけ**が該当する。

### 原因

`assembler/reactor.js:543` `outwardCandidates()` の候補の並び。

```js
const angles = [base, base + Math.PI / 6, base - Math.PI / 6,
                base + Math.PI / 3, base - Math.PI / 3, base + Math.PI / 2, base - Math.PI / 2];
```

`base` ＝「隣接原子と反対の向き」＝ **鎖の延長**。末端炭素はまず `base` が空いているので、
＝O が鎖と一直線に出る。**垂直（`base ± π/2`）は候補の最後**。

### 提案

**カルボニルの ＝O を置くときだけ候補の順序を差し替え、`base ± π/2` を先頭にする。**
`outwardCandidates` に「垂直優先」の引数を足すのが最小の変更に見える。

**同じ考え方はすでにこのファイルにある**ので横展開で済むはず:

- `attachGroup()`（ニトロ・スルホ）… 枝を `angle ± π/2` に出している（`reactor.js:362`）
- `attachAcetyl()` … カルボニル O を `spot.angle + π/2` に置いている（`reactor.js:407`）

**つまり「置換基として付ける」経路では既に垂直。「反応で O を1つ置く」経路だけが漏れている。**

### 検証してほしいこと

1. エタノール → 酸化 → アセトアルデヒド → 酸化 → 酢酸 で、**2段とも ＝O が縦**になる
2. ライブラリから呼び出した図（`stages.json` の酢酸など）と**同じ形になる**
   （`node tools/check-demo-shapes.js` の考え方で、結合ベクトルが一致するか）
3. 既存の反応で**貫通や重なりが増えていない**（`attachGroup` の衝突判定はそのまま使えるはず）
