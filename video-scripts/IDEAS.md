## 1. クイズ型（サムネと冒頭3秒だけで問いが成立する）

**サムネ設計の要点**: 静止画1枚で「問いと選択肢」が読めること。
**①② を並べる型が強い**（V11 で実証。アプリが2分子を ①② と番号で呼ぶのでそのまま選択肢になる）。

> **⚠ ただし「答えが名前になるクイズ」では①②型は使えない**（2026-08-02・V24 で判明）。
> **キャンバスに分子を2つ置くと、名称チップが `① L-乳酸 ＋ ② ペンタン …` と答えを出してしまう。**
> チップは `position:fixed` の DOM なので **`frame` で切れない**。名前の無い化合物にすると
> 今度は「① （該当なし）」になり、機械判定を見せる手段が消える。
> **名前を伏せたいクイズは、アプリのクイズ画面（`#btn-quiz` など）を使う**——
> 左右に並び、名前を出さず、答えると解説で明かす作りになっている。

| 案 | 内容 | 実現性 |
|---|---|---|
| **同じ？違う？** | 2つ並べて「同じ分子？」。回転しただけ vs 鏡像。`#btn-quiz-same` | ◎ **出題ストック無限・制作最速。独立シリーズに切り出す価値** |
| **仲間はずれはどれ？** | 3つ並べて1つだけ官能基が違う | ○ 呼び出しだけで組める |
| **不斉炭素はどれ？** | 分子1つ、炭素に①②③。不斉マークで答え合わせ | ◎ `isAsymmetricCarbon()` で裏取りできる |
| **官能基はいくつ？** | 数え上げクイズ `#btn-count-quiz` | ○ |
| **名前を見て描ける？** | 命名クイズ `#btn-naming`。枝の位置の付け方 | ○ |
| **この分子式で作れないのはどれ？** | 4つのうち1つが価標違反 | △ 作図で作れないものを見せる方法を要検討 |
| **どっちが沸点が高い？** | — | ✗ **アプリは物性を持たない**。判定を見せられないので不採用 |

## 3b. 立体パズルの展開（2026-08-01・ユーザー案）

**十字の模型（C-5c）ができると、その上にいくつも出題形式を載せられる。**
土台は1つ、出題は4種類、という構造にすると作りやすい。

### 土台: 模式化した模型でやる（実際の分子を使わない）

4つのスロットに **A・B・C・D**（あるいは色）を置くだけの抽象モデル。

- **化学の知識なしで規則だけを練習できる**。名前も分子式も要らないので**認知負荷が最小**
- **出題の生成が自明**（4記号の並べ替え24通り）＝**出題ストックが無限**
- **判定は置換の偶奇だけ**で決まるので、分子モデルを通さず実装できる＝軽い
- **動画としても作りやすい**。分子の説明が要らないので **20〜30秒に収まる**

### 出題形式（土台が同じなので、どれも同じ判定で作れる）

| 形式 | 内容 | 動画との相性 |
|---|---|---|
| **作る**（現行のタイムアタック） | 見本と同じ立体異性体を操作で作る | ○ 手数と時間が出るので達成感がある |
| **同じ？違う？** | **左右に2つ示して答える**。タイムアタック化できる | ◎ **①②を並べる型**（V11 で実証） |
| **4択** | **見本1つに対して4つ示し、同じものを選ばせる** | ◎◎ **サムネ1枚で問いが成立する。いちばん強い** |
| **上級: R/S** | **実際の分子**で R か S かを答えさせる／選ばせる | ○ 難関大水準。v331 の R・S 実装に乗る |

**作る順の推奨**: 土台（模式模型）→ **4択** → 同じ？違う？ → R/S。
4択を先に置くのは、**静止画1枚で問いが読める＝サムネが最強**だから（IDEAS §1 の設計要点）。

> **⚠ 用語の確認が要る**: 「L/R を答えさせる」とあったが、
> **R/S**（カーン・インゴールド・プレローグ則）と **D/L**（フィッシャー投影に基づく古い表記）は
> 別の体系。アプリは両方を持っている（R・S ティップス＝v331／D-乳酸・L-乳酸＝compounds.json）。
> **上級版でどちらを答えさせるか決める必要がある。**
> 高校化学の範囲なら **D/L のほうが出番が多く**（糖・アミノ酸）、
> **R/S は難関大の記述で効く**。両方を別レベルにする手もある。

### 量産の前提（2026-08-11 に実データで確かめた）

**① 使える元素は C・O・N・Cl・S・Br だけ**（内部に I・Na・K。`chemistry.js` の `VALENCIES`）。
**P と F は価標表にも無い**ので、それを含む分子は**原理的に描けない**。

**② ライブラリは「骨格はあるが有名化合物の名前が無い」。**
ピリジン・ピリミジン・イミダゾール・インドール・ピロール・フラン・チオフェン・キノリン・
ナフタレン・アントラセンは収録ずみ。いっぽう**テオブロミン・尿酸・プリン・ドーパミン・
セロトニン・アドレナリン・メントール・リモネン・DNA の4塩基は1つも入っていない**。
→ **この枠は1本撮るごとにライブラリの穴が1つ埋まる。** 動画とアプリが同時に育つ。

**③ 尺の目安は重原子14個で43.5秒**（V68 の実績）。
~~20個を超えると短尺に収まらない。~~ → **大きい分子は途中を早送りして尺を詰める**
（ユーザー判断・2026-08-11）。そのために **`speed` アクションを足した**（v1042）:

```json
{ "type": "speed", "value": 2 }   ← ここから基準速度の2倍で走る
{ "type": "speed" }               ← 基準へ戻る（value 省略）
```

`value` は**基準速度への掛け算**なので、`--speed=2` の収録で `value: 2` を置くと
実速度は4倍になる。**収録の速度を変えても「ここは他より速い」という台本の意図が保たれる**。
再生の終わりに基準へ戻るので、続けて再生しても次の台本へ漏れない（回帰テスト N2c で固定）。

**⚠ `wait` も同じだけ割られる。** 早送りの区間で静止させたい秒数を保ちたければ、
その `wait` を倍率ぶん大きく書く。

**どこを早送りするか**: 手順が同じ作業（メチル基を何本も置く・長い鎖を伸ばす）。
**芯の1手は等速のまま**にする——早送りは「作業を飛ばす」ためで、話を飛ばすためではない。

> **⚡ 倍率は机上で決めない。焼き上がりを見て決める**（ユーザー判断・2026-08-11）。
>
> - **視聴者が追えない速さでよい。** 早送りの区間は「たくさん手を動かしている」ことが
>   伝わればよく、1手ずつ読ませる必要はない。**むしろ速いほうが「大変さ」が出る**
> - `speed` アクションの倍率に**上限は掛けていない**（`?speed=` の 0.25〜4 の制限は
>   URL 側だけ）。基準2倍の収録で `value: 4` なら実速度8倍まで素直に上がる
> - 手順: **強めの値で1本撮る → `tools/frames.js` で早送り区間のフレームを抜いて見る
>   → 速すぎ／遅すぎを直す**。等速側の区間は声と合わせる必要があるので、
>   **倍率をいじったら wait を引き直す**（wait も同じだけ割られるため）

**④ 量産の型は「骨格を使い回すクラスタ」で組む。** 1本目で座標を実測すれば、
同じクラスタの2本目からは**置き換えるところだけ差し替えればよい**。

**✅ 解決: 探りは必ず収録と同じ 810x1440 で回す**（2026-08-11）。

アドレナリンの N-メチル基がどこにも置けず「モジュールを使った直後は原子ツールが効かない」と
疑ったが、**アプリのバグではなかった**。原因は**探りをデスクトップ幅（1400x950）で回していた**こと:

| 画面 | SVG(431,433) のクライアント座標 | そこにある要素 | 結果 |
|---|---|---|---|
| 1400x950 | (940,926) | **`#btn-molecule-modal`**（この分子を調べるバー） | ❌ モーダルが開くだけ |
| **810x1440**（収録と同じ） | (474,1022) | `#chem-svg` | ✅ 置ける |

**縦に長い分子は、横長の画面だと下端がバーの下へ回り込む。** `getSnappedCoords` は
どちらでも `isValid=true` を返すので、**判定を読んでも気づけない**——クリックが
別の要素に吸われているだけだった。

**アプリが選ぶ配置は直交（東西南北）**なので、手で座標を書くより実際に置かせたほうが
ライブラリの流儀に揃う（アドレナリンの N-メチルは手書きの (419,463) から
アプリが選んだ (431,433) に直した）。

### ⚠ 置きたい場所ではなく、**付けたい原子の近く**を押す（2026-08-11）

メントール（枝の上に枝がある）を描こうとして、イソプロピルの2本目が
どうしても環の炭素に付いてしまった。「アプリの側鎖配置（±30° 振り分け・回帰テスト D5）が
邪魔をしていて、仕様を変えないと描けない」と一度は結論しかけたが、**それは誤りだった**。

原因は押し方。**置きたい座標そのもの**（根の 42px 東 = (535,252)）を押していた。
吸着は「いちばん近い原子」と「その原子が空けている向き」で決まるので、
目的地を押すと**別の原子の候補点として拾われる**ことがある。
**根の近くで、付けたい向き**（(517,234)）を押すと一発で付く。

実測: 枝を1本付けたあとの状態でも、**根に2本目を付けられる点は32か所あった**。
つまり操作性の問題ではなく、狙い方の問題。**アプリの仕様変更は要らない。**

```
シクロヘキサン(420,294) → -OH(420,252) → メチル(342,315) → 根(498,273)
  → 枝1(514,217) → 枝2(517,234)   ＝ 名称チップに「メントール」
```

**この押し方はシリーズ全体の作法**にする——枝の上に枝がある分子（イソプロピル・
tert-ブチル・イソプロペニル）はどれも同じやり方で描ける。

### 制作の手順（1本ぶん）

1. **ライブラリに居るかを見る。** 居なければ**先に描いて実測し、`compounds.json` に登録する**
   （V68 のカフェインがこの形。描けることを確かめてから登録する順番を守る）
2. **座標を実測する。** ヘッドレスで実際に描いて原子座標・名称チップ・結合の貫通を確かめる。
   **同じクラスタの2本目からはこの実測を使い回せる**
3. ナレーション → wait の逆算 → 収録 → `--events` で詰め直し → mux → フレーム目視
4. **最終ステップの wait は大きめに**（30000）。**完成形の前にハイライト消し**を1組入れる

**強み**: 出題データが要らない。**アプリの自由モードだけで成立する**。
そして**ライブラリの穴埋めと同時に進む**ので、動画とアプリが一緒に育つ。
**弱み**: クイズ型のように「範囲を変えるだけ」では作れず、**1本目は座標の実測が要る**。
ただし**クラスタを組めば2本目以降はほぼ差し替えで済む**（プリン系がその代表）。

## 4c. 「スクロースの中のフルクトースは本当に裏返っているか」（2026-09-01・ユーザー案）

**V121 の続き。** V121 は「加水分解するとフルクトースがひっくり返る」と言って見せているが、
⛔ **見ている側には「アプリがそう描き替えただけ」と区別がつかない**。
⭐ **この回は、それを炭素番号で確かめにいく。**

### 見せ方

1. **フルクトース単独**を呼び出し、**主鎖と番号**を出す
2. **スクロース**を呼び出し、同じく番号を出して、**フルクトース部分の番号を読む**
3. ⭐ **2番に着目する** …… 単独では **-OH**、スクロースの中では **グリコシド結合が下向き**に出ている
4. **番号の回り方を見比べると、環が裏返して描かれていることが分かる**

⛔ **アプリの改修待ち**: **分子が複数あるとき、すべての分子に番号を振れるようにする**改修が走っている
（ユーザー談・2026-09-01）。⚠ **入ったら版番号をもらってから収録する。**
⚠ **いまは番号が1分子ぶんしか出ないので、2 と 3 が並べられない ＝ この回は成立しない。**

### 付けてよい話

- **インベルターゼの語源** …… スクロースの水溶液は右に旋光するが、加水分解した混合物は左に振れる
  （スクロース +66.5° → グルコース +52.7° と フルクトース −92° の混合で約 −20°）。
  **旋光が「反転（invert）」する**ので **転化糖（invert sugar）**、その酵素が **インベルターゼ**。
- ⚠ **旋光はアプリが持っていない。** ⭐ **音と投稿文だけの話として置く**
  （※ の扱いは V121 の meta を見る ＝ **アプリが写していないことを断る ※ は残す**）

## 5. 保留・不採用（理由つき）
