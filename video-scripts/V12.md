## 1. 画面の流れ（demos-stereo.json の8ステップと一致）

| # | 画面（操作） | テロップ | アプリの表示 |
|---|---|---|---|
| 1 | α-D-グルコピラノースが置かれた状態から開始（`state`）。ハース図の寄り | 水に溶かしたグルコース、形は1つだけ？ | 名称チップ「α-D-グルコース（α-D-グルコピラノース） C₆H₁₂O₆」 |
| 2 | 自由モードへ | ① 結晶は α型（-OH が下） | 反応候補に「開環 → 鎖状の D-グルコース」だけが出る |
| 3 | 開環を実行（2段階モーフィングの**第1段階で止まる**） | ② まず結合が切れる（六角形のまま） | **六角形の配置のまま C1–O5 が切れ、C1 が C=O になった図**。名称チップは既に「D-グルコース（鎖状）」 |
| 4 | 画面をクリック → 第2段階 | ③ 伸びて鎖状に ＝ アルデヒドが出る | フィッシャー投影へ整列。**アルデヒドの C=O がハイライト** |
| 5 | 環化 → β を実行（**第1段階で止まる**） | ④ すぐにまた折りたたまれる | **結合はまだ無いまま、六角形の配置に折りたたまれた図** |
| 6 | 画面をクリック → 第2段階 | ⑤ 結合ができて β型（-OH が上） | 環が閉じ、**C1・アノマー OH・環内 O がハイライト**。OH は上向き |
| 7 | 静止 | 答え: 開いた形を経て α と β が平衡に達する（変旋光） | 名称チップ「β-D-グルコース（β-D-グルコピラノース）」 |
| 8 | 静止 | 次回: 乳酸の D体と L体 | 〃 |

- **環化・開環は2段階モーフィングを持つ唯一の反応**（`reactor.js` の `morphStages`）。
  開環は `bondsFirst`（①結合だけ切る ②鎖状に整列）、環化は `moveFirst`（①折りたたむ ②結合ができる）。
  **第2段階はユーザーのクリックで進む**ので、デモでは `click` アクションで進めている
  （`game.handleMouseDown` → `reactor.skipMorph()` → `advanceMorph()`。クリックは消費されるので**原子は置かれない**。
  収録結果の分子式が最初から最後まで C₆H₁₂O₆ のままであることで確認した）
- **第1段階のアニメ自体はシートの裏で走る**。`reactionButton` はシートを開いてから押すので、
  700ms の第1段階が終わるころにシートが閉じる。**動くところが見えるのは第2段階だけ**で、
  第1段階は「止まった図」として見せている。この構成なら**動く見せ場が2回**（③と⑤）入る
- クリック位置は論理座標 **(300, 120)** ＝ 常に空白。最寄りの原子まで 70 以上ある

## 2. ナレーション全文（ずんだもん版・VOICEVOX）

正は [narration/V12.json](narration/V12.json)。

> グルコースを水に溶かすと、形が変わるのだ。どういうこと？
> 結晶のグルコースは、六角形に閉じたアルファ型。
> 水の中では、まずこの結合が切れてひらくのだ。
> 伸びるとくさり状。アルデヒドが顔を出すのだ。
> でも、すぐにまた六角形へ折りたたまれるのだ。
> 結合ができて、こんどは上向きのベータ型。違いはここだけ。
> ひらいた形を通って行き来するから、割合が一定になって落ち着くのだ。これが変旋光。
> 次は、ヨーグルトと筋肉の乳酸、ディーたいとエルたいなのだ。

読み仮名の確認で**実際に直したもの**（`narrate.py` の出力を毎回見ること）:

- **「環」は一度も使わない**。既知の誤読（環→たまき）を避けるため、**すべて「六角形」に置き換えた**
- **「エル体」→ エルカ'ラダ**（体＝からだ）と読まれた。**「エルたい」と仮名で書いて解決**。
  「ディー体」は ディイタ'イ で正しいが、そろえて「ディーたい」にしている
- **「OH」→ オオエ'ッチ** と間延びするので、**言うのをやめてテロップに逃がした**
  （テロップ側は「-OH が下」「-OH が上」と書いている）
- 確認済みで問題なかったもの: 変旋光→ヘ'ンセンコオ／くさり状→_クサリジョオ／
  結合→ケツゴオ／行き来→イ_キキ／上向き→ウワムキ／六角形→ロッカ'ッケエ

## 3. 化学の裏取り（実機で確認したこと）

- **α → 鎖状 → β が実際につながる**。α-D-グルコピラノースを置いて `開環` → `環化 → β` を通すと、
  名称チップが **α-D-グルコース → D-グルコース（鎖状） → β-D-グルコース** と変わる。
  アプリの判定は `canonicalStereoCode` の一致（`isRegisteredCompound`）なので、
  **立体込みで「登録済みの α/β/鎖状と同じもの」であることが保証されている**
- **α と β の違いは C1 の -OH の向きだけ**。実機で座標を読むと、
  α は アノマー O が (500, 338)＝環の下、β は (500, 268)＝環の上で、**ほかの原子の相対配置は同一**。
  テロップ「違いはここだけ」はこの実測に基づく
- **「交互に変化する」とは言わない**。α と β の間に直接の反応ルールは無く、
  **α からは開環だけ、鎖状からは環化（α/β の両方）だけ**が候補に出る。
  アプリの反応候補がそのまま「開いた形を通らないと行き来できない」ことの証明になっている
- **「平衡に達する」の言い方**: ナレーションは「**割合が一定になって落ち着く**」、
  テロップは「**開いた形を経て α と β が平衡に達する**」。
  どちらも「行ったり来たりの結果、組成が変わらなくなる」という意味に読める形にしてある
- **α/β 面マーク（`#btn-haworth-mark`）は使わなかった**。あれは `haworthFace` を編集する道具で、
  **未設定の置換基を最初にタップすると ▲（上）が付く**（`game.js` の
  `clickedAtom.haworthFace = (clickedAtom.haworthFace === 1) ? -1 : 1`）。
  呼び出した α の C1-OH は図では下にあるので、**1回目のタップで図と食い違う ▲ が出てしまう**。
  α/β の違いはハース図の上下でそのまま見えるため、道具を使わないほうが安全と判断した

## 4. 座標と構図の根拠

3つの状態（α環・鎖状・β環）を**同じ `frame` で通す**。付け替えると画が跳ねるため。

| 状態 | 描画の外接（H こみ・実測） |
|---|---|
| α-D-グルコピラノース | x 278–522 / y 166–396 |
| D-グルコース（鎖状） | x 320–448 / y 140–454 |
| β-D-グルコピラノース | x 278–522 / y 172–402 |

**`frame` は cx 400, cy 270, width 400**（4ステップとも同じ値）。

- 収録は 810×1440 ビューポート。SVG は 796×1224 なので、**見える論理高さ ＝ `width` × 1.538**
  （`preserveAspectRatio` の meet で幅が先に合う）。width 400 → 見える高さ 615
- **上を空けるのは `.rec-short` のオーバーレイのため**。テロップが top 9%、名称チップが top 23% にあり、
  **画面上端から 27% ほどが死んでいる**。最初 `cy 288` で撮ったところ、
  **鎖状の一番上の O が名称チップの下辺に食い込んだ**（フレームを抜いて発覚）。
  `cy` を 18 下げて（＝被写体を下へずらして）解決した
- 下は SNS のUI帯（下 25%）に入れない。この値で鎖状の最下端が画面の 73% に収まる

```
  --out=video-scripts/out/V12-final.mp4
```

- 実測コスト（この回で確かめたもの）: **`click`（キャンバスの空白をタップ） 0.94〜0.95s**。
  LANES.md の表に無かったので、`wait` は 0.95s として逆算した
- テロップとナレーションのずれ（`--events` − 累積秒）は
  **+0.30 / +0.27 / +0.29 / +0.24 / +0.24 / +0.15 / +0.12 / +0.18 秒**で全ステップが窓（0.1〜0.4秒）の中
  （`cy` を直す前の収録では +0.24〜+0.34 だった。**収録ごとに 0.1〜0.2秒は揺れる**）
- **`video-scripts/out/.tmp` は収録の共有作業場所**。別レーンが同時に収録していると
  `EBUSY` / `ENOENT scandir .tmp` で落ちる。**再実行すれば直る**ので、
  リトライ付きで回すとよい（実際に4回連続で衝突した）
