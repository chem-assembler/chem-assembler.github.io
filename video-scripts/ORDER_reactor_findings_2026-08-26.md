## 1. ⛔ 付加重合が**スチレンでは効かない**（塩化ビニルでは効く）

### 再現手順

```
自由モードで スチレン を summon で4つ並べる
→ 「反応させる・調べる」を開く
→ 「付加重合（並べた単量体をまとめて）→ 高分子の繰り返し単位」を押す
```

**ボタンは一覧に出ている**（画面を撮ってある。§3 の再現コマンドで同じ画が出る）。
**押しても分子はスチレン4つのまま**で、結末は `C₃₂H₃₂ ① スチレン ＋ ② スチレン ＋ ③ スチレン ＋ ④ スチレン`。

**同じ手順を 塩化ビニル に替えると通る**（`C₈H₁₂Cl₄R₂`）。
＝ **多分子・同一単量体の流れ自体は動いている**。スチレン側の何かで止まっている。

### 動画レーンが読んだ範囲（当たりを付けただけ。断定していない）

- `vinylBonds` は **環内の C=C と芳香族結合を除く**（1648行・1650行）ので、
  スチレンのビニル基（環の外）は1本だけ残るはず ＝ `detect` の
  「1分子に C=C が2本以上あるものは除く」には引っかからないように見える
- 頭尾は `heavyN` で決まる。スチレンは **環側の炭素が head、=CH₂ が tail** になる
- ⚠ **怪しいのは並べ替えの向き**（3128〜3141行・v1436 の §14 の直し）。
  `sum = Σ(head座標 − tail座標)` の符号で並べ替えの向きを決めているが、
  スチレンは **head 側に環がぶら下がっている**ので、`summon` が置いた配置での
  head/tail の向きがエチレン系と揃わない可能性がある。
  向きが逆だと**鎖が並びと逆向きに伸びようとして塞がれる**——
  同じ節のコメントが「右隣が塞がっているぶん階段状に折れていた」と書いている症状の親戚に見える
- **ただし今回は「折れた」のではなく「1本も繋がらなかった」**ので、別の原因かもしれない

### 動画レーンとしての扱い

**V120（発泡スチロール）は諦めて、塩化ビニル（PVC）に題材を替えた。**
スチレンで通るようになったら「発泡スチロールを一から」は作りたい
（**身近さでは PVC より強い**ので）。

## 2. ⚠ 側鎖酸化は**メチル基だけ**（仕様。念のため記録）

エチルベンゼンの反応一覧に側鎖酸化は出ず、「⚠ 酸化（ここでは図を変えない範囲）」だけが並ぶ。

**これは仕様**で、`reactor.js` 1452〜1456行に理由が書いてある——
「炭素2個以上の側鎖でも生成物は安息香酸だが、**切れて出ていく側の行き先（CO₂・カルボン酸）が
条件で変わるので図にしない**」（DESIGN_reaction_execution.md §10.3）。

⚠ **直してほしいという話ではない。** ただし動画レーンとしては
「トルエンでもエチルベンゼンでも同じ安息香酸」が**この回のいちばん面白いところ**だったので、
**§10.3 の線引きを緩める余地があるなら知りたい**（例: 切れた側を描かず「＋ 酸化生成物」とだけ置く、
info ルールで「エチルベンゼンも安息香酸になる」と文章で返す、など）。

## 4. ⛔ 重合まわり（ユーザー申し送り「重合まわりはまだチェックできていない」を受けて）

**第2陣で 1,4-付加重合 と 加硫 を通した。§1（スチレンの付加重合）と同じ形の詰まりが出る。**

### 4-1. 加硫を1本の鎖に掛けると、**分子内で橋が架かる**

```
イソプレン ×4 を並べる → 1,4-付加重合 → 加硫
```

結末は `C₂₀H₃₄R₂S`。**硫黄は入る**（重合も加硫も動いている）。
⚠ ただし**鎖が1本しかないので、橋が同じ鎖の中で架かってループになる**。
画では鎖が斜めに引かれ、そこを硫黄の橋がまっすぐ横切る——
**「2本のゴムの鎖を橋でつなぐ」という加硫の絵になっていない**。

`vulcanization` のコメントは
「1本目の架橋で2本の鎖が1分子になっても、続けて架橋できる必要がある」と書いており、
**2本以上の鎖を前提にしている**ように読める。
だとすると **1本の鎖に掛けられてしまうのは想定外**かもしれない
（`vulcanizablePairs` が同一成分の C=C の組も返している）。

### 4-2. 鎖を2本つくろうとすると、**2回目の重合が効かない**

```
イソプレン ×2 → 1,4-付加重合（→ ① C₁₀H₁₆R₂ ができる）
→ イソプレン ×2 を追加 → 1,4-付加重合  ← ここが効かない
→ 加硫                                  ← ボタンが見つからず再生が止まる
```

結末は `C₂₀H₃₂R₂ ① （該当なし） ＋ ② イソプレン ＋ ③ イソプレン`
＝ **追加した2つはイソプレンのまま**。

⚠ **パネルの分析対象が ① に固定されている**のが関係していそう。画面にはこう出ている:

> **分析中: ① この分子 … C=C二重結合（アルケン）×2**
> 【3分子】キャンバス全体: C=C二重結合（アルケン）×6
> **いま見ている「C₁₀H₁₆R₂」が関わる反応だけを出しています**
> （ほかの分子の反応は、上のタブか図の分子名から切り替えると出ます）

この状態で「この分子にできること」に並ぶのは
酸化／付加: Br₂／H₂／HBr／HCl／HI で、**②③ のイソプレンどうしの重合は出ていない**。

⚠ **そのあとの加硫はボタンが見つからず、`reactionButton` が例外を投げて再生が止まる**
（38.56秒で終了。台本は約50秒の予定だった）。

### 4-3. §1 との関係

**スチレンの付加重合（§1）も「ボタンは出て押せるのに効かない」形**だった。
- スチレン ×4 … 押せる・効かない
- 塩化ビニル ×4 … 効く
- イソプレン ×4（1,4-付加重合）… 効く
- **イソプレン ×2 を2回に分けて** … 2回目が効かない

**「効く／効かない」がきれいに分かれていない**ので、動画レーンからは原因を1つに絞れない。
共通しているのは **多分子をまとめる系のルール**であることだけ。

### 4-4. 動画レーンとしての扱い

**V125（ゴムと加硫）は保留にした。**
- 1本の鎖に掛けた絵（§4-1）は**化学として誤解を招く**ので出せない
- 2本の鎖にする手順（§4-2）は**そもそも通らない**

⚠ **台本 `reaction-rubber-vulcanization` は消していない**——§4-2 の再現手順そのものなので、
`sns: false` にして**再現用に残してある**。

### 6-1. ⛔ 加硫は**箇所選び（`narrow`）が終わらない**——押しても永久に確定しない

**「鎖が2本あれば加硫できる」ところまでは直っている。**札も出るし、`detect` も候補を返す。
**止まっているのは、そのあとの「どこに架けるか」を選ばせる所**。

```
イソプレン ×2 → 1,4-付加重合 → イソプレン ×2 を追加 → 1,4-付加重合 → 加硫
```

実測（`reactor.picking` を直接読んだ）:

```
btn: 加硫（硫黄で鎖を架橋する）→ 弾性ゴム（7箇所）
picking: あり sites=7
sites: C(337,336)/C(316,300)/C(694,342)/C(715,378)  ← ①
       C(484,373)/C(463,336)/C(841,378)/C(862,415)
       C(316,300)/C(337,336)/C(694,342)/C(715,378)  ← ③ ①と同じ4原子
       C(463,336)/C(484,373)/C(841,378)/C(862,415)
       C(484,373)/C(463,336)/C(862,415)/C(841,378)
       C(316,300)/C(337,336)/C(715,378)/C(694,342)  ← ⑥ ①と同じ4原子
       C(463,336)/C(484,373)/C(862,415)/C(841,378)
```

**`detect` が返す `[ca, ca2, cb, cb2]` は「どちらの炭素に硫黄が付くか」で向きが違うだけで、
4つの原子の集合は同じ**。だから `handlePick` が

- `matched.length === 1` … 実行
- `matched.length > 1` … `narrow` で**もう一度選ばせる**

の後者へ落ちたあと、**`narrow` の `distinguishing`（＝どのサイトにも入っているわけではない原子）が空になる**
＝ **何を押しても同じ3組（または4組）に戻る**。実測でも4回連続で同じ原子に戻り、硫黄は1つも入らなかった:

```
#0 sites=7 → click C(316,300)
#1 sites=3 → click C(316,300)
#2 sites=3 → click C(316,300)
#3 sites=3 → click C(316,300)
式: C₂₀H₃₂R₄   S: （なし）
```

⚠ **台本の問題ではない**。`tutorial.js` の `reactionButton` は1回しかクリックしないが、
**人が何回押しても確定しない**ので、手で操作しても同じところで止まる。

⚠ **`sites.length === 1` なら `narrow` は即実行する**ので、
**「候補が1組だけになる並べ方」を台本側で作れれば回避できる**——が、
イソプレン×2 の鎖は C=C を2本持つので、鎖2本で最低でも4組×向きになり、**1組には落ちない**。
**動画レーンの手では避けられない。**

## 7. ⛔ 反応のハイライトが消えない——別の分子を出しても前の印が残る（2026-08-28）

**ユーザーが V115 の完成品を見て見つけた。** 発見の言葉:

> **0:13でケトンのマーカーだけさきに表示される。マーカーは反応後の0:20以降に表示されるべきでは？
> このマーカーは3級アルコールのときも表示され続ける**

### 7-1. 実測（V115 の完成 mp4・フレーム4枚）

台本は「**分子を出す → 反応させる**」を3回くり返す（1級・2級・3級）。
最終動画での局面の時刻は 0.15 / 9.29 / 15.56 / 21.06 / 27.68 / 32.49秒。

| 時刻 | 画面 | 印 | 正しいか |
|---|---|---|---|
| **5秒** | 1-プロパノール（**まだ一度も反応していない**） | **無し** | ✅ |
| 13秒 | プロピオンアルデヒド（1級を酸化した**あと**） | あり | ✅ |
| **17秒** | 2-プロパノール（**出しただけ。反応は21秒**） | **あり** | ⛔ |
| **29秒** | 2-メチル-2-プロパノール（**出しただけ。押すのは32秒**） | **あり** | ⛔ |

⭐ **5秒に印が無いことが効いている**——「summon したら印が付く」仕様ではなく、
**前の反応の印が残っている**と分かる。

### 7-2. 読んだ範囲での原因

- `game.js:10082` `highlightAtoms()` は `uiGroup` に破線の円を足す（先頭で `clearUIOverlay()`）
- `reactor.js:6581` が反応の実行後に `highlightAtoms` を呼ぶ（**ここは正しい**）
- ⚠ **`clearUIOverlay()` を呼ぶ唯一の「人の操作」は `game.js:888` の
  `svg.addEventListener('pointerleave', …)`**
- ⛔ **`#btn-clear-all`（全消去）も `summon`（名称から呼び出す）も `clearUIOverlay()` を呼んでいない**

**＝ キャンバスを空にして別の分子を出しても、前の反応の印がそのまま残る。**
`frame` で view が合わせ直されるので、印は**新しい分子の上に乗って見える**
（V115 では、たまたま次に反応する場所とほぼ重なった）。

⚠ **これは録画だけの話ではない。** 人が触っていても「全消去 → 別の分子を呼ぶ」の順で
**同じことが起きる**（マウスを図の外へ出せば消えるので気づきにくい）。

### 7-3. ⛔ 台本側では回避できない

**動作の一覧に `pointerleave` を起こすものが無い。**
`hover` は `svg.dispatchEvent(pointermove)` しか出さない（`tutorial.js:451-457`）。
`button` はボタンの矩形へカーソルを動かすだけで、SVG の `pointerleave` は発火しない。

**→ 直せるのはアプリ側だけ。** 直し方はそちらの判断だが、動画レーンから見ると
**「全消去」と「名称から呼び出す」で `clearUIOverlay()` を呼ぶ**のが素直に見える。
