# 投稿キュー（出す順）

**このファイルが持つのは「出す順」だけ。** 1本ぶんのデータ（タイトル・投稿文・投稿日・URL）は
`video-scripts/meta/<ID>.json` にあり、そちらが正。**二重に書かない。**

- **このファイルは main（管理役）が持つ。レーンは触らない**（4レーンが同じ行を編集すると毎回衝突するため）
- レーンは `meta/<ID>.json` を作って自分のブランチにコミットするだけでよい。
  `node tools/videos.js` が「meta にあるのに QUEUE に無い」を検出するので、管理役が取りこぼさない
- 在庫表・不整合の確認は `node tools/videos.js`（URLも見るなら `--urls`）

## 順番を決めるときの原則

1. **予告を出した回は、その次に必ず回収する**。V16→V17・V6→V11・V11→V18 は動画の中で
   「次回」と言っているので、間に別の回を挟まない
2. **シリーズは出し切ってから切り替える**。異性体を全部出してから反応へ移ると、
   「この枠は毎回同じ型」が伝わってフォローの理由になる
3. **新機能を題材にした回は鮮度があるうちに**（V15）
4. **短い回は差し込み用に温存する**（V13・26秒）

## 投稿したらやること

1. `meta/<ID>.json` の `posted` に**投稿日と媒体別のURL**を書く
   ```json
   "posted": { "date": "2026-08-05", "youtube": "https://…", "tiktok": "https://…",
               "instagram": "https://…", "x": "https://…" }
   ```
2. `node tools/videos.js --urls` で入ったことを確認する

**URLを残す理由**（面倒でも省かない）:

- **次の回が前作にぶら下がる**。投稿文のチェックリストに「V6 にぶら下げてスレッドにする」
  「V16 をカードか固定コメントでつなぐ」と書いてあるが、**前作のURLが無いとそこで手が止まる**
- **UTM（`?utm_campaign=v6`）と突き合わせる**ため。どの動画がアプリへ何人送ったかは、
  「投稿日・URL・campaign」が揃って初めて読める
- **1本につきURLが4つ**（三面＋X）。記憶にも履歴にも頼れない

**やらないこと**: 再生数・いいね数をここに書き写す。手作業の写経は続かないし、
各媒体の管理画面が持っている。ここに置くのは**自分にしか作れない対応表**（ID ↔ URL ↔ campaign）だけ。
