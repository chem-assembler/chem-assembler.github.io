> ### ⚠ 予約投稿は「URL がまだ無い」状態を作る（2026-08-06 に踏んだ）
>
> **予約しただけの回には公開 URL が存在しない。** そのため**次の回の投稿文が空欄のまま生成される**。
>
> - **X の下書き・予約には URL が無い**（投稿された瞬間に初めて ID が振られる）。仕様なので取得方法の問題ではない
> - **Meta Business Suite で予約した Instagram の「リンク」は `facebook.com/<数字>` 形式**で、
>   **公開リールの URL（`instagram.com/reel/…`）ではない**。**台帳に入れないこと**
>   （解決しない URL が入ると、次の回のぶら下げと UTM の突き合わせが静かに壊れる。空欄のほうが安全）
> - 公開後の取り方: Instagram はアプリでリールを開く → `⋯` → リンクをコピー。
>   X は該当ポストを開く → 共有 → リンクをコピー
>
> **手順**: 公開 → URL を `meta/<ID>.json` の `posted` へ → **次の回の投稿文を作り直す**
> （`node tools/record/mux.mjs --metaonly --video=<mp4> --out=<同じmp4> --meta=<json>`）。
> これを飛ばすと、次の回の固定コメントと X 自己返信が
> 「※ 前作の URL がまだ台帳にありません」のまま出る。
- **1本ずつ完了させる**（次の回の X 自己返信と YouTube 固定コメントが前作のURLを要るため）。
  1本 → URLを台帳へ → `node tools/videos.js --refresh` → 次の1本
- **見るのは翌日以降の「コンテンツ ページ」の累計視聴回数**。4本目だけ落ちていたら境目は4と5でなく3と4
- 結果が出たら**この節を結果で上書きする**（予定のまま残さない）

### 運用

- **絞られても慌てて消したり上げ直したりしない。** YouTube は TikTok と違い、
  同じ動画を上げ直しても評価は戻らず重複として扱われるだけ。**本数を戻して様子を見る**
  （8/2 に1本へ落としたら翌日には通常に戻った＝**絞りは一時的**）
- **同じ日に複数出すときは、順番どおりに1本ずつ完了させる。**
  次の回の X の自己返信と YouTube の固定コメントが**前の回のURLを必要とする**ため、
  まとめて上げると導線が空欄のまま出る。**1本 → URLを台帳へ → `node tools/videos.js --refresh` → 次の1本**
- 在庫は十分あるので**急ぐ理由がない**（`node tools/videos.js` の在庫表を見ること）
- **YouTube は予約投稿でよい**（V13 は 19:00 予約）。時刻を散らすと1日の中でも山が分かれる

## 順番を決めるときの原則

1. **予告を出した回は、その次に必ず回収する**。V16→V17・V6→V11・V11→V18 は動画の中で
   「次回」と言っているので、間に別の回を挟まない
2. **シリーズは出し切ってから切り替える**。異性体を全部出してから反応へ移ると、
   「この枠は毎回同じ型」が伝わってフォローの理由になる
3. **新機能を題材にした回は鮮度があるうちに**（V15）
4. **短い回は差し込み用に温存する**（V13・26秒／V22・31秒）。
   **差し込み用の回には次回予告を持たせない**（持たせると差し込めなくなる。2026-08-01・V22 で判明）

## 投稿したらやること

1. `meta/<ID>.json` の `posted` に**投稿日と媒体別のURL**を書く
   ```json
   "posted": { "date": "2026-08-05", "youtube": "https://…", "tiktok": "https://…",
               "instagram": "https://…", "x": "https://…" }
   ```
2. `node tools/videos.js --urls` で入ったことを確認する

**URLを残す理由**（面倒でも省かない）:

- **次の回が前作にぶら下がる**。投稿文のチェックリストに「V6 にぶら下げてスレッドにする」
  「V16 をカードか固定コメントでつなぐ」と書いてあるが、**前作のURLが無いとそこで手が止まる**
- **UTM（`?utm_campaign=v6`）と突き合わせる**ため。どの動画がアプリへ何人送ったかは、
  「投稿日・URL・campaign」が揃って初めて読める
- **1本につきURLが4つ**（三面＋X）。記憶にも履歴にも頼れない

**やらないこと**: 再生数・いいね数をここに書き写す。手作業の写経は続かないし、
各媒体の管理画面が持っている。ここに置くのは**自分にしか作れない対応表**（ID ↔ URL ↔ campaign）だけ。
