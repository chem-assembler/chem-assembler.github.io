## A. エステルが「🔤 官能基をまとめる」でまとまらない

### 実測（v1375）

| 分子 | 押す前 | 押した後 |
|---|---|---|
| **酢酸** | `H H H H C C O O` | **`H H H C COOH`** ✅ |
| **酢酸エチル** | `H×8 C C O O C C` | **変化なし** ❌ |

酢酸ではトースト（「官能基をまとめて表示しています…」）が出てボタンも
`🔤 結合をすべて表示` に反転するが、**酢酸エチルでは何も起きない**。

### なぜ困るか

**示性式 `CH₃COOC₂H₅` は高校で必ず書かされる形**。エステルは
「カルボン酸とアルコールから水がとれてできる」を示性式で追うのが定番の説明で、
そこがまとまらないと**この機能はカルボン酸止まり**になる。

ボタンの title は「-COOH や -NO₂ などの官能基を、1つのカードにまとめて表示します」なので、
**意図的にエステルを外している可能性はある**。その場合は仕様として確認したい。

### 決めてほしいこと

1. **エステル `-COO-` をまとめる対象に足す**（`CH₃COOC₂H₅` まで出せるようにする）
2. **足さない**（カルボン酸・ニトロなど「1つの原子団で閉じる」ものだけに限る、が仕様）

**1を勧める**。エステルは高校有機の山場（けん化・油脂）で、示性式で書けないと説明が続かない。
ただし `-COO-` は**両側に炭素が続く**ので、カルボン酸のように「端の1かたまり」として
扱えない可能性がある——そこが実装上の難所だと思う。

### 受け入れ条件（1を選ぶ場合）

- [x] 酢酸エチルで `CH₃COOC₂H₅` 相当の表示になる
- [x] もう一度押すと結合が全部もどる（カルボン酸と同じ往復）
- [x] 作図データが変わらない（トーストの文言どおり）
- [x] 回帰テストが全合格

⚠ **V102 の台本は「カルボン酸で撮る」前提で書いてある**ので、**この件は収録の妨げにならない**。
1で直ったら、V102 の②に「エステルでも同じ」を1手足せる。

### ✅ 決着（案1を実装。`03c7d18` / main は v1380）

**直しは「新しい種類を足す」ではなく「1つに決め打っていた所を可変にする」だった。**
`findCondensableGroups` が返す形の `anchorId`（分子側の接続点が**1つ**）を `anchorIds`（配列）にし、
2つ以上のときだけカードを**アンカーの間**に置いて線を2本出す。
`-COOH` `-CHO` `-NO₂` `-SO₃H` は末端なので1つで足りていた ＝
**「畳んだ先は行き止まり」が構造に埋め込まれていた**のが、エステルだけ畳めなかった理由。
既存4種は `anchorIds:[id]` になっただけで置き方も見た目も無変更。

実測: 酢酸 `H H H C COOH`（変わらず）／酢酸エチル ❌ → **`CH₃COOC₂H₅`**／
ギ酸メチル ❌ → **`HCOOCH₃`**／安息香酸エチル ❌ → 環そのまま＋`[COO] C C`／
**トリステアリン（油脂）0枚 → COO 3枚**（けん化を示性式で追える）。

⚠ **ギ酸メチルは受け入れ条件の外だが足してある**（ラベルは `HCOO`。`COO` にすると図が
`CH₃` だけになりギ酸エステルだと読めない）。ギ酸そのものを外している既存の線引きとはずれる。

## B. 反応機構ビューアは「反応を選ぶ」だけでは始まらない

### 症状（v1375・実測）

**📚学習 → ⚗️ 反応機構ビューア** を開いて**一覧から反応を選んでも、何も起きない**。
キャンバスは空のまま、ステップ送りの帯（`#ws-reaction`）も出ない。

実体は**「反応機構モード」のチェックボックス**のほうで、そこを入れて初めて始まる
（`reactionPlayer.active` が false のあいだ、select の change は無視される実装）。
チェックを入れると学習モーダルが自動で閉じ、帯 `🔄 ⏮ ▶ ⏭ 🎯 予測 判定 やめる` が出る。

### なぜ困るか

**その場の案内文が「選べば始まる」と読める**:

> 反応を選ぶと、ステップ送り（⏮ ▶ ⏭）はキャンバスの下に出ます。

選んでも出ないので、**入口で止まる**。台本を書くためにこちらが押したときも実際に詰まった
（コードを知っていて、原因が分かるまで数回試した）。**初見の生徒は「壊れている」と判断する**。

### 直し方の案

1. **select を選んだら、チェックが入っていなくても始める**（＝ 案内文どおりにする）。
   実装は `selectEl` の change で `active` を見ずに `enter()` を呼ぶだけ。**これを勧める**
2. チェックを外すと止まる、は今のまま残す（出口としては分かりやすい）
3. 1が難しければ、**案内文を実態に合わせる**（「反応機構モードをオンにすると…」）。
   ただし**選んでも動かない**こと自体は残るので、次善

### 受け入れ条件（1の場合）

- [x] 一覧から反応を選ぶだけで、学習モーダルが閉じて帯が出る
- [x] チェックボックスの表示が「オン」に追従する（状態が2つに割れない）
- [x] チェックを外すと今までどおり止まる
- [x] 回帰テストが全合格

⚠ **V104 の台本はチェックを入れる手順で書いてある**ので、**収録の妨げにはならない**。
1で直ったら台本の②を1行消すだけ。

### ✅ 決着（案1を実装。`247a8e4` / main は v1379）

直しは `selectEl` の `change` から `if (this.active)` を外して無条件に `enter()` を呼ぶだけ。
`enter()` が `checkMode.checked = true` を立てるのでスイッチの表示は自動で追従する。出口は無改変。

```
直す前 ①一覧で選ぶ     active=false ❌ / 帯 隠れ ❌ / チェック false ❌ / モーダル 開いたまま ❌
直した後 ①一覧で選ぶ    active=true / 帯 出る / チェック true / モーダル 閉じる
直した後 ②スイッチを切る  active=false / 帯 隠れ / チェック false
```

**案内文も実態に合わせた。** 入口が select になった以上**止め方がどこにも書いていない**状態に
なるため「上のスイッチを切ると終わります」を足した。

⚠ **ここから次の問題が生まれた**（2026-08-17・ユーザー指摘で着手）: スイッチは入口として
使われなくなり**実質「やめる」スイッチ**になったのに、ラベルは「反応機構モード」のままで、
しかも**帯（`#ws-reaction`）には終了ボタンが無い** ＝ 見ている画面から抜ける道が無い。
v1392 で直した「学習の出口」と同じ系統。**帯に終了ボタンを足す**方向でユーザーが判断済み。

## C. 3つの書き出し練習で、操作の型がそろっていない

### 実測（v1375）

同じ「✏️ 構造の書き出し練習」のアコーディオンの中に3つ並んでいるのに、**答案の作り方が3通り**ある。

| 練習 | 答案の作り方 | 画面の帯 |
|---|---|---|
| ✏️ **異性体**の書き出し | **キャンバスがそのまま答案用紙**（登録という操作は無い） | `いま 3個 描いてあります` |
| ✏️ **アルキル基**の書き出し | **枠を増やす**（`＋ 答案をもう1つ`） | `いま 0枠 に描いてあります` |
| 🪞 **立体異性体**の書き出し | **1つずつ登録**（`＋この立体を登録`） | `0/3` |

### なぜ困るか

**`DESIGN_isomer_practice.md` §0 の失効表は「登録という操作を廃止した」と書いている**
（v147 の調整 → 本改訂で §12「キャンバスを答案用紙にする」へ）。異性体はそうなり、
アルキル基も「枠」という形で追随したが、**立体異性体だけ古い「登録」のまま残っている**。

生徒から見ると、**隣り合った3つのボタンで操作が変わる**。
「異性体では並べて描いたのに、立体では1つずつ登録」——覚え直しが要る。

⚠ **ただし立体は事情が違う可能性がある。** 立体異性体は**つながり方が同じで置換基の向きだけが違う**ので、
**同じ図を動かして作る**——並べて描く形と相性が悪い（1つのキャンバスに同じ骨格を4つ並べると読めない）。
**「登録が正しい」という結論もありうる**。

### 決めてほしいこと

1. **立体も「並べて描く」に寄せる**（3つの型を1つにする）
2. **立体は登録のままでよい**（動かして作る性質上こうなる、と設計書に書いて閉じる）
3. **アルキル基の「枠」も含めて3つとも意図どおり**と確認し、**言葉だけそろえる**
   （「答案」「枠」「登録」が混ざっているのを、どれか1つの言い方に統一する）

**3を勧める。** 操作を変えるのは重く、**立体を並べる形にすると読めなくなる**恐れが実際にある。
いっぽう**言葉の不統一は安く直せて、効き目がある**——3つのボタンが同じ場所に並んでいる以上、
**同じ語で説明されている**だけで「同じ種類の練習だ」と伝わる。

### 受け入れ条件（3の場合）

- [x] 3つの練習の帯とパネルで、答案を指す語が1つにそろっている
- [x] 設計書（DESIGN_isomer_practice.md）に**なぜ立体だけ操作が違うのか**が1行ある
      → **違わなくなったので「経緯」として** §12-8 に書いた
- [x] 回帰テストが全合格

⚠ **V105・V106 の台本は今の形のまま書いてある**ので、**収録の妨げにはならない**。

### ✅ 決着

**1（立体も並べて描く形に寄せる）が先に入り、そのうえで 3（語をそろえる）を入れた。**

- **1 は済んでいた**（`DESIGN_practice_revision.md` §5-8a・SW1）。上の ⚠ で心配した
  「1つのキャンバスに同じ骨格を並べると読めない」は、**`🧹 並べ直す`（W4・SW3）で解ける**
  ことが分かったので、登録のままにする理由が消えた
- **3（語）は「個」に寄せた**（「答案」でも「枠」でもなく）。理由: **3つのうち2つが既に
  「個」で数えていて**、答え合わせの見出しも `描いた図 N個` だったから ——
  浮いていた1つを多数派へ寄せるのが、直す量も読み替えの負担もいちばん小さい。
  「枠」は**コード側の内部の言葉として残す**（付け根 C1–R の置き場所のこと）

**実測（着手時 v1386。発注書の表は古かった）**

| 練習 | 直す前の帯 | 直した後 |
|---|---|---|
| ✏️ 異性体 | `いま 0個 描いてあります` ／ `0個` | 変えていない |
| ✏️ アルキル基 | `いま 0枠 に描いてあります` ／ `0枠` | **`いま 0個 描いてあります` ／ `0個`** |
| 🪞 立体異性体 | `いま 1個 描いてあります` ／ `1個`（**発注書の `0/3` は既に解消ずみ**） | 変えていない |

あわせて**立体の答え合わせだけ `あなたが書いた図`** だったのを `描いた図` にそろえた
（他の2つは最初から `描いた図`）。**操作は1つも変えていない**
（`＋ 答案` でアルキル基の枠を明示的に増やせるのはそのまま）。検査は **`IW15`**。

## D. 実験カードが 56枚 並んでいて探せない

### 指摘（ユーザー・2026-08-16）

> このインターフェイスについてですが、カードが多すぎて実際に使うと大変だと思います。
> ここを使いやすくする（カードを分類する・部分一致の検索機能を追加など）のがよいのではないか

### 実測（v1375）

| | |
|---|---:|
| カードの枚数 | **56枚** |
| カード領域の高さ | **1448px** |
| モーダルの窓の高さ | 968px |

**カードの一覧だけで窓の1.5倍**ある。しかも一覧はモーダルのいちばん下なので、
**カウンタ（残り N 通り）を見ながら探すことができない**（V99 の収録手順がここで詰まった）。

⚠ **入試問題を選んでも 56枚のまま**。画面には
「`B　この列の実験 5 枚　→ 正しく積めば 3 通り`」と**必要な5枚が名前で出ている**のに、
それは**表示だけでボタンではない**——**アプリが答えを知っているのに、利用者は 56枚から探す**。

### 中身を数えた（分類の下地）

56枚は**もともと構造を持っている**。並べ直すだけで相当減る。

| 群 | 枚数 | 中身 |
|---|---:|---|
| −OH まわり | 6 | ナトリウム○/×・酸化で級を決める3枚・エーテル |
| C=O まわり | 8 | 銀鏡○/×・IR・還元3枚・ヨードホルム○/× |
| C=C・不飽和 | 5 | 臭素水○/×・水素付加・オゾン分解1種/2種 |
| 酸・エステル | 4 | 炭酸水素Na／中性・加水分解・ラクトン |
| 窒素 | 8 | 塩酸○/×・第一級アミン・アミド○/×・ニンヒドリン○/×・ニトロ |
| 環 | 8 | 環○/× ＋ **3〜8員環が1枚ずつ6枚** |
| 立体・不斉 | 4 | 光学異性体○/×・ジブロモ体・アルキル基を H に換える2枚 |
| 骨格 | 3 | 直鎖/枝分かれ・等価なメチル3つ |
| 脱水（濃硫酸） | 7 | アルケン **1/2/3種類・得られない**・シス-トランス有/無・オゾン分解 |
| 環上の位置 | 2 | −OH と枝分かれ/直鎖アルキル基が隣接 |

**気づいたこと2つ**:

1. **○/× の対が 13組（26枚）ある**（ナトリウム・ヨードホルム・銀鏡・臭素水・光学異性体・環・
   オゾン分解・酸性/中性・塩酸・アミド・ニンヒドリン・シス-トランス・直鎖/枝分かれ）。
   **1行に「陽性／陰性」のトグル**にすれば 26枚 → **13行**
2. **数が軸になっているものがある**——環の員数（3〜8 の6枚）、脱水生成物の数（1/2/3/0 の4枚）。
   **数を選ぶ1行**にすれば 10枚 → **2行**

### 提案（安い順）

1. **部分一致の絞り込み**（ユーザー案）。入力欄1つ。
   ⚠ **実験の文と「＝ 何が分かるか」の両方に当てる**——問題文を読んでいる人は
   「ヨウ素と水酸化ナトリウム」で探し、意味から入る人は「ヨードホルム」で探す。**どちらも通す**
2. **タグで絞る**（ユーザー案の「分類」。**排他的な群ではなくタグ**——下の節）。
   タグを押すとそのタグの付いたカードだけが残る。既定はどれも押していない状態＝全部出る
3. **○/× の対を1行に**（26枚 → 13行）
4. **数の軸を選択に**（10枚 → 2行）
5. **入試問題モードでは、その問題で使う5枚を上に出す**（すでに名前は表示している。押せるようにするだけ）

**1と2だけでも効く。3・4は構造の作り直しになるので後段でよい。**
1〜4 を全部やると **56枚 → 10群・約20行**になり、**畳んだ状態なら10行**＝1画面に収まる。

### なぜ「中〜大」か

- **この機能はいま、いちばん見せたい機能**（構造決定シリーズ V99・V101 の題材）。
  入口で使いにくいと、動画で興味を持った人がそこで落ちる
- **56枚は「全部入っている」証でもある**（2021年の入試19問を実際に解ける網羅性）。
  減らすのではなく**畳む**のが正しい方向
- ⚠ **V99 の収録手順がこの問題の回避策になっている**（最初に400pxスクロールして固定）。
  1・2 が入れば**その回避策自体が要らなくなる**

### 分類は「群」ではなく「タグ」にする（ユーザー・2026-08-16）

> カードの分類については１つのカードが複数の分類に含まれていてよいと思います。
> 自分で考えたのは ・構造関連（環や枝分かれ官能基の有無など）・分子式関連・アルコール関連
> ・反応性・アルデヒド・ケトン関連 などなど

**これで上の「10群」案は捨てる。** 排他的に分けようとすると必ず割り切れないものが出る——
実測でも「銀鏡反応を示さず、還元すると第二級アルコールが得られた＝ケトンをもつ」のように
**アルデヒドとアルコールと C=O をまたぐ**カードがある。

**タグなら1枚に複数付く**。上の実測から素直に付くタグ:

| タグ | 付くカードの例 |
|---|---|
| **構造** | 環○/×・3〜8員環・直鎖/枝分かれ・等価なメチル3つ・環上の隣接 |
| **分子式** | 水素を付加しなかった（不飽和度）・オゾン分解の1種/2種 |
| **アルコール** | ナトリウム○/×・酸化で級を決める3枚・エーテル・還元で第一級/第二級 |
| **アルデヒド・ケトン** | 銀鏡○/×・IR の C=O・還元3枚・ヨードホルム○/× |
| **反応性** | 臭素水○/×・脱水（濃硫酸）7枚・塩酸○/×・加水分解 |
| **酸・塩基** | 炭酸水素Na／中性・塩酸○/×・ニンヒドリン |
| **窒素** | 塩酸○/×・第一級アミン・アミド○/×・ニンヒドリン・ニトロ |
| **立体** | 光学異性体○/×・ジブロモ体の不斉炭素2つ・アルキル基を H に換える2枚 |

**同じカードが複数の列に出る**（例: 「ヨードホルム陽性」は**アルデヒド・ケトン**にも**アルコール**にも。
CH₃-CO- と CH₃-CH(OH)- の両方を指すので、実際どちらでもある）。
タグは**絞り込みの道具**であって分類学ではないので、**重複してよい**というのがこの案の要点。

### 同値な表現をどう扱うか（ユーザーの問い・2026-08-16）

**「同値」には2種類ある。混ぜると設計を誤る。**

#### ① 実験が違うが、分かることが同じ（＝ 言い換え）

銀鏡反応とフェーリング反応はどちらも「アルデヒド」。臭素水と過マンガン酸カリウムはどちらも「C=C」。
**いまのカードは「実験文＝意味」を1枚に固定している**ので、実験を増やすとカードが増える。

**提案: 内部は「制約」、表示は「実験文」の2層にする。**

- 絞り込みの計算に効くのは**制約**（`−OH をもつ`・`C=O をもたない`…）だけ
- 実験文はその**言い換え**にすぎない。1つの制約に**複数の実験文**をぶら下げる
- カードは制約の数だけ。**別名（フェーリング・過マンガン酸カリウム）は検索に引っかかるが、行は増えない**

⚠ 当初は「データ構造の作り直しで重い」と見ていたが、**コードを見たら `test`（制約）と `say`（表示）は
すでに分かれていた**（下の「2層化はほぼ済んでいた」）。残るのは `say` の複数化だけで、軽い。

#### ② 積んだ結果として同じ集合を切る（＝ 冗長・重複）

「環をもたない」と「水素を付加しなかった」は、**その分子式のもとでは同じ集合を切る**ことがある。
これは**カードの性質ではなく、いま解いている問題に依存する**——事前には決まらない。

**ここは直す必要がない。すでに実装されている。** 積んだあとに画面がこう言う（実測）:

```
積んだカードの性質
  ヨードホルム陽性     必須   単独で 11 通り
  炭素間二重結合なし   必須   単独で 30 通り
  第二級アルコール     冗長   単独で 17 通り
  C=O をもたない       冗長   単独で 51 通り
  （C₄H₁₀O の例では「情報ゼロ」「重複」も出る）
```

**①を事前に潰し、②は積んだあとに言う**——この切り分けが答えだと思う。
②を事前に消そうとすると「この問題では冗長」を一覧の段階で判定することになり、
**答えを先に見せてしまう**（絞り込みの面白さがなくなる）。

### ✅ 決定（ユーザー・2026-08-16）

- **タグは上の8つでやってみる**（構造／分子式／アルコール／アルデヒド・ケトン／反応性／酸・塩基／窒素／立体）
- **① の2層化も同時に進める**（後回しにしない）

### ⭐ コードを見たら、2層化はほぼ済んでいた（2026-08-16 実測）

`assembler/narrowing.js` のカード定義は**すでに制約と表示が分かれている**:

```js
{ id: 'na', say: 'ナトリウムを加えると水素が発生した', mean: '−OH をもつ',
  row: '−OH', cell: '○', test: (m) => NW.hydroxy(m) }
```

| 欄 | 役割 |
|---|---|
| `test` | **制約の実体**（絞り込みの計算はここだけ見る） |
| `say` | 実験文（表示） |
| `mean` | 意味（表示） |
| `row` / `cell` | **行と選択肢**。いまは結果の要約表にだけ使われている |

**つまり①の2層化で足りないのは「1つの制約に複数の `say`」だけ**——
`say` を配列にすれば、銀鏡／フェーリングのような言い換えを**行を増やさずに**足せる。

**そして `row`/`cell` がすでにある**ので、「対を1行に」も新しい設計が要らない。
**`row` でまとめると 52枚 → 19行**（実測）:

```
−OH(2) アルコールの級(3) ヨードホルム(2) アルデヒド(2) C=C(2) 不飽和結合(1)
エーテル(1) C=O(4) 光学異性体(2) 環(2) 芳香環(2) オゾン分解(3) 酸・エステル(4)
骨格(3) 付加物(1) 脱水生成物(6) 環上の位置(4) アミノ基(6) アミド(2)
```

**19行ならモーダルの窓（968px）に収まる**。タグで絞ればさらに短くなる。

### やること（この順）

1. **カードの一覧を `row` でまとめる**（52枚 → 19行。`cell` を選択肢として横に並べる）。
   **データ変更ゼロ・UI だけ**。ここだけで「探せない」はほぼ消える
2. **`tags: []` を足す**。**row 単位で付けてよい**（52枚に付ける必要はない）。8タグ
3. **`say` を配列にする**（①の2層化の残り）。いまは1要素でよい。
   **足したい言い換えが出たとき、行を増やさずに足せる**状態にしておくのが目的
4. **部分一致の絞り込み**。`say`（配列の全要素）と `mean` の**両方**に当てる
5. **入試問題モードで、その問題の札を上に出す**（「この列の実験 5 枚」はいま表示だけ。押せるようにする）

**1と2で1画面に収まるようになる。3は将来のための下地、4は仕上げ、5はおまけ。**
### 受け入れ条件（1と2の場合）

- [x] 絞り込みに「ヨード」と入れて、ヨードホルムの2枚だけになる（実験文からも意味からも引ける）
- [x] タグを1つ押した状態で、**カードの一覧がモーダルの窓（968px）に収まる**
- [x] タグを押し外ししてもカウンタ（残り N 通り）が画面から出ない
- [x] **1枚のカードが複数のタグに出る**（例: ヨードホルム陽性がアルコールにもアルデヒド・ケトンにも）
- [x] 積んだカードを外す操作（もう一度押す）が、絞り込み中でもできる
- [x] 回帰テストが全合格

### ✅ 決着（1〜4 を実装。5 は範囲外のまま）

**この発注書の枚数は数え落としていた。** 正しくは **58枚・20行**（52 は
`NARROW_CARDS` のリテラルだけで、**ループで足している環の大きさ 3〜8員の6枚・1行が入っていない**）。
