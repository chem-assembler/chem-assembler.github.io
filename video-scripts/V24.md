## なぜこの見せ方か（2026-08-02 の判断）

### 作図（キャンバス）では出題が成立しない

最初に検討したのは **キャンバスに2分子を並べる ①②型**（V11 で実証済み）だった。**実機で確かめて没にした。**

アプリはキャンバスに分子が2つ以上あると、

1. **各分子の下に SVG の見出し「① ペンタン」「② 2-メチルブタン」を描く**（`renderMoleculeLabels`）
2. **モバイル名称チップに「① ペンタン ＋ ② 2-メチルブタン　C₁₀H₂₄」と出す**（`syncMobileNameChip`）。
   `rec-short` ではこのチップが画面上部23%に25pxで出る＝**いちばん読まれる位置**

実測（ペンタン＋2-メチルブタンを呼び出して DOM を読んだ）:

```
chip   : ① L-乳酸 ＋ ② ペンタン ＋ ③ 2-メチルブタン　C₁₃H₃₀O₃
labels : ["① L-乳酸", "② ペンタン"]
```

**名前が出た時点で答えが割れる**ので、「3秒静止して考えさせる」が成立しない。
名前の出ない化合物（o-ジクロロベンゼン等）を選ぶと今度は
チップが「① （該当なし） ＋ ② （該当なし）」になり、機械判定を見せる手段が消える。
**キャンバスに寄りで逃げることもできない**（チップは `position: fixed` の DOM なので `frame` で切れない）。

### だからアプリのクイズ画面をそのまま使う

`#btn-quiz`（🎓 同じ化合物？）のモーダルは、**2つの図を名前なしで並べ、「同じ」「違う」の
2択ボタンを出す**。これがこの回に必要なものそのものだった。

- `quiz-svg-a` / `quiz-svg-b` が **左右に並ぶ**（810×1440 で実測 x=79 と x=411、どちらも 320×250）。
  縦型でも折り返さないので、**左＝①・右＝② として読める**
- 答えたあとの解説文が**両方の名前と分子式を明かす**＝答え合わせが1画面で完結する
- アプリの言い方が「左は…、右は…」なので、**テロップとナレーションも「左と右」で統一**した
  （①② の見出しはモーダル側には無い）

## 出題の乱数と、その封じ込め（この回の肝）

`SameCompoundQuiz.nextQuestion()` は毎回ランダムに問題を作る。**デモ台本から問題を指定する
手段は無い**ので、次の2つで「撮れば必ず同じ内容になる」ところまで寄せた。

| 絞り込み | 値 | 効果 |
|---|---|---|
| 出題範囲 `#quiz-series` | **異性体をつくる（枝分かれアルカン）** | 15化合物・C₄〜C₇ に限定。高校範囲で、図が小さく読みやすい |
| 崩し方 `#quiz-strength` | **弱（回転・反転のみ）** | `TRANSFORM_LEVELS[0]` ＝ 伸長も屈曲もケクレ反転もしない。**剛体変換だけ**なので図が崩れない |

- **崩し方「弱」はブリーフの「回転しただけ vs 別物 から始める」をそのまま実装したもの**。
  標準・強は結合を伸ばしたり折ったりするので、3秒で読ませる出題には向かない
- **答えだけは乱数のまま**（`wantSame = pairs.length === 0 ? true : Math.random() < 0.5`）。
  出題範囲を pairs=0 の系列（直鎖アルカン等）にすれば「同じ」に固定できるが、
  **それは V14「曲げても同じ物質」と同じ主張になる**ので採らなかった
- そこで **台本は「違う」に賭け、`#btn-quiz-diff` を押す**。外れたら撮り直す（1回あたり 1/2）。
  **焼き上がりのフレームで ⭕ 正解 が出ていることを必ず目視する**（§4）

### ナレーションは「どの2つが出ても正しい」書き方にした

出題される化合物は撮るまで分からないので、**個別の名前・分子式・炭素数を一切言っていない**。

- 「分子式はどちらも同じ」… `allPairs` は**分子式が一致するペアだけ**を集めているので常に真
- 「いちばん長い鎖の炭素を数えて、枝が何番目に付くかを数える」…
  枝分かれアルカン15件のどの異性体ペアでも、**主鎖の長さか枝の位置のどちらかが必ず違う**
  （枝の本数が違う場合は主鎖の長さが変わるので、この2手で必ず決着する）
- **位置番号を読む場面が無い**ので、`2-メチル` を「にばん」と補う事故（LANES.md §4）も起きない

## 1. 画面の流れ（demos-isomer.json の6ステップと一致）

| # | 画面（操作） | テロップ | 画面に出ているもの |
|---|---|---|---|
| 1 | 🎓 クイズを開く → 出題範囲を「枝分かれアルカン」→ 崩し方を「弱」 | 左と右、同じ分子？ | 2つの図＋「同じ」「違う」 |

| 5 | **「違う」を押す** | 答えは 違う（構造異性体） | ⭕ 正解！＋両方の名前と分子式 |

  **次回の出題がその場で画面に出る**＝次回予告と画が一致する

## 6. 収録が止まっている理由（2026-08-02）

**収録直前の回帰テスト（`http://localhost:8132/assembler/test.html`）が 155/156。**
失敗は1件だけで、**この回とは無関係のアプリ側の作りかけ**だった。

```
ST31: 記号パズル（模式模型・分子を使わない。ORDER 第2段）
      symbolPuzzle が初期化されていない
```

- **原因**: `quiz.js` に `class SymbolPuzzle` は入っており、`game.js` も
  `window.symbolPuzzle = new SymbolPuzzle();` を呼んでいる。しかし
  **クラス宣言はグローバル変数であって `window` のプロパティにはならない**ので、
  テストの `const SP = W.SymbolPuzzle` が常に `undefined` になる。
  `quiz.js` の末尾に **`window.SymbolPuzzle = SymbolPuzzle;` を1行足せば通る**見込み
- **持ち主**: `ORDER_stereo_puzzle.md` の第2段（記号パズル）＝**アプリ改修セッション**。
  未コミットの作業中で、`game.js` `index.html` `quiz.js` `tests.js` `style.css` が同時に開いている。
  **動画レーンはアプリのコードに触らない約束**なのでこちらでは直さない
- **この回への影響はゼロ**。`quiz.js` の差分はすべて 1609行目以降（FischerPractice /
  StereoTimeAttack / SymbolPuzzle）で、**V24 が使う `SameCompoundQuiz`（450〜630行）は1文字も
  変わっていない**。`index.html` の差分も記号パズルのモーダル追加で、
  `#quiz-modal` の中身は行番号が下にずれただけ
- **N2（録画モード用のSNSデモが完走する）は合格**しているので、
  **`isomer-same-or-diff` の台本そのものは検証済み**
