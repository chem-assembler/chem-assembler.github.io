```
【問題】 次のイオンのうち、いくつかを含む水溶液がある。

         実験を行って、含まれているイオンをすべて答えよ。
```

- **universe U** … 問題文が示す候補（上の 7 個）
- **真の中身 T ⊆ U** … 実際に入っているもの（学習者には見えない）。**空でない**
- **その時点の候補集合 C** … 学習者がいま「有りうる」と考えている状態。⚠ **アプリが持つ**

⚠ **C は「イオンごとの3値（有る／無い／未確定）」で持つ**。集合の集合（2^|U| 通り）では持たない ——
2^7 = 128 なら持てるが、**§6 の全数検査を通すには状態を小さく保つ必要がある**。
3値表現なら |U| に線形。**これで足りることは §3 の判定の定義から言える**（判定は「未確定が減ったか」だけを見る）。

### 2-2. 操作は札から選ぶ。順番は完全に自由

⚠ **自由にするのは順番だけ。操作の種類は小さく閉じる。**

**第1段の札（案。§7 で段階分け）**:

| 札 | 量の段階 | 何をする操作か |
|---|---|---|
| 希塩酸 HCl を加える | 1段階 | 液性を酸性にし、Cl⁻ を入れる |
| 硫化水素 H₂S を通す | 1段階 | S²⁻ を入れる。**還元剤としても働く**（§4） |
| アンモニア水 NH₃ を加える | **少量／過剰** | 弱塩基。過剰は錯イオンを作る（§4） |
| 水酸化ナトリウム NaOH を加える | **少量／過剰** | 強塩基。過剰は両性水酸化物を溶かす（§4） |
| 炭酸アンモニウム (NH₄)₂CO₃ を加える | 1段階 | CO₃²⁻ を入れる |
| **煮沸する** | 1段階 | 溶けている H₂S を追い出す |
| **希硝酸 HNO₃ を加える** | 1段階 | 酸化剤。Fe²⁺ → Fe³⁺ |
| **沪過する** | 1段階 | ★ **容器を2つに分ける**（§2-3） |
| 炎色反応を見る | 1段階 | 沈まないイオンを見る唯一の手段 |

⚠ **量は「必要なものだけ2段階」。連続量にしない。** 連続にすると状態が無限になり、§6 の全数検査が
成立しない。⚠ **札に無いことはできない**（＝ 未知の試薬を試して落とし穴に落ちることが原理的に無い）。

⚠ **順番の制約は一切かけない。** 発注の芯なので、UI でも「次はこれ」と誘導しない。
**定石順（塩酸→酸性 H₂S→煮沸・硝酸→アンモニア→塩基性 H₂S→炭酸→炎色）は、
ヒントとしても既定でも出さない。** 定石が定石である理由は §4 の結果で体験させる。

### 2-3. ★ ビーカーの状態を持つ。沪過で容器が枝分かれする

⚠⚠ **いちばん落としやすいのがこれ。系統分離は「分ける」実験なので、
容器が1つしかない模型では、そもそも系統分離にならない。**

**容器（Vessel）の状態**:

```
Vessel {
  id            : 'v0' / 'v0-ppt' / 'v0-filt' / ...
  dissolved     : Map<化学種, 有/無/未確定>   // 溶けているもの
  precipitate   : Map<化学種, 有/無/未確定>   // 沈んでいるもの（まだ沪過していない）
  ph            : 'ACIDIC' | 'NEUTRAL' | 'BASIC'
  h2s_present   : bool        // 溶けている H₂S が残っているか（煮沸で false）
  nh4_present   : bool        // NH₄⁺ が居るか（アンモニアの緩衝に効く）
  history       : 操作の列
  candidates    : Map<イオン, 有/無/未確定>   // 学習者の知識。★ 容器ごとに持つ
  alive         : bool        // この容器がまだ調べる価値があるか
}
```

- **操作は「答えを教える」のではなく「状態を変える」**
- **観察は状態から導く。** ⚠ **返すのは「Ag⁺ が居ます」ではなく「白い沈殿ができた」。判断は学習者がする**
- **沪過**は容器を2つに分ける:
  - `precipitate` を全部持っていく**沈殿側**の容器（新しい `id`）
  - `dissolved` を全部持っていく**ろ液側**の容器（新しい `id`）
  - ⚠ **`candidates` は両方に複製されるのではなく、割られる**（§3 の判定はこれが本体）
- ⚠ **沈殿側にはさらに操作ができる**（塩酸で溶かす・熱湯で PbCl₂ を溶かす・アンモニアで溶かす）。
  第1段では**沈殿側は「色を見る」だけ**にして、溶かし直しは第2段に回す（§7）

**画面の形（案）**: 縦に伸びる**樹**。上が最初のビーカー、沪過のたびに下へ2股に分かれる。
各節に「行った操作」と「見えたもの（色の帯・沈殿の絵）」が並ぶ。
★ **これは入試問題の分離の流れ図そのもの**なので、§0 の芯（紙の形が読めるように）に直接効く。

**観察として返すもの（状態から導出。ハードコードしない）**:

| 観察 | 導き方 |
|---|---|
| 溶液の色 | `dissolved` の有色種の**吸収を足して**色に戻す（§5） |
| 沈殿の色と量 | `precipitate` の各種の色。**複数あるときは「混ざった色」と言わず、色を並べて見せる**（§5-5） |
| 気体 | CO₃²⁻ ＋ 酸 → CO₂、S²⁻ ＋ 酸 → H₂S、NH₄⁺ ＋ 強塩基＋加熱 → NH₃ |
| 炎色 | `dissolved` の炎色を持つ種。⚠ **Na の黄が強すぎて他が見えない**ことも再現するか要判断（§8） |

## 3. ★ 判定 — 3区分（発注 (a) の芯）

⚠ **「間違い」という言葉を、どの区分でも使わない。**

| 区分 | 意味 | 判定（状態から**導出**する。一覧表を持たない） |
|---|---|---|
| **有効** | その時点の候補を実際に絞れた | 操作の**前後で、どこかの容器の `candidates` の「未確定」が1つ以上減った** |
| **無駄** | ⚠ **絞りようがなかった** | 操作が**分けられるイオンの集合**と、**その時点の候補集合**の**交わりが空** |
| ★ **取り返しがつかない** | ⚠ **余計なことが起きて、あとで分からなくなった** | ある化学種が**系から出た／別のものに化けて**、**以降どの操作を積んでも区別できなくなった** |

### 3-1. 「無駄」の定義 —— なぜ「候補が変わらなかった」ではダメか

⚠ **弱い定義（＝候補集合が変わらなかったら無駄）は採らない。** 理由:

> ★ **Ag⁺ が候補にあるときに塩酸を入れて沈殿しなかったのは、無駄ではない。**
> 「Ag⁺ は無い」と分かったので、立派に情報を得ている。

弱い定義だと**この操作まで無駄にしてしまう**。正しい定義は
**「そもそも何も分かりようがなかった」だけを無駄と呼ぶ**。

**定義（1つに決める）**:

> **操作 op を容器 v に行うとき、**
> **`Split(op, v)` ＝「その操作で*沈む側*に行くイオン」の集合とする。**
> **その時点の候補集合 `C(v)`（＝「未確定」のイオンだけ）に対して、**
>
> - **`Split(op,v) ∩ C(v) = ∅`** → **無駄**（1つも沈まない。何も割れない）
> - **`C(v) ⊆ Split(op,v)`** → ⚠ **これも無駄**（全部沈む。やはり割れない。情報が増えない）
> - **それ以外（真に割れる）** → **有効**

⚠ **「分けられる」の意味を1つに決めた: 沈殿する／しない で、候補が2つ以上の組に割れること。**
★ **全部が沈む操作も無駄に含まれる**（発注の指示どおり）。上の第2条件がそれを拾う。

⚠ **`Split` は表としてハードコードしない。** ビーカーの状態から
「この試薬を入れたら、いま溶けている各イオンは沈むか」を模型に問い合わせて作る。
**だから「その時点の」が自動的に効く。**

### 3-2. ★ 「その時点の」が効く —— 順番によって無駄の出方が変わる

**候補集合は操作のたびに縮む。** 初手では意味があった操作が、あとの段では無駄になりうる
（分けられる相手がもう候補に残っていない）。

⚠ **判定は初期の候補集合ではなく、その操作を行った時点の候補集合に対して行う。**
★ **これがそのまま「定石順でなくてもよいが、順番によって無駄の出方が変わる」の説明になる。**

**例**（U = {Ag⁺, Cu²⁺, Fe³⁺, Al³⁺, Zn²⁺, Ca²⁺, Na⁺}、T = {Cu²⁺, Al³⁺, Na⁺}）:

| 手 | 操作 | その時点の C | Split ∩ C | 判定 |
|---|---|---|---|---|
| 1 | 希塩酸 | 全7個が未確定 | {Ag⁺} | **有効**（沈まない → Ag⁺ は無い、と分かる） |
| 2 | 酸性で H₂S | {Cu,Fe,Al,Zn,Ca,Na} | {Cu²⁺} | **有効**（黒沈 → Cu²⁺ 有り） |
| 3 | **もう一度 希塩酸** | {Fe,Al,Zn,Ca,Na} | ∅ | ⚠ **無駄**（Ag⁺ はもう候補に無い） |

**答え合わせの文面（無駄）**:

> **この操作では、候補が1つも絞れませんでした。**
> 塩酸で分けられるのは Ag⁺・Pb²⁺ ですが、この時点でどちらも候補に残っていませんでした
> （Ag⁺ は 1 手目で「無い」と分かっています）。

⚠ **なぜ絞れなかったかを、候補集合の言葉で言う。**「間違い」とは書かない。

### 3-3. ★ 「取り返しがつかない」の判定

**定義**:

> **操作 op のあと、真の中身 T のうちあるイオン x について、**
> **「x が有る世界」と「x が無い世界」が、以降どんな操作をどんな順で積んでも**
> **同じ観察列しか生まないなら、op は x について「取り返しがつかない」。**

⚠ **これも一覧表を持たない。状態から出す。** 具体的には次の2つの形で現れる:

- **系から出た** … 沈殿を沪過したあと、ろ液側でその沈殿の中身を問うことはもうできない
  （**ただしこれは正常な操作**。沈殿側の容器が残っているので取り返しはつく）
- ⚠ **区別できなくなった** … 沈殿が**溶けてしまい**、ろ液に紛れて他と見分けられなくなった。
  あるいは**酸化数が変わって別の群に化けた**

⚠ **実装としては、§6 の全数検査と同じ道具でよい**: その時点の状態から
「x を含む仮説」と「含まない仮説」を両方進め、**到達しうる観察列が完全に一致したら区別不能**と判定する。
札が有限・量が2段階なので、これは**有限回で必ず終わる**。

**答え合わせの文面（取り返しがつかない）**:

> **この時点で水酸化ナトリウムを過剰に入れたので、Al³⁺ の水酸化物が溶けてしまい、
> 以降は Al³⁺ の有無を確かめられなくなりました。**
> Al(OH)₃ は両性水酸化物で、過剰の強塩基には [Al(OH)₄]⁻ になって溶けます。
> 少量にとどめていれば、白い沈殿として分けられました。

⚠ **何が起きて、何が分からなくなったかを言う。「間違い」とは書かない。**

## 4. ★ 妨害（想定外の反応）—— 入れるものと入れないもの

ユーザーの言葉:

> **問題 → 想定外の反応などあるかもしれない**

★ **順番を自由にするなら、外したときに起きる妨害を実装しないと、
「順番はどうでもいい」と教えることになる。** これが「定石順が定石である理由」そのもの。

### 4-1. ⚠⚠ 線引き —— これが設計の腕の見せどころ

> ★ **入れるのは「教科書が順番の理由として説明しているもの」だけ。それ以外は入れない。**
> ⚠ **線を引かないと、「アプリだけが知っている落とし穴」で生徒を落とすことになる（＝ 紙で解けない問題）。**

**模型の精度も同じ線で切る:**

> ★ **教科書と同じところまで。それ以上に賢くしない。**

⚠ **線の外にある挙動を、アプリはどう振る舞うか（決め）:**

| 場合 | 振る舞い |
|---|---|
| 札にある操作 × 線の内側の化学 | 模型どおりに状態を変え、観察を返す |
| 札にある操作 × **線の外側**（教科書が扱わない副反応） | ⚠ **何も起こさない**。副反応を黙って再現しない |
| 学習者が線の外を知っていて質問した | ⚠ **「この教材ではそこまで扱いません」と明示的に言う**。黙って無視しない |

⚠ **教科書に書かれていない説明をアプリが足す場合は、そう明記する**
（`qa/KNOWLEDGE_CAVEATS.md` の型）。§4-3 がまさにその1件。

### 4-2. 入れるもの（教科書が順番の理由として説明する型）

⚠ **以下は高校化学の標準的な扱いとして書いた。実装に入る前に、
`scan/` の資料または `化学新研究` 実物で1件ずつ裏を取ること**（§8 の決め事に入れた）。

| # | 妨害 | 効く相手 | 区分 | 教科書が順番の理由として書くか |
|---|---|---|---|---|
| **W1** | **過剰の NaOH で両性水酸化物が溶ける** | Al³⁺, Zn²⁺, Pb²⁺, Sn²⁺ | 取り返しがつかない | ★ **書く**（両性の定番。`ion-equation` に式が既にある） |
| **W2** | **過剰の NH₃ で錯イオンになって溶ける** | Ag⁺, Cu²⁺, Zn²⁺, Ni²⁺ | 取り返しがつかない | ★ **書く**（錯イオンの定番。`ion-equation` に式が既にある） |
| **W3** | ⚠ **H₂S が還元剤なので、酸性で Fe³⁺ → Fe²⁺ になる** | Fe³⁺ | 取り返しがつかない（§4-3） | ★ **書く**（煮沸＋硝酸の理由として） |
| **W4** | **液性を戻す操作が要る**（煮沸で H₂S を追い出す） | — | 取り返しがつかない | ★ **書く**（定石の手順そのもの） |
| **W5** | **PbCl₂ は熱湯に溶ける** | Pb²⁺ | 有効な操作（妨害ではない） | ★ **書く**（Ag⁺ と Pb²⁺ を分ける手段） |
| **W6** | **共沈** | — | — | ⚠ **入れない**（下記） |

**W6・共沈について**: ⚠ **高校の教科書は共沈をまず書かない**（本設計での判断）。
書いていないものを入れると、まさに「アプリだけが知っている落とし穴」になる。
★ **入れない。** ⚠ もし裏取りで「教科書が順番の理由として共沈を挙げている」と分かったら、
そのとき初めて検討する（§8 の決め事に入れた）。

**⚠ 煮沸せずに硝酸だけ入れたら何が起きるか（決め）**:
残った H₂S が硝酸に酸化されて**単体の硫黄（淡黄色・水に溶けない）が濁りとして出る**、
という説明は化学としては正しい。⚠ **しかし、これを教科書が順番の理由として書いているかは未確認**なので、
**第1段では入れない**。代わりに **「煮沸していない容器に硝酸を入れても、H₂S が残っているので
Fe²⁺ が Fe³⁺ に戻りきらない」**（＝ W3 が解消されない）だけを実装する。
⚠ **これは「何も起きない」ではなく「効果が出ない」なので、線の内側**（W3 の裏返し）。

### 4-3. ★★ 中心にある1件 — なぜ「煮沸してから硝酸」なのか

ユーザーの言葉（2026-08-23）:

> **酸性条件で硫化水素を加えた後、煮沸から硝酸を加える操作 → Fe²⁺ を 3+ に戻すのが理由であることは
> 広く教えられているが、なぜ戻す必要があるかはほとんど知られていない。どのように反映させるか**

**「なぜ戻すのか」の答え**:

第3属（アンモニア水で沈む群）の分離は、**水酸化物の溶けにくさ**で割っている。
アンモニアは弱塩基で、しかも **NH₄⁺ と共存させて OH⁻ の濃度を低く抑えてある**ので、
**いちばん溶けにくい水酸化物（Fe(OH)₃・Al(OH)₃・Cr(OH)₃）だけが沈む**ようにできている。

★ **Fe(OH)₂ は Fe(OH)₃ よりずっと溶けやすい。**
だから **Fe²⁺ のままだと、この段では沈まずに素通りする。**
そして**次の段（塩基性で H₂S）で FeS として沈む** ——★ **鉄が「第3属」ではなく「第4属」に現れる。**

★ **つまり、間違いは「鉄を見落とす」ではなく「鉄を別の群だと判定する」。
群で分類するという仕組みそのものが崩れる。**

⚠ **これがこの教材でいちばん良い「取り返しがつかない」の例になる ——
操作の途中では何も間違って見えず、最後に答えが1つずれる。**

**★ どう反映させるか（決め）**:

⚠ **警告を出さない。**「煮沸と硝酸を忘れています」と教えたら、この問いは死ぬ。
**結果を起こして、答え合わせで説明する:**

1. 煮沸＋硝酸を飛ばすと、**Fe²⁺ のままアンモニアの段を素通りする**（沈殿しない）
2. **次の段で FeS として沈む**
3. 学習者は「鉄は第4属にあった」と推定して答え合わせに進む
4. ★ **答え合わせで初めて言う**:

> **鉄は第3属です。**
> 酸性で硫化水素を通したとき、H₂S が還元剤としてはたらいて Fe³⁺ が Fe²⁺ になりました。
> そのままアンモニアの段に進んだので、**Fe(OH)₂ は Fe(OH)₃ ほど溶けにくくなく、沈みませんでした。**
> 素通りした鉄は、次の塩基性硫化水素の段で FeS として沈んでいます。
> **煮沸して硫化水素を追い出し、硝酸で Fe³⁺ に戻してから進むのは、このためです。**
>
> ※ 教科書は「硫化水素で還元された Fe²⁺ を Fe³⁺ に戻すため」までは書いています。
>   **「戻さないと鉄が第4属に現れて、群の分類そのものが崩れる」までは、この教材が足した説明です。**

⚠ **最後の1行（出典の断り）は必ず出す。`qa/KNOWLEDGE_CAVEATS.md` の型。**
実装前に、教科書・資料集が実際にどこまで書いているかを確かめ、**書いていたら断りを外す**（§8）。

### 4-4. ⚠ この件が実装に課す要求

- ★ **イオンの識別に酸化数を含める。`Fe2+` と `Fe3+` は別の化学種。**
  ⚠ **これを「同じ鉄」として持つと、この設計は成立しない。**
  ⚠ **現行の `muki/chemistry.js` は `'Fe'` 1個しか持っていない**（実測・§1-1）ので、
  **系統分離モードは既存の `CATIONS` を流用せず、別のデータを持つ**（§7-4）
- **水酸化物が沈むかどうかの表を、酸化数ごとに持つ**（Fe(OH)₂ と Fe(OH)₃ で違う）
- **操作が化学種を変えうる**枠 —— **H₂S（還元）／HNO₃（酸化）／煮沸（H₂S を追い出す）**
- **アンモニアの段は「NH₄⁺ と共存した弱塩基」として扱う**（OH⁻ が薄い）。
  ⚠ **NaOH（強塩基）とは沈む相手が違う**ことを模型が区別できること

## 5. ★ 色の扱い（発注 (b)・ユーザーが難所と名指しした点）

ユーザーの見立て:

> **問題：複数の有色イオンを含む溶液の色の推定が難しい / 色の足し引きで理論上可能**

### 5-1. ⚠ RGB の平均（加法混色）で混ぜてはいけない

溶液の色は**吸収**で決まる。足し引きするのは**吸収**であって、**光の色ではない**（減法混色）。

**採る方式**:

1. 各イオンの**モル吸光係数 ε(λ)** を、**数本のガウス帯**（中心波長・半幅・ピーク ε）で持つ
2. 混合液の吸光度を**帯ごとに足す**: `A(λ) = Σ ε_i(λ)·c_i·L`（Lambert–Beer）
3. 透過率に戻す: `T(λ) = 10^(−A(λ))`
4. D65 光源と CIE 1931 等色関数で **XYZ → sRGB** に落とす

⚠ **足すのは吸光度 A であって透過率 T ではない**（T は掛け算になる。A で足すのと同値）。

**★ 両方を実装して比べた（実測）。RGB 平均がどう外れるかがはっきり出た:**

| 組み合わせ | ✗ **RGB 平均** | ○ **吸収を足す** | 外れ方 |
|---|---|---|---|
| Cu²⁺ + Fe³⁺ | `#8f9377` 淡い黄 | `#664b00` **濃い黄土** | ⚠ **明るすぎる** |
| Ni²⁺ + Co²⁺ | `#7c7e8a` **淡い青** | `#662f27` **暗い赤褐** | ⚠⚠ **色相が真逆** |
| Fe³⁺ + Ni²⁺ | `#80b148` 黄緑 | `#716400` **濃い黄** | ⚠ 色相も明度も外れる |
| Cu²⁺ + Cr₂O₇²⁻ | `#8fbc77` 緑 | `#6e8300` **黄** | ⚠ 外れる |
| Cu²⁺ + Co²⁺ | `#8b60b9` 青紫 | `#68007f` 青紫 | ○ **たまたま合う** |
| Cu²⁺ + Ni²⁺ | `#0fc9bf` 青緑 | `#00a384` 青緑 | ○ **たまたま合う** |

★ **系統的な誤り: RGB 平均は絶対に暗くならない**（2 つの明度の中間にしかならない）。
実際の溶液は**2 つのイオンが違う波長を吸うので、足すと必ず暗くなる**。
⚠ **「たまたま合う」組があるのが厄介** —— テストを 1〜2 件しか書かないと通ってしまう。

### 5-3. ⚠ 合わなかった 4 件の見立て（隠さず書く）

| 件 | 何が起きたか | 見立て |
|---|---|---|
| **Fe²⁺ が黄緑になる** | 可視域の吸収がほぼ無く、色が紫側の弱い吸収だけで決まってしまう | ⚠ Fe²⁺ の色は**もともと非常に薄く**、「淡緑」は肉眼の印象に近い。**帯データの精度の問題**（推測） |
| **Cr³⁺ が灰になる** | 408 nm と 575 nm の 2 本で挟むと、青緑と赤が同じくらい残って無彩色寄りになる | ★ **これは模型の失敗ではない。** `COLOR_AUDIT.md` §3-B-3 が既に指摘しているとおり、**[Cr(H₂O)₆]³⁺ 本来の色は紫**で、教科書の「緑」は**配位子交換が起きた結果**。⚠ **水和イオンの吸収帯から教科書の緑は原理的に出ない** |
| **Fe³⁺ が橙で、「褐」の暗さが出ない** | 「褐」は色相ではなく**明度が低い橙**。濃度を上げれば暗くなるが、そのとき色相も赤へ寄る | ⚠ **「褐」は色名の問題**。§5-5 の結論に効く |
| **Cr₂O₇²⁻ が濃度で黄⇄橙を行き来する** | 350 nm の強い帯の裾が可視域に伸びる量が濃度で変わる | ★ **模型は正しい。教科書の色名のほうが濃度を前提にしている** |

### 5-4. ⚠⚠ いちばん大事な問い —— その色は、生徒が紙の上で予測できるか

**答え: 予測できない。**

根拠は 3 つ、すべて上の実測から出る。

1. ★ **色名が同じでも混色の結果が違う**（Cu²⁺+Fe³⁺ と Cu²⁺+CrO₄²⁻）。
   生徒が持っているのは色名だけなので、**入力が足りない**
2. ★ **濃度で色名が変わる**（Cu²⁺ は 0.01 M で無色、Cr₂O₇²⁻ は黄と橙を行き来する）。
   **問題文は濃度を書かない**ので、**入力が定まらない**
3. ★ **強い吸収を持つイオンが1つ入ると、他が全部隠れる**（MnO₄⁻ は Cu²⁺ の 1/200 の濃度で同じ濃さ）。
   **「複数の色の混合」ですらなく、単に強いほうの色になる**

★ **したがって「アプリは計算できるが、生徒には解けない」問題そのもの。**
⚠ **出題の手がかりとして混色を使ってはいけない。**

★ さらに、`COLOR_AUDIT.md` の一次資料調査がこれを裏から支えている:

- **`化学新研究` p.477 の系統分離の表に載っている有色イオンは 4 つだけ**（Fe²⁺・Fe³⁺・Ni²⁺・Cu²⁺）
- **教科書は色名を連続量として扱っていない**（Li も Sr も同じ「赤」。§4-3 の該当節）
- **色名は資料によって割れる**（K の炎色は「赤紫」と「紫」で、学校でバツにされた報告まである）

⚠ **色名が採点の対象として割れる以上、色を正誤の判定点にしてはいけない。**
これは `qa` が既に採っている方針（`COLOR_AUDIT.md` 目録 A-3「色そのものを正誤の判定点にしない」）と同じ。

### 5-5. ★ 決め —— 色をどこまで使うか（線引き）

| 場面 | 扱い | 理由 |
|---|---|---|
| **溶液に有色イオンが 1 つだけ** | ★ **手がかりとして使ってよい**（「青い ＝ Cu²⁺ が居る」を根拠にできる） | 教科書の表がそのまま使える。紙で予測できる |
| **溶液に有色イオンが 2 つ以上** | ⚠ **見せるだけ。問わない。** 判定の根拠にしない | §5-4。予測できない |
| **沈殿の色** | ★ **手がかりとして使ってよい** | ⚠ **ただし混ぜない**。下記 |
| **沈殿が複数あるとき** | ⚠ **色を混ぜて 1 色にしない。**「白い沈殿と黒い沈殿が混じって見える」と**並べて言う** | 実験でもそう見える。混色の計算は**懸濁液には物理的に当てはまらない**（吸収ではなく散乱） |
| **濃度** | ⚠ **持たない**（第1段）。「濃い／薄い」も問わない | 濃度を入れると §5-4 の 2 が問題文に侵入する |
| **炎色反応** | ★ **手がかりとして使ってよい**。ただし**色名は複数受理**（K = 赤紫／紫 の両方） | `COLOR_AUDIT.md` §4-2 の結論 |

**★ 混色の計算は、それでも実装する価値がある —— ただし「見せるだけ」として。**

⚠ **判定には使わないが、画面には正しい色を出す。** 理由:
このサブブランドは「**色でみる無機化学**」であり、
**「教科書の色名からは予測できない」ということ自体が、見せる価値のある事実**だから。
★ **答え合わせで一言添える**:

> この溶液は Cu²⁺ と Fe³⁺ を含んでいて、実際にはこういう色になります。
> **「青」と「黄褐」から混ざった色を当てることはできません**（濃度で変わるためです）。
> **色で判断してよいのは、色のついたイオンが 1 つだけのときです。**

⚠ **この一言は毎回出さない**（うるさい）。**有色イオンが2つ以上ある回だけ**出す。

**実装の形（第1段では作らない・§7）**: 吸収帯の表を `muki/spectra.js` に持ち、
`mixColor(species[], concs[], L)` で hex を返す。⚠ **`SPECIES_COLOR`（`ion-equation`）とは別物**
なので流用しない（あちらは1種1色の見た目専用）。

- **色**: ⚠ **白と黒だけ**（AgCl 白・CuS 黒・CaCO₃ 白）。有色イオンは Cu²⁺ 1つ。
  ★ **§5-5 の「有色イオン1つだけなら手がかりにしてよい」の実例になる**
- **判定**: 3 区分のうち **有効／無駄の2つだけ**（この候補では取り返しがつかないが起きない）
- **全数検査**: 6⁵ × 15 ≈ 12 万経路。⚠ **必ず通す**
- ★ **これだけで発注の芯（定石順でなくてよい・無駄を指摘する）が成立する**

### 第2段 — 「取り返しがつかない」が入る

- 候補に **Al³⁺・Zn²⁺** を足す（→ 6 個）
- 札に **アンモニア水（少量／過剰）・水酸化ナトリウム（少量／過剰）** を足す
- **W1（両性）・W2（錯イオン）** が効くようになる → **3 区分が揃う**
- 答え合わせから `ion-equation` の該当ステージへ**往復リンク**を張る
- ⚠ **全数が回る大きさか、この時点で必ず試算し直す**

### 第3段 — ★ Fe の件（この教材の山場）

- 候補に **Fe³⁺** を足す。⚠ **`Fe2+` と `Fe3+` を別の化学種として持つ**（§4-4）
- 札に **煮沸・希硝酸** を足す
- **W3・W4** が効く → §4-3 の答え合わせが成立する
- ⚠ **警告は出さない。結果を起こして、答え合わせで説明する**

### 第4段 — 色を「見せる」

- §5 の吸収帯モデルを `muki/spectra.js` として実装
- ⚠ **判定には一切使わない**。有色イオンが2つ以上のとき §5-5 の一言を出す
- 図鑑（既存の `populateDict()`）に**吸収スペクトルの帯**を並べる

### 第5段 — 沈殿側の操作

- 沪過した沈殿を**溶かし直す**（熱湯で PbCl₂・塩酸・アンモニア）
- ⚠ **ここまで来ると全数が厳しい。§6 の畳み込みが要る**
