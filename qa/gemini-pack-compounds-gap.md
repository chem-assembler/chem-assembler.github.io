# Gemini 依頼パック: 高校化学の定番で欠けている化合物の追加（compounds.json）

## これは何の作業か

Chem-Assembler の名称ライブラリ `assembler/compounds.json` に、**高校化学の教科書に出るのに
まだ入っていない化合物**を追加する。いま 176 件（stages.json 56 + compounds.json 120）あり、
アルカン・芳香族・エステル・高分子の単量体はよく揃っているが、**アミノ酸と油脂の単元に穴がある**。

**この作業が Gemini に向いている理由**: 出来上がりを機械で検査できる。
座標・結合・価標が1つでも狂えば `tools/verify-compounds.js` が落ちる。
既存エントリという正解のひな形があり、判断で迷う余地が小さい。

---

## 追加してほしいエントリ

### A群: α-アミノ酸（優先・4件）

教科書が挙げる代表的なα-アミノ酸のうち、**グリシン・アラニン・フェニルアラニン・チロシン・
グルタミン酸・アスパラギン酸は既にある**。欠けていて、かつこのアプリで描けるものが下の4件。

| 名前 | `formula` に書く式 | 側鎖（α炭素に付く枝） |
|---|---|---|
| セリン | `HOCH2CH(NH2)COOH` | -CH₂-OH |
| リシン | `H2N(CH2)4CH(NH2)COOH` | -(CH₂)₄-NH₂ |
| バリン | `(CH3)2CHCH(NH2)COOH` | -CH(CH₃)₂ |
| ロイシン | `(CH3)2CHCH2CH(NH2)COOH` | -CH₂-CH(CH₃)₂ |

**システインとメチオニンは追加しないこと。** このアプリの硫黄は**6価固定**（スルホ基 -SO₃H 用）
として扱われており、**チオール -SH（2価の S）は正しく表現できない**。描くと価標検査で落ちる。
トリプトファンもインドール環（縮合複素環）が扱えないため対象外。

**立体（D/L）は指定しない。** 既存のフェニルアラニン・チロシン・グルタミン酸と同じく、
`stereo` フィールドを持たない「立体を指定しない形」で作る。
（D/L を区別しているのはアラニン・乳酸・グリセルアルデヒドだけで、そこに合わせる必要はない）

### B群: 芳香族・高分子（余力があれば・3件）

| 名前 | `formula` | 構造 | なぜ要るか |
|---|---|---|---|
| 1-ナフトール | `C10H7OH` | ナフタレンの1位に -OH | ジアゾカップリングの定番 |
| 2-ナフトール | `C10H7OH` | ナフタレンの2位に -OH | 同上。1位との違いが問われる |
| クロロプレン（2-クロロ-1,3-ブタジエン） | `CH2=CClCH=CH2` | 1,3-ブタジエンの2位に -Cl | 合成ゴムの単量体 |

### C群: 脂肪酸（余力があれば・2件）

油脂の単元で使う長鎖脂肪酸が**1件も入っていない**（いまは吉草酸 C5 が最長）。

| 名前 | `formula` | 構造 |
|---|---|---|
| パルミチン酸 | `CH3(CH2)14COOH` | 炭素16個の直鎖＋末端 -COOH |
| ステアリン酸 | `CH3(CH2)16COOH` | 炭素18個の直鎖＋末端 -COOH |

**オレイン酸は作らないこと。** シス二重結合の指定が必要で、別の仕組み（`stereo.bondGeo`）が
絡むため、このパックの範囲外とする。

**優先順位は A > B > C。** A群4件だけでも十分な成果。時間や自信の都合で B・C を省いてよい。
省いた場合は報告にそう書くこと。

## データの形式

`assembler/compounds.json` は**1件1オブジェクトの配列**。既存の2件をそのまま示す。

```json
{"name":"グリシン","formula":"H2NCH2COOH","target":{"atoms":[{"element":"N","x":316,"y":300},{"element":"C","x":358,"y":300},{"element":"C","x":400,"y":300},{"element":"O","x":400,"y":258},{"element":"O","x":442,"y":300}],"bonds":[{"atom1Index":0,"atom2Index":1,"type":1},{"atom1Index":1,"atom2Index":2,"type":1},{"atom1Index":2,"atom2Index":3,"type":2},{"atom1Index":2,"atom2Index":4,"type":1}]}}
```

```json
{"name":"酪酸（ブタン酸）","formula":"CH3CH2CH2COOH","target":{"atoms":[{"element":"C","x":316,"y":321},{"element":"C","x":358,"y":321},{"element":"C","x":400,"y":321},{"element":"C","x":442,"y":321},{"element":"O","x":484,"y":321},{"element":"O","x":442,"y":279}],"bonds":[{"atom1Index":0,"atom2Index":1,"type":1},{"atom1Index":1,"atom2Index":2,"type":1},{"atom1Index":3,"atom2Index":2,"type":1},{"atom1Index":3,"atom2Index":4,"type":2},{"atom1Index":3,"atom2Index":5,"type":1}]}}
```

### 作図の規約（守らないと検査で落ちる）

1. **水素は書かない。** アプリが空き価標から自動で補う。`H` を `atoms` に入れてはいけない。
   例外は無い（グリシンの例に H が1つも無いことを確認すること）。
2. **結合長は 42px、直交格子。** 原子の座標は必ず 42 の倍数ぶんだけ離す。
   斜め結合を使う場合も x と y の差をそれぞれ 42 にする（対角線長は 59.4 になる）。
   これは「手書き感覚」を意図した仕様であって、角度が不自然でも正しい。
3. **原点の目安は x=300〜500, y=250〜350 あたり。** 既存エントリと同じ帯に置く。
4. `bonds` の `type` は 1=単結合、2=二重結合、3=三重結合。
   `atom1Index` / `atom2Index` は `atoms` 配列の**添字**（0始まり）。
5. **枝は上下に伸ばす。** 例: バリンの -CH(CH₃)₂ は、中心炭素から上と下に CH₃ を1つずつ。
   原子どうしが 42px より近づかないように配置する（近いと警告、重なると不合格）。
6. 芳香環（ナフトール）は、既存の**ナフタレンのエントリをそのままコピー**して -OH を足すこと。
   環の座標を自分で作らない。ケクレ構造（単結合と二重結合の交互）も既存のものを引き継ぐ。

## 作り方（この手順どおりに）

1. リポジトリのルートで `assembler/compounds.json` を開く。
2. **末尾の `]` の直前に、カンマ区切りで新しいエントリを追記する。**
3. ひな形は上に示した既存エントリ、または似た骨格を持つ既存エントリ
   （アミノ酸ならグリシン、脂肪酸なら酪酸、ナフトールならナフタレン）をコピーして書き換える。
4. **1件足すごとに検査を走らせる。** 全部書いてからまとめて走らせない。
   どのエントリが原因か分からなくなる。

### やってはいけないこと

- **ファイル全体を再整形しない。** 既存の行の書き方（1オブジェクト1行、キーの順序、
  空白の入れ方）を一切変えないこと。整形すると差分が数千行になり、
  何を追加したのか読めなくなって受け取れない。**追記した行だけが差分に出る状態にすること。**
- **既存エントリを1文字も変更しない。**
- **ファイルを UTF-8（BOMなし）以外で保存しない。** BOM が付くと検査で落ちる。
- **改行コードを変えない**（既存は CRLF）。

## 検査（これが合格の定義）

リポジトリのルートで:

```bash
node tools/verify-compounds.js
```

- 終了コードが 0 で `✅ 不合格の問題はありません` と出れば合格。
- `△ 警告` は既存データにも7件あるもので、**不合格ではない**（増やさなければよい）。
  いま出ている警告は「自動水素がやや近い（11.5px）」が7件。
- よく出るエラーと意味:
  - `価標が超過` … 結合の数か次数が多すぎる。水素を手で書いていないか確認する。
  - `「〇〇」と区別できません（構造も立体も同一）` … 既存エントリと同じ分子を作ってしまった。
  - `原子が近すぎます` … 座標が 42px 未満に接近している。枝の伸ばし方を変える。

あわせて、追記後に次も通ること:

```bash
node tools/verify-release.js
```

こちらは文字化け・BOM・改行の事故を見る。`✅` にならなければ保存方法を疑うこと。

## 報告してほしいこと

1. 何件追加したか、**どれを省いたか（省いた理由も）**
2. `node tools/verify-compounds.js` の出力そのまま（警告の件数を含む）
3. 追加した各エントリについて、**構造をどう決めたか**の一行説明
   （例:「バリン = α炭素に -NH₂ と -COOH、側鎖はイソプロピル基。α炭素から上下に CH₃ を配置」）
4. **自信が持てなかった箇所**があれば正直に書くこと。省いてくれたほうが助かる

なお、この検査ツールは**形式と幾何しか見ない**。化学的に正しいかは人が読んで確認するので、
「検査が通った＝正しい」とは考えないこと。3 の説明はそのために必要。
