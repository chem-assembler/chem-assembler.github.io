# 一問一答 — 知識項目コード体系・難易度・習得モデル（規約）

このファイルは `qa/questions.json` の設計規約。方式は **A（コード付き知識項目台帳＋習得マップ）**、
app非依存に設計し将来 **D（全アプリ共通の背骨）** へ育てる。目標水準は**難関大受験まで**。

---

## 1. 知識項目コード（PatternID の正式化）

1知識項目 = 1コード = 1 pattern。**安定・人間可読・app非依存**（assembler ステージや ion-equation からも同じコードで参照できる）。

```
<domain>.<unit>.<topic-slug>
例) org.ali.alkene-addition   org.aro.phenol-detection
```

- **domain**（全化学共通）: `org`(有機) / `theo`(理論) / `inorg`(無機) / `calc`(計算)
- **unit（有機）**:
  `anal`(元素分析・構造決定) / `ali`(脂肪族炭化水素) / `alcohol`(アルコール・エーテル) /
  `carbonyl`(アルデヒド・ケトン・カルボン酸・エステル) / `aro`(芳香族炭化水素) / `phenol`(フェノール類) /
  `aroN`(芳香族窒素化合物) / `fat`(油脂・セッケン) / `bio`(糖・アミノ酸・タンパク質) / `poly`(合成高分子)
- **topic-slug**: 小項目を表す短い英字ケバブ。単元内で一意。

> コードは**一度振ったら変えない**（習得データ・他アプリ参照の主キーになるため）。表記ゆれ防止に、単元・topic-slug は本ファイルの一覧を正とする。

## 2. 難易度ルーブリック（4段階・項目ごと）

`difficulty`: 1–4。**知識項目ごと**に付す。目標水準=難関大まで。

| Lv | 呼称 | 基準 |
|----|------|------|
| 1 | 生存 | 落とすと定期試験で不合格になりかねない最低限（用語・定義・代表物質・基本の一般式）。狭くてよい |
| 2 | 標準 | 教科書標準。定期試験で得点するのに必要（大半の性質・反応・命名・基本的な区別・主要な製法） |
| 3 | 受験標準 | 共通テスト〜国公立2次・難関私大で戦うために必要（構造決定の手がかり・反応や検出の細部） |
| 4 | 難関 | 難関大で差がつく細部・例外・応用（細かい条件や数値、反応の連鎖の応用） |

- フラグ `beyond: true` … 教科書範囲外／発展的補足（標準学習に混ぜない制御。例: sp混成、反応機構の詳細）。**Lv とは独立**。既定は範囲内。

### Lv の割り当て基準（客観化 / 2026-07-27）

Lv は概念的な難しさではなく**受験での位置づけ**で決める。客観的な目安として **「市販問題集のどのレベルで問われるか ＋ 出題頻度」** を用いる（＝レベル・頻度という事実メタデータを参照するだけで、問題文は転記しないので著作権に抵触しない）。
- 標準的な問題集で頻出 → Lv2
- 共通テスト〜2次・難関の問題集で問われる → Lv3
- 難関の細部・低頻度 → Lv4
- **概念が易しくても、頻度が低く標準必須でなければ Lv2 に上げない**（例: 炭素間結合長の順序は概念は易しいが低頻度の受験細部 → Lv3）。

> **Lv の意味に注意**: Lv は「暗記必須度・受験の階層」であって「重要度・知る必要の有無」ではない。Lv が高い＝「知らなくてよい」ではない。
> 「入試で見本（反応式・生成物）が示されるので丸暗記の優先度は低いが、仕組みの理解は必要」という細部は、**測定は"仕組み・使いどころ"の核に寄せ、丸暗記対象の細部は補足(supplement)に置く**（例: アルケンの酸化開裂は"切断が起こる・構造決定に使える"を測定し、オゾン/KMnO₄の生成物の違いは補足）。

### 分割ルール（難易度が割れたら別項目）

1問の中で事実ごとに難易度が割れるのは「別の知識項目」のサイン。ある細部が次の複数を満たすなら**別コードに切り出し** `req` で結ぶ:
- 独立に問われうる／独立に間違えうる／難易度が明確に違う・受験の決め手
（例: 「アルケン＋H₂→アルカン」= Lv2 と「触媒は Pt/Ni」= Lv3 を分ける）

**切りすぎ防止**: 単なる言い換え・同一事実の別角度は同一項目に留める（例:「二重結合が単結合になる」≒「生成物はアルカン」）。分割の閾値に満たない細部（例: 水付加のリン酸触媒）は、測定の選択肢には入れず**補足(supplement)に置く**。

## 2.5 関係レイヤ（tags・group・req）

1問と1知識項目(コード)は 1:1（測定の要）。1項目に複数問(variants)は可。比較・統合の知識も"またがり"にせず1項目にする。

- **`group`**（必須）: 小項目ラベル。習得マップのグリッド行になる（例: 分類・一般式／アルカン／シクロアルカン／アルケン／アルキン／異性体・命名）。
- **`tags`**（統制語彙）: 観点の横串。「検出だけ」等の演習・集計に使う。当面の語彙:
  - 観点: `分類` `一般式` `官能基` `分子の形` `命名` `異性体` `反応` `検出` `製法` `性質` `身のまわり` `実験` `計算`
  - 反応種: `付加` `置換` `脱水` `酸化` `重合` `縮合` `加水分解`
  - 化合物: `アルカン` `アルケン` `アルキン` `シクロアルカン`（以降の単元で拡張）
- **`req`**（任意）: 前提の知識項目コードの配列（DAG）。診断・学習順に使う。**領域を跨いでよい**（例: `org.anal.*` の `req` に `calc.ratio`）。未作成コードを先に書いてよい（後で実体化）。
- （後回し）混同ペア: マルコフ⇔ザイツェフ等。コンテンツが揃ってから別フィールドで。

### どちらの領域にも置ける知識をどこに入れるか（2026-08-10 決定）

領域の境目にある知識（例: 酸性アミノ酸の多段階の電離平衡 —— 有機か理論か）は、次の2つを守る。

1. **収録単元は多数派に合わせる。** 傍用問題集・受験用問題集での扱いに従う
   （上の例なら**有機**。学習順の都合で有機に入るのが多数派）。
   理屈で「本来は理論」と決めて多数派と違う場所に置くと、**探した人が「無い」と思う**
2. **他方の領域からも置き場が分かるようにする。** 片方にしか入口が無いと、
   もう一方から探した人に届かない

**2 の仕掛け**: `req` に相手の領域のコードを書いて依存を宣言しておく（未実体でよい）。
相手が実体化したときに相互参照を張る。**忘れないように `tests.js` が見張る** ——
「req: 領域を跨ぐ前提が既知のものだけで、まだ実体化していない」が、
**相手の実体化でも、新しい跨ぎの追加でも鳴る**。

⚠ **いまは「辿れる」仕掛けそのものが無い**（逆引きの表示を持っていない）。
相手の領域を収録するときに、表示のしかたも一緒に決める。

## 2.6 飛び道具リンク（一問一答 ⇆ assembler・双方向）

🔧 構造系の項目は assembler と**同じコードで双方向**に結ぶ（＝方式D の背骨）。組めない事実（製法・沸点等）は純・一問一答のまま。

- データ: `link: { "label": "…", "build": "C₅H₁₂" }`（対象アプリは当面 assembler 固定）
- 一問一答 → assembler: `../assembler/?from=qa&code=<コード>&build=<式>`（app側でコードから組み立て）
- assembler → 一問一答: `../qa/?code=<コード>`
- **前方互換**: assembler は未知パラメータを今は無視。ディープリンクの実装は別タスク（規約だけ先に確定）。

## 2.7 出題頻度データ（`freq`・将来のプレミアム層／予約）

各知識項目に**出題頻度**を持たせられる（現時点は空。データ収集は別トラック）。習得マップの習得度と掛けて「**志望校で頻出かつ未定着**」の優先度トレーニングに使う（プレミアム／B2school 向け）。

- 形（予約）: `freq: { "tier": {"kyotsu": n, "nan_kokkoritsu": n, "kokkoritsu": n, "nan_shiritsu": n, "shiritsu": n}, "univ": {"<大学名>": n} }`
- `tier` は難関度ティア別、`univ` は**ターゲット大学ごと**の頻度も持てる。
- 値は出題頻度の指標＝**統計（事実メタデータ）**。市販問題集・過去問へのコード・タグ付けで集計し、**問題文は転記・配布しない**（著作権配慮。Lv割り当て基準 §2 と同じ原則）。

## 3. 二面構成（1項目に代替可能な複数 variant）

- `mode: "flip"` … **暗記**（めくり・自己採点 ○×）。毎日の想起練習。
- `mode: "choice"` … **測定**（複数選択・客観採点。正解集合と完全一致でのみ正解＝勘で当たらない）。到達度の証明。
- 同一項目に複数 variant を持たせ、出題時にランダム選択＝**丸暗記が効かない**。選択肢の表示順も実行時シャッフル。

**複数選択(choice)の作問ルール**
- **排反（相反）の選択肢を入れない**: 正解肢の単純な否定・反対（「高い⇔低い」「する⇔しない」「発生する⇔しない」）を誤答肢にしない。複数選択では自明に消せてしまう。
- **誤答肢は独立した"ありそうな誤り"**（典型的な誤解）にする: 値の取り違え・条件の混同・別物質の性質・惜しい勘違い など。
- **正解数を固定しない**: 3個固定を避け、2〜4個などばらつかせる（「毎回3つ選ぶ」攻略を防ぐ）。選択肢数も5固定にせず4〜6程度で可変。

## 4. 習得モデル（習得マップの実体）

進捗は**知識項目コード単位**で `localStorage` に蓄積（Lv1ローカル成績。将来サーバ同期・B2school ダッシュボードへ地続き）。

各項目の状態（4つ）:
- **未着手** … 一度も出題していない
- **学習中** … 出題済みだが繰り返せていない（`box < 4`）
- **測定で未確認** … 繰り返せてはいるが、**測定モードでまだ正解していない**
- **定着** … 繰り返せていて、かつ測定モードで正解した

> **定着の認定は「測定モード(choice)での正解」で行う**（自己採点のめくりは練習であって証明ではない）。
> **2026-08-06・v39 で実装した**（それまでは flip/choice を区別せず box 値だけで判定していた）。

### 実装（`qa/app.js`）

**`box` が兼ねていた2つの仕事を分けた**のが要点。

| | 何を決めるか | どのモードの結果で動くか |
|---|---|---|
| `box`（0〜5） | **次にいつ出すか**（間隔反復のスケジュール） | **両方**。想起のタイミングはめくりの結果でも動いてよい |
| `cRight` / `cWrong` | **定着したか**（認定） | **測定モードだけ** |

判定は `stateOfRecord(r)` の1箇所だけに書く（ホームの単元カードと習得マップが同じ関数を使う。
別々に書くと「カードでは定着なのにマップでは学習中」というずれが出る）。

```js
function stateOfRecord(r) {
  if (!r || !r.seen) return 'new';
  if (r.box < MASTER_BOX) return 'wip';
  return (r.cRight || 0) > 0 ? 'done' : 'unconfirmed';
}
```

**`unconfirmed` を `done` にも `wip` にも混ぜない理由**: `done` に入れると自己申告が到達度として
数えられる（それが直したかった問題）。`wip` に落とすと実態より低く見える（実際そこまで積んである）。
**測定モードで1回通せば `done` になる**ので回復は軽く、習得マップから
「未確認だけをまとめて測定する」導線を置いてある。

**記録の器が変わったので保存キーを `slz-qa-v2` に上げた。** 旧 `v1` の記録は mode を持たず
**遡ってどちらで正解したか判定できない**ため、読み込むと根拠のない「定着」が残る。
`v1` は消していない（読まなくなるだけ）。

習得マップUI: **単元 × 難易度**のグリッドで、マスの点1つ＝知識項目1つを上の4状態で色分け。
網羅（存在する項目）と習得（できた項目）を同時に可視化する。
**「測定で未確認」は定着と同じ緑を枠だけで持つ**（塗り＝測定で確かめた証。別の色を割り当てると
学習中より進んでいるのに「悪い状態」に見える）。色は `style.css` の1箇所で決め、
点・凡例・帯・明細が同じ色を使う。

## 5. カバレッジ台帳（網羅表）の作り方

1. 手持ち資料の**目次・項目見出し**から、単元内の**知識項目を洗い出す**（※資料の問題文は転記しない。項目の洗い出しと事実確認にのみ使用）。
2. 各項目に**コード**と**難易度**を割り当て、台帳（この規約に沿った pattern 群）を作る。→ これが受験網羅性の設計図。
3. 各項目を二面構成で起草 → 単元ごとに検収（`REVIEW_<unit>.md`）＋機械チェック。
4. 網羅率・習得率を習得マップで可視化。

### 例（脂肪族・既存23項目のコード化イメージ）

| コード | 難易度 | 知識 |
|---|---|---|
| `org.ali.alkane-formula` | 1 | アルカンの一般式 CₙH₂ₙ₊₂ |
| `org.ali.alkene-addition` | 1 | アルケンの主反応は付加 |
| `org.ali.ethanol-dehydration` | 3 | エタノール＋濃硫酸 160–170℃ → エチレン（分子内脱水） |
| `org.ali.geometric-isomers` | 3 | 2-ブテンはシス–トランス異性体をもつ |
| … | … | （全23項目を org.ali.* に移行） |
