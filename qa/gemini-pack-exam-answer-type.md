# Gemini 依頼パック: 入試の設問で「その知識が解答になっていたか」を判定する

## これは何の作業か

入試の出題実績（`qa/data/exam_usage.jsonl`・2021年入試の有機140大問の悉皆）には、
知識項目がどう使われたかを `via` で記録していただいています。

- `via: "手筋"` … **解き方を支える知識として使った**（2,235件）
- `via: "題材"` … **その問題が扱う物質・実験**（1,896件）

ここに**もう1つの軸が要る**ことが分かりました。**その知識が「解答そのもの」になっていたか**です。

| 出方 | 例 | 暗記の必要度 |
|---|---|---|
| **解答になる** | 「この反応の名称を答えよ」→ 答えが《ヨードホルム反応》 | **覚えていないと1点も取れない** |
| **解くのに必要**（既存の「手筋」） | 不飽和度を使って構造を絞る | **リード文で与えられることもある** |

**この2つは難易度への効き方が逆になります。** 前者が多い項目は「覚えるべき必修の基礎」、
後者が多い項目は「使えるようになるべき道具」です。いまは後者しか測れていないため、
**暗記の必要度が主観のまま**になっています。そこを埋めたいのです。

---

## 絶対の制約（著作権）— 既存の `_解析/SCHEMA_問題DB.md` と同じです

- **問題文・解説文・解答の文章を一切転記しない。** 要約もしない
- 記録するのは「**その知識項目が解答になっていたか**」の **true / false だけ**
- **大学名・年・設問の印字番号は記録してよい**（既存の `exam_usage.jsonl` と同じ範囲）
- **答えの中身は書かない。** 「答えが《ヨードホルム反応》だった」も**書かないでください**
  （知識項目コードが既にそれを指しているので、値は true / false で足ります）
- 出力に問題文や解答の断片が混じっていたら、その行は使えません

---

## 判定してほしいこと

**既存の `exam_usage.jsonl` にある（知識項目 × 大問）の組それぞれについて、
その大問の設問のどこかで、その知識項目が解答になっていたか**を true / false で付けてください。

判定の目安:

| | 判定 |
|---|:--:|
| その知識項目の**名称・用語そのものを書かせる／選ばせる**設問がある | `true` |
| その知識項目を**使って**別のもの（構造・数値・式）を答えさせている | `false` |
| その知識項目が**リード文や与えられた条件の中にある**（前提として使われている） | `false` |
| 判断がつかない | `null`（無理に決めないでください） |

⚠ **「構造式を書かせる」は false** にしてください。
構造式の解答は複数の知識が合わさった結果で、どの項目が「解答」かを一意に決められません。
**用語・名称・反応名・法則名を答えさせている場合だけ true** です。
（この線引きはこちら側の都合です。分類の解釈はこちらで持ちたいので、
判断に迷う形は `null` で残していただくのがいちばん助かります。）

## 作るもの

`qa/data/exam_answer_type.jsonl` に入れる **1行1組** の JSON。
**既存の `exam_usage.jsonl` を書き換えないでください**（あちらは
`_解析/tools/build-exam-usage.js` の生成物なので、別ファイルで受け取ってこちらで結合します）。

```json
{"code": "org.carbonyl.iodoform-carbonyl", "printed": "横浜市大・医2", "year": 2021, "asAnswer": true}
{"code": "org.ali.unsaturation", "printed": "横浜市大・医2", "year": 2021, "asAnswer": false}
{"code": "org.bio.glucose-ring", "printed": "○○大・工1", "year": 2021, "asAnswer": null}
```

| フィールド | 中身 |
|---|---|
| `code` | 知識項目コード（既存の `exam_usage.jsonl` と同じもの） |
| `printed` | 設問の印字番号（**既存の `problems[].printed` と一字一句同じ**にしてください。これが結合キーです） |
| `year` | 2021 |
| `asAnswer` | `true` / `false` / `null` |

### 結合キーがずれると使えません

こちらは `code` ＋ `printed` で既存データに突き合わせます。
**`printed` の表記が既存と違うと結合できず、その行が捨てられます。**
既存の `exam_usage.jsonl` から `printed` の値をそのままコピーしてお使いください。

---

## 刻んで納品してほしい

**まず、出現回数の多い上位10コードぶんだけを出して止めてください。**
（`exam_usage.jsonl` の `count` が大きいものです。`org.ali.unsaturation` が 45 で最多です。）

こちらで機械検査（`printed` が既存と結合できるか・`code` が実在するか・
`asAnswer` が3値のどれか）にかけて、**判定の線引きが合っているか**を確認します。
そのあと残りを回数の多い順にお願いします。**272コードすべてを一度に出さないでください。**

### 量の目安

既存の記録はのべ4,131件（手筋2,235＋題材1,896、うち両方付いたもの550）です。
**同じ（コード × 大問）の組に1つ値を足すだけ**なので、新しく読む範囲はありません。
ただし**設問の解答欄を見る必要がある**ので、前回より1件あたりの手間は増えます。
きついと感じられたら、**上位50コードで止めていただいても十分な精度が出ます**
（回数の分布が偏っているので、上位で大半をカバーできます）。

## この値を何に使うか

`difficulty`（難しさ）とは**別のフィールド** `priority`（出題での効き）を作り、そこに入れます。

- `asAnswer` が多い → **暗記必須度が高い**（覚えるべき必修の基礎）
- `via: "手筋"` が多い → **道具としての重要度が高い**（使えるようになるべき）

**閾値は先に決めません。** データが揃ってから分布を見て決めます
（前回、対応表を先に作って外した反省です。§3-5 に記録があります）。

また **「出ていない＝優先度が低い」とは判定しません。** 母集団は2021年の1年分なので、
出ない項目が多数あります（316項目のうち34項目はセミナーにも入試にも出ません）。
**出た回数の多さだけを信号として使います**（片側の論法）。
