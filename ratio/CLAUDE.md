# 比例式でみる化学計算（slug: ratio）

高校化学の計算問題を「比例式」で解けるようにする学習アプリ。vanilla JS + SVG なし（HTML表＋CSS）、
ビルドなし・静的配信。Chem-Assembler / Ion-Equation の姉妹プロジェクトで、開発ルールも同じ流儀。

公開予定URL: https://chem.schoollenz.com/ratio/ （= chem-assembler.github.io/ratio/）
（**このディレクトリ自体が親リポジトリの `/ratio/` サブディレクトリ**。専用リポジトリは持たず、
ここで直接開発・直接コミットする。デプロイ = 親のルートで `git add ratio && git commit && git push`）

## このアプリの核（設計の要）

比例式を **2列×2行の表**として持つ。列 = 量の種類（質量・物質量・体積・粒子の数）、
行 = 上が「基準」・下が「知りたい量」。**同じ列に同じ種類の量が来る**ことが唯一のルールで、
列の色がその視覚的な根拠になっている。

解き方は「内項の積＝外項の積」**ではなく【倍率が同じ】**。倍率が分かればかけ算1回で終わる。

- **倍率は2方向**にとれる: たて（行→行 `factorV`）／よこ（列→列 `factorH`）。
  **問題によって楽な向きが変わる**ので両方の矢印を描き、`recommend()` で推奨を出す
  （'v' / 'h' / 'either'）。判定基準は「暗算できる倍率か」＝整数倍≤50・単位分数で分母≤10・分母≤4。
- **倍率は分数で見せ、答えは小数で書く**。分数で理解を深め、解答は小数にする。
- **操作の流れ**: 単位をえらぶ → 既知の値から倍率を自分で探す（分数入力）→
  **正しければ自動でもう一方の矢印に同じ倍率が入る** → 答えを計算。
  倍率が確定するまで答え入力は無効（`answerReady`）。
- 段階（足場）は問題ごとに `steps: {unit, factor}` で指定。省略した段階は最初から見せる。

## 重要ルール

- **model.js は DOM 非依存の純粋ロジック**。表示用の文字列も markup ではなく
  Unicode（上付き `6.0×10²³`）で作る。DOM を触るのは app.js だけ
- **有効数字は問題文で桁を指定し、解答に必須**。採点は3値（`grade()` → ok / sigfig / wrong）。
  sigfig＝値は正しいが桁違い → 「値は合っています。書き方を直そう」と指導し、クリアにはしない。
  小数点なしの末尾0は曖昧なので桁数は**範囲**で判定（'20' は1〜2桁のどちらでも可）
- **採点時に分数⇔小数の対照表**を添える（計算が苦手な人向け）。その問題で使う倍率を強調
- 問題データの数値は**文字列で書くと有効数字の表記がそのまま表示に使われる**（'9.0'・'22.4'）。
  指数は `'6.0e23'` 形式で持ち、表示時に変換する
- 全ファイル UTF-8（BOMなし）。コミット前に文字化けパターン（`縺`・`繧`・`繝`）確認
- バージョン `vNN` は index.html・balance.html・stoich.html・test.html のキャッシュバスターと
  ヘッダー表示を同時更新（`sed -i 's/?v=OLD/?v=NEW/g' *.html` ＋ `<div class="version">` の置換）
- 1修正=1コミット。**コミット前に test.html 全合格＋ブラウザで実挙動確認**
- 起動: `python -m http.server 8126 --directory ratio`（fetch 不使用なので直開きでも動く）

## 現状（v13 プロトタイプ）

**比例式モード20問＋天秤モード8問＋反応の量的関係14問**。test.html は ALL PASS (576)。

**問いとして成立しているかを疑うこと**（v12〜v13・ユーザー指摘）。ちょうど反応の問題で
「先に足りなくなるのはどちら？」と2択で聞いていたが、**そもそも存在しない**ものを
選ばせていた（どちらを選んでも正解にしていた）。
v12 では「どちらも同時」を選択肢に足したが、**この型にそんな正解は要らない**（ユーザー判断）。
v13 で**そういう問い自体を作らない**ことにした ＝ ちょうど反応は**見せる**問題にし、
`steps.limit` を付けない。**選択肢を足して凌ぐより、出題を直すほうが正しい**。
`steps.limit` と `isExact` が両立しないことは回帰テストで固定した。
**答えを図に先出ししない**のも同じ筋（えらばせる問題では、えらぶまで停止線と塗りを描かない）。

**反応の量的関係モード**（`stoich.html` + `stoich.js`・v10〜v11）は3行表と過不足。
比例式の【倍率が同じ】をそのまま広げたもので、**係数の行が基準・変化量 ＝ 係数 × 倍率**。
過不足は**倍率の比べっこ**（`mol ÷ 係数` が最小の物質で止まる）で、横棒の図で見せる。
**多いほうが余るとは限らない**ことを図で分からせるのが要点。
誤答は「余るほうで計算した（`limit`）」「係数が逆さま（`flip`）」と名指しする。
**係数は与えられたものとして扱う**（係数を決めるのは ion-equation の担当。回帰テストで固定）。

g・L の出題（v11）で踏んだ落とし穴:
- **表はいつでも mol で通す**。換算は表の外の帯（① mol にそろえる／③ 単位を戻す）に置く。
  `beforeOf()` は `given` が `{v, q}` でも常に mol を返す
- **`p.given[key]` を直接読んではいけない**。mol 指定は文字列だが g・L 指定はオブジェクト
  なので `M.disp()` に渡すと `NaN` になる（`givenSpec()` を通すか、mol の値を使う）
- **候補倍率（`mol ÷ 係数`）は必ず mol の値で書く**。g のままでは係数で割る意味が消える
- **mol にそろうまで棒くらべを出さない**（候補倍率が変換の答えを漏らす）
- 誤答の再現（`flippedStoich` / `wrongLimitAnswer`）も**答えの単位に直してから**比べる
- 量を指定しない反応物は**問題文で「十分量の◯◯と」と明示する**（表と文を食い違わせない）

天秤の図で踏んだ落とし穴（v9）:
- **SVG の `<text>` は `<sup>`/`<sub>` を描画しない**。`³⁵Cl` は `plainLabel()` で
  Unicode に変換すること。変換前は同位体番号が消えていた
- **図の要素は縦の帯に分けて配置する**。文字はベースラインより上に伸びるので、
  支点の直下に数値を置くと重なる。回帰テストは `getBBox()` の実測で重なりを検査している

v5〜v6 の重要な決定（ユーザー指摘による）:
- **列は「左＝与えられた量／右＝問われる量」**。矢印は常に ↓ と → で、答えは右下
- **倍率は分母が小さい分数のみ分数表示**。それ以外は小数（`×112/5` → `×22.4`）
- **扱いやすさは点数（`effort` 0〜3）で比較**。小数を独立した段として扱う
- **指数表記は仮数 1〜10 を要求**（`12×10²³` を弾いて書き方を指導）
- **天秤の存在比は % 付き**。与えられた平均は丸めない（36 と誤表示する不具合を修正）
- **天秤の解説は 内分比 → 個数の比 → 丸める前の値 → 別解の式** まで載せる
①倍率が見えている → ②単位をえらぶ → ③倍率を自分で探す、の足場外しを実装済み。

**天秤モード**（`balance.html` + `balance.js`）は平均原子量・平均分子量。レンズが違う
（数直線と支点）ので別ページにした。核心は **腕の長さの比 ＝ 個数の逆比**。
出題は2方向（存在比→平均／平均→存在比）。有効数字の採点は `gradeValue()` を比例式側と共有。

- **問題は仕様から生成する**（`SPECS` → `buildProblem()`）。手書きするのは物質・与えられた量・
  問われる量・段階・桁数だけ。基準の行は `perMol()`（1 mol あたりの値）から、答えの表記は
  `toSig()` から機械的に決まる。**`base` や `ansDisp` を手書きしない**
- 物質20種の分子量・式量を `SUBSTANCES` に持つ（**文字列**。`H2: '2.0'` の末尾の0を保つ）
- mol を経由しない組み合わせにも対応（質量↔体積 = 44 g : 22.4 L、質量↔粒子の数 = 18 g : 6.0×10²³ 個）
- よこが楽な問題（q9: CO₂ 0.30 mol → g。たては ×3/10、よこは ×44）を入れて推奨判定を実際に使っている
