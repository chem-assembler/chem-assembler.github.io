# 比例式でみる化学計算 設計書（2026-07-25 合意・v1 プロトタイプ検証済み）

化学計算を**比例式で解けるようにする**アプリの設計。プロトタイプ（v1）で操作の手触りを
確認したうえで書き起こしたもの。**進行状況は DEVELOPMENT.md（未作成）または本書末尾の
ロードマップが正**。カタログ上の位置づけは 5本のうちの「**計算できるようになる**」担当。

## ion-equation との棲み分け（2026-07-26 確定）

中和・過不足・滴定は「イオンでみる化学反応式」とも重なるが、**担当が違う**:

| アプリ | 担当 |
|---|---|
| イオンでみる化学反応式 | **係数を決める**（粒の数で納得して反応式を書けるようにする） |
| **比例式でみる化学計算** | **係数から量を出す**（書けた式を使って質量・体積・濃度を求める） |

だから M3（3行表・過不足）や M4（滴定）をこちらで扱っても衝突しない。
**係数は与えられたものとして扱い、係数を求めさせる問題は作らない**（それは向こうの担当）。

## 目的

1. mol 計算を「**方程式を解く**」ではなく「**比例式を立てる**」で理解させる（理解が深まる）
2. 倍率さえ分かれば**かけ算1回で終わる**という手触りを与える（計算が楽になる）
3. 「同じ種類の量どうしを比べる」という**唯一のルール**を体で覚えさせる
4. 単位・桁・比の向きの**典型的な誤りをその場で言葉にする**
5. 同じ器で 天秤（平均分子量）・過不足・滴定・熱化学まで扱う（レンズが同一だから同居できる）

## 設計の核 1：比例式を 2列×2行 の表として持つ

```
              質量(g)          物質量(mol)     ← 列 = 量の種類
  基準         18 g            1 mol           ← 行 = 基準（1 mol あたり）
  知りたい量    9.0 g          [ ? ] mol        ← 行 = 知りたい量
```

- **列に同じ種類の量が来る**ことがこの表の唯一のルール。**列の色**（質量=青／物質量=緑／
  体積=橙／粒子の数=紫）がその視覚的な根拠になっている
- 未知セルは、単位が確定するまで**灰色**。単位を選んだ瞬間に色が付くので、**上のセルと色が
  違えば即座におかしいと分かる**（色の不一致 = 種類の不一致）
- 横に読む比例式（`18 g : 1 mol ＝ 9.0 g : 0.50 mol`）も常時1行で表示し、入力に追従させる

## 設計の核 2：解き方は「倍率が同じ」（内項の積＝外項の積ではない）

**採用しない**: 内項の積＝外項の積 → 立式してから割り算になり、計算が重い。
**採用する**: **行間・列間の倍率が同じ** → 倍率が分かればかけ算1回で終わる。

倍率は**2方向**にとれる。どちらが楽かは問題によって変わり、**たまにどちらでも大差ない**。

| 方向 | 意味 | 関数 |
|---|---|---|
| **たて** | 基準の行 → 知りたい量の行（両方の列で同じ倍率） | `factorV(p)` |
| **よこ** | 既知の列 → 未知の列（両方の行で同じ倍率） | `factorH(p)` |

```
基準       40 g  ──×?──▶  1 mol
            │ ×1/2          │ ×1/2   ← 既知列で読んだ倍率を未知列へ「運ぶ」
知りたい量  20 g  ──×?──▶  0.50 mol
```

- **列は常に「左＝与えられた量／右＝問われる量」**。こうすると たては ↓、よこは → の
  一方向だけで読め、**答えは必ず右下**に来る。矢印の向きが問題ごとに変わると読みにくいので、
  「mol を右端に置く」より**この規則を優先する**（v5 で変更）
- 両方向の矢印を描き、**使う方向だけ濃く**（もう一方は薄い矢印だけ）。切替ボタンで往復できる
- **倍率の書き方は分母で決める**。分母が 2,3,4,5,6,8 の分数だけ分数で見せ、それ以外は
  短い小数を優先する（`×112/5` ではなく `×22.4`、`×3/10` ではなく `×0.3`）。
  分母が 10ⁿ の分数は小数と同じなので小数のほうが楽、という判断（`factorForm`）
- `recommend(p)` が `'v'` / `'h'` / `'either'` を返し、「この問題は たて が楽」「どちらでも
  大差ない」と明示する。判定は**扱いやすさの点数**（`effort`。小さいほど楽）を両方向で比べ、
  同点なら `either`:
  - **0** … 一桁の整数倍（即答）
  - **1** … 2桁までの整数倍・分母が小さい分数・単位分数（分母 ≤ 10）
  - **2** … 短い小数ならかけられる（`×22.4`・`×0.3`）
  - **3** … つらい（`×1/18`・`×6.0×10²³`）
  - 「既約分数より 10ⁿ 分母（＝小数）のほうが楽な場合がある」ため、小数を独立した段として扱う
- **倍率は分数で見せ、答えは小数で書く**。分数で理解を深め、解答は小数にする
  （`factorText` は `×1/2`・`×3`。大きい倍率は `×6.0×10²³` と指数表記）

実測（v1 の6問）:

| 問題 | たて | よこ | 推奨 |
|---|---|---|---|
| 水 9.0 g → mol | ×1/2 | ×1/18 | たて |
| CO₂ 0.25 mol → g | ×1/4 | ×44 | どちらでも |
| O₂ 5.6 L → mol | ×1/4 | ×5/112 | たて |
| C 3.0 mol → g | ×3 | ×12 | どちらでも |
| O₂ 3.0 mol → L | ×3 | ×22.4 | たて |
| CO₂ 0.30 mol → g | ×0.3 | ×44 | **よこ** |
| Cu 0.25 mol → g | ×1/4 | ×64 | どちらでも |
| 水 0.50 mol → 個 | ×1/2 | ×6.0×10²³ | たて |

## 設計の核 3：足場を段階的に外す（steps）

学習者にやらせる段階を**問題ごとのデータ**で指定する。省略した段階は最初から見せる（＝足場）。

```js
steps: { unit: true, factor: true }   // 両方やらせる（最終形）
steps: { unit: true }                 // 単位だけ選ばせ、倍率は見せる
steps: {}                             // 倍率も単位も見せる（導入）
```

| 段階 | 学習者の操作 | 狙い |
|---|---|---|
| ① | 完成した表の**数値だけ**入力（倍率は矢印に表示済み） | 型を焼き付ける。まず解ける快感 |
| ①' | `unit` — 答えの**単位を4択**（g / mol / 個 / L） | 「ここに来るのは何か」＝対応関係の意識化。1タップ |
| ② | `factor` — 既知の値から**倍率を分数で**入力 | 比例の中身そのものを自分で見つける |

**フル組み立て（表を一から埋める）は採用しない**。煩わしさが学習効果を上回るため。
①' の1タップでフル組み立ての学習価値のほとんどが取れる。

### 操作の流れ（②が有効なとき）

```
単位をえらぶ ──▶ 倍率を分数で入れる ──(正しい)──▶ 自動でもう一方の矢印に同じ倍率が入る
                                                    ＋ 答え入力が有効化・フォーカス移動
                                                              │
                                                              ▼
                                                        答えを計算して入力
```

- **倍率が確定するまで答え入力は無効**（`answerReady()` が false、グレー表示）。
  順序を強制するのではなく、次にやることが1つに見える状態を作るための仕掛け
- 倍率の正誤は**入力のたびに即時判定**（ボタンを押させない）。正しければその場で転記アニメ。
  約分していない `2/4` や小数 `0.5/1` も正解として受ける（理解の本質ではないため）

## 有効数字

**問題文で桁を指定し、解答に必須。桁の誤りは指導する（減点ではなく書き方の矯正）。**

採点は3値（`grade()`）:

| status | 条件 | 表示 | クリア |
|---|---|---|---|
| `ok` | 値も桁も正しい | 正解＋計算過程 | ○ |
| `sigfig` | **値は正しいが桁が違う** | 「値は合っています。書き方を直そう」＋正しい表記 | ×（再提出） |
| `flip` | 倍率を逆さまに使った値 | 「倍率が逆さまになっています」＋正しい倍率 | × |
| `wrong` | それ以外 | 「ちがうみたい」＋倍率のヒント | × |

- **値の許容幅は要求された桁から決める**（`tolerance()`）。`13.2` を2桁で答えると `13` になるが、
  これは相対 1.5% のずれで、固定の 0.5% では**正しい答えが弾かれる**（v3 で実際に踏んだ）。
  桁の最終位の 0.51 倍を許容幅にすれば、正しく丸めた答えだけが通り、桁が増えるほど自動的に狭くなる
  （2桁の 13.2 → 許容 ±0.51／3桁の 0.500 → 許容 ±0.00051）
- `0.5` と `0.50` は値として区別しない。桁は別軸（`sigFigRange`）で見る
- 桁数は**範囲で判定**する。小数点なしの末尾 0 は曖昧なので `'20'` は 1〜2桁の
  どちらとも解釈でき、どちらの要求でも通す（`sigFigRange` が `{min, max}` を返す）
- 指数表記の問題は**仮数の桁**で判定する（`3.0e23` → 2桁、`3e23` → 1桁）
- **指数表記の書き方も見る**（`sciform`）。`12×10²³` は `1.2×10²⁴` と値が同じなので、
  値だけ見ていると通ってしまう。仮数が 1 以上 10 未満でなければ
  「値は合っています。指数の書き方を直そう」と指導する（クリアにはしない）。
  ユーザー案の「計算欄と解答欄を分ける」は煩わしいので、まず書き方の指導で対応する
- **`sigfig` を「不正解」と書かない**のが要。値の誤りと表記の誤りを混同させないため

## 分数と小数の対照表

計算が苦手な学習者向けに、**採点時（正解・誤答・桁指導すべて）に対照表を添える**。
共通分数12個（1/10・1/8・1/5・1/4・1/3・1/2・2/3・3/4・4/5・3/2・2・3）を値の小さい順に並べ、
**その問題で使う倍率**（たて・よこ両方）を強調表示する。一覧に無い倍率は追加して表示する。

割り切れない分数は `0.333…` のように末尾に … を付ける（`fracDec`）。

## 問題の生成（手書きするのは仕様だけ）

問題を手書きすると `base` や答えの表記を間違える。**分子量から機械的に生成する**。

```js
// 仕様（手書きするのはこれだけ）
{ id: 'q9', sub: 'CO2', given: { q: 'mole', v: '0.30' }, asked: 'mass',
  steps: { unit: true }, sig: 2 }
```

`buildProblem()` が仕様から次を作る:

- **`cols`** — `COL_ORDER`（mass → volume → count → mole）で並べる。**mol は常に右端**に来るので、
  表が「基準の軸」として読める
- **`base`** — 各列の **「1 mol あたりの値」**。`perMol()` が返す:
  質量 = 分子量／物質量 = 1／体積 = 22.4 L（標準状態）／粒子の数 = 6.0×10²³。
  **これで基準の行は分子量さえあれば決まる**。mol を経由しない組み合わせ（質量↔体積 = 44 g : 22.4 L、
  質量↔粒子の数 = 18 g : 6.0×10²³ 個）も同じ規則で自然に作れる
- **`title` / `hint`** — 量の組み合わせから生成。体積が絡めば「標準状態で」を前置し、
  ヒントは基準の行が何を意味するかを述べる（列の組み合わせごとに文型を用意）
- **`ansDisp`** — `toSig(solve(p), sig)` で**有効数字から機械的に決める**（手書きしない）
- **`choices`** — 単位の4択。全4種を出し、**正解の位置を問題ごとに回す**（位置で覚えられないように）

分子量・式量は**文字列で持つ**（`H2: '2.0'` の末尾の 0 を表示で保つため）。

## データスキーマ

```js
{
  id: 'q1',                       // 一意キー
  steps: { unit: true },          // 学習者にやらせる段階（省略した段階は見せる）
  sigfigs: 2,                     // 解答に要求する有効数字の桁数（問題文に明示）
  title: '水 H<sub>2</sub>O 9.0 g は何 mol か',
  hint: '水 H<sub>2</sub>O 1 mol の質量は 18 g',
  cols: ['mass', 'mole'],         // 列の量の種類（左, 右）。QUANTITIES のキー
  base:   [18, 1],                // 基準の行
  target: ['9.0', null],          // 知りたい量の行。null がちょうど1つ = 未知
  ansDisp: '0.50',                // 正しい表記の答え（有効数字つき）
  choices: ['mole', 'volume', 'mass', 'count']   // steps.unit のときの4択（順序も固定）
}
```

**数値は文字列で書くと有効数字の表記がそのまま表示に使われる**（`'9.0'`・`'22.4'`）。
計算には `val()` で数値化して使う。指数は `'6.0e23'` 形式で持ち、`disp()` が
Unicode 上付き文字で `6.0×10²³` に変換する（**model.js を DOM 非依存に保つため
markup は使わない**）。

粒子の数（`count`）が未知の問題は、答えの入力欄が**仮数＋指数の2枠**になる（`6.0×10²³` を
テキストで打たせない）。倍率方式の利点が最大化する題材でもある（`6.0×10²³ × 1/2` で終わる）。

## 天秤モード（M2・加重平均）

平均原子量・平均分子量は**レンズが違う**（比例式の表ではなく**数直線と支点**）ので、
`balance.html` + `balance.js` に分けた。モデルは `model.js` に同居させる（純ロジックなので）。

核心は **腕の長さの比 ＝ 個数の逆比**。3行のルールで全問が解ける:

1. 平均は軽いほうと重いほうの**あいだ**に必ず来る
2. **多いほうに支点が寄る**（同じ数なら真ん中）
3. **腕が短いほうが多い**（腕の長さの比は個数の比の逆）

```
        75個                    25個
    ┌────────┐              ┌──┐
    │  ³⁵Cl  │              │³⁷Cl│
 ───┴────────┴──▲───────────┴──┴───
   35.0      35.5(支点)        37.0
        ├ 0.5 ┤├───  1.5  ───┤     ← 腕 0.5 : 1.5 → 個数 3 : 1
```

- 出題は2方向。`kind:'average'`（存在比 → 平均を求める）と `kind:'ratio'`（平均 → 存在比を求める）
- **皿の大きさが個数を表す**。`kind:'ratio'` では個数が未知なので皿を点線＋「?」で描き、
  正解すると実際の比の大きさになる
- **存在比には % を付ける**（原子量の数字と混同しないため）。体積比には付けない（`amountUnit`）
- `kind:'average'` では**答えるまで支点を描かない**（支点の位置＝答えそのものなので）
- **与えられた平均は丸めない**。`kind:'ratio'` で支点ラベルに有効数字を適用し、
  35.5 を「36」と描く不具合があった（v5 で修正）。問われている場合だけ丸めた表記を使う
- **図の縦の帯を分けて重なりを防ぐ**（v9）。上から 皿 → 支点の値 → 数直線 → **支点** →
  数値 → ラベル → 腕の寸法線。数値は支点の下端より下に置く（文字はベースラインより
  約17px 上に伸びるので、支点の直下に置くと重なる。実測 `getBBox` で回帰テストしている）
- **SVG の `<text>` は `<sup>` を描画しない**。`³⁵Cl` や `N₂` は `plainLabel()` で
  Unicode の上付き・下付きに変換してから描く（変換前は「35」が消えて Cl だけが出ていた）
- **区間の等分**（なし／2〜10等分）を選ぶと目盛りが入り、内分点を目で見つけられる。
  **目盛りはクリックできる**（任意の分点を選べる）。選ぶと点線の三角で**仮の支点**が置かれ、
  「選んだ点 35.5：35.0 と 37.0 を 1 : 3 に内分」と表示される。
  平均を問う問題では**その値がそのまま解答欄に入る**（選んで答えられる）。
  比を問う問題では内分比とその逆（個数の比）を並べて示す。同じ点をもう一度押すと選択が外れる。
  `divisionsFor()` が「支点が目盛りにちょうど乗る等分数」を求めて案内する。
  存在比が 69.2% のような問題は 250〜1000 等分が必要なので `null` を返し、
  「この問題は簡単な等分では目盛りに乗らない」と正直に表示する
- **解説は3段構え**（ユーザー要望）: ①腕の長さと内分比（「35.0 と 37.0 の間を 1:3 に
  内分する点」）②個数の比とその % 表記 ③**丸める前の値**と**天秤を使わない別解の式**
  （`kind:'average'` は定義どおりの加重平均、`kind:'ratio'` は x を置いた方程式）
- 誤答の指摘は比例式側と同じ思想で「何を取り違えたか」を名指しする:
  **真ん中を挟んで反対側の値**（多い少ないを逆にした位置）を `flip` として拾い、
  「多いほうと少ないほうが逆です／◯◯ のほうが多いので支点は ◯◯ 側に寄ります」と返す
- 有効数字の扱いは比例式側と完全に共通（`gradeValue()` を両モードで共有）

## 反応の量的関係モード（M3・過不足）

反応式の量的関係は、**比例式の核（倍率が同じ）をそのまま広げたもの**として実装した。
レンズが同じなので同居できるが、表の形が 2列×2行 ではなく**列＝反応式の各物質**になるため
`stoich.html` + `stoich.js` に分けた。

```
          H₂    ＋   O₂   →  H₂O
係数（比）  2         1         2      ← 基準の行
反応前     0.30      0.10       0
変化量    −0.20     −0.10     ＋0.20   ← 係数 × 倍率
反応後     0.10       0        0.20
```

- **倍率 x ＝ 反応が何 mol 分進んだか**。比例式モードの矢印の倍率と同じ役割なので、
  **変化量の行の見出しに「係数×⬚」のバッジ**として置いた（位置づけを揃える）
- **列の間に ＋ と → を挟む**ので、表そのものが反応式として読める。
  反応物と生成物で列の色を変える（矢印のどちら側かが一目で分かる）
- **過不足は「倍率の比べっこ」**。反応物ごとに `mol ÷ 係数`（候補倍率）を出し、
  **一番小さいところで反応は止まる**。これが限定反応物。`candidates` / `progress` / `limiting`

### 過不足の図は「仮説テスト → 公式」の順で見せる（v16）

`mol ÷ 係数` を最初から見せると、**なぜその計算をするのか**が分からないまま
「小さいほうが答え」という手続きだけが残る。そこで図を**3段階**にした（`#bars`）:

| 段階 | 見せるもの | 狙い |
|---|---|---|
| ① | **持っている量**だけ（÷係数 の値は出さない） | 「多いほうが余るとは限らない」を後で崩すための出発点 |
| ② | **「もし◯◯を使い切るなら？」の検証** | 必要量と所持量をくらべて、**破綻する仮定と成り立つ仮定**を自分で見つける |
| ③ | **`量 ÷ 係数` のまとめ**（限定反応物が決まってから） | ②で納得したことを公式の形に畳む |

②の描き方（`hypothesis()` / `renderHypoBars`）:

```
もし CH₄ を使い切るなら、ほかはどれだけ必要か
  CH₄ 必要 2.0  ████████│                    ちょうど
  O₂  必要 4.0  ████████████│▒▒▒▒            1.0 足りない   ← 超えた分は赤
                棒＝必要な量 ｜ 縦線＝持っている量
        ✗ この仮定は無理（O₂ が 1.0 足りない）
```

- 棒 ＝ **必要な量**、縦線 ＝ **持っている量**。所持量を超えた分は赤、余った分は緑の点線
- 仮定は**何度でも切り替えられる**（同じボタンをもう一度押すと外れて①に戻る）。
  仮定を試しても**停止線は描かない**（限定反応物は最後に自分で選ぶ）
- `feasibleHypothesis(p).sub === limitAnswer(p)` を回帰テストで固定してある。
  **直感の道筋と公式が同じ結論に着く**ことの保証がないと、2つの見せ方が食い違う
- 図の縦の伸縮に合わせて `viewBox` を段階ごとに付け替える（`setViewBox`）。
  凡例と判定は棒の下の帯に置き、重なりは `getBBox` の実測で検査している
- **ちょうど反応の問題では、限定反応物をえらばせない**。「先に足りなくなるほう」が
  **存在しない**問いは成立しないため（v11 まではどちらを選んでも正解にしていた）。
  ちょうど反応は**見せる**問題にする（図が「どちらも同時に無くなる」と教え、
  学習者は倍率から先をやる）。**選択肢を足して凌ぐのではなく、問い自体を作らない**
  という判断（v13。v12 では「どちらも同時」を選択肢に足したが、この型に
  そんな正解は要らない）。データ側の約束として回帰テストで固定してある:
  `steps.limit` と `isExact` は両立しない
- **えらぶまで、止まる位置を図に描かない**。塗りと停止線は答えそのものなので、
  先に描くと肝心の作業が消える（上の①②が「えらぶまで」の段階）。
  えらび直しの途中に出す指摘も、**どちらで止まるかは言わない**（`quotListText`）
- 学習の流れ: **限定反応物をえらぶ**（`steps.limit`）→ **倍率を入れる**（`steps.x`）→
  正しければ**変化量の行が一斉に埋まる** → 問われているセルを計算する。
  段階が済むまで次の入力は無効（比例式モードの `answerReady` と同じ思想）
- 誤答は**何を取り違えたか**を名指しする。採点は `gradeStoich`:

| status | 条件 | 指導 |
|---|---|---|
| `limit` | **余るほうの倍率で計算した** | 「◯◯ は使いきれずに余ります」＋候補倍率を並べて見せる |
| `flip` | 係数を逆さまに使った | 「係数は**かける**数です」 |
| `sigfig` | 値は正しいが桁が違う | 比例式モードと共通（`gradeValue`） |

### g・L で与える／答える（v11）＋【mol を使わなくてよいときは使わない】（v14）

入試の標準形は g や L で出題される。これを **表の外に置いた2つの帯**として扱う。
ただし **mol を経由しなくてよい問題では帯を出さない**（v14 の方針）:

```
① まず mol にそろえる   H₂ 0.60 g → [0.30] mol      （H₂ 1 mol ＝ 2.0 g）
② まず mol にそろえる   O₂ 3.2 g  → [0.10] mol      （O₂ 1 mol ＝ 32 g）
   ［棒くらべ → 3行表（ここは常に mol）］
③ 答えの単位に戻す      H₂O 0.20 mol → [3.6] g      （H₂O 1 mol ＝ 18 g）
```

- **表は最後まで1つの単位で通す**。換算は表の中に混ぜず、必ず外の帯でやる。
  その単位を `workUnit(p)` が決める（`beforeOf()` はその単位で返す）

#### mol を使わなくてよいときは使わない（v14・方針）

係数の比を**その単位のまま**使えるのは、その量が**物質によらず mol に比例する**ときだけ。
これを `coefProportional()` が判定する:

| 単位 | 係数の比に直に乗るか | 理由 |
|---|---|---|
| 体積 L | **乗る**（**量をやりとりする物質**が気体なら） | 標準状態の気体はどれも 22.4 L/mol で共通 |
| 粒子の数 個 | **乗る** | どの物質も 6.0×10²³ 個/mol で共通 |
| 質量 g | **乗らない** | **分子量が物質ごとに違う**。必ず mol を経由する |
| 物質量 mol | —（これが基準） | |

`workUnit(p)` は「与えられた量と問われる量が**すべて同じ単位**で、その単位が上の意味で
係数の比に乗る」なら**その単位**を、そうでなければ `mole` を返す。

- 気体同士の反応（`H₂ ＋ Cl₂ → 2HCl` を L で出題）は **L のまま**計算する。
  22.4 で割って掛け直す二度手間が消え、**問題の値もきれいになる**
  （旧 r14 は 4.48 L・6.72 L と 22.4 の倍数にせざるを得なかったが、
  新 r15 は 2.0 L・3.0 L で出せる）
- **これはアボガドロの法則の要点そのもの**なので、ヒントで根拠を言う:
  「同温・同圧の気体同士なので、係数の比がそのまま体積の比（アボガドロの法則）。
  **mol に直さなくてよい**」
##### 気体かどうかを問うのは「量をやりとりする物質」だけ（v15）

`CH₄ ＋ 2O₂ → CO₂ ＋ 2H₂O` は水が生じるが、**水の量を問わないなら L で通す**
（`measuredSubs()` ＝ 与えられた物質と問われる物質だけを気体判定する）。
式に非気体が現れるだけで L を諦めるのは厳しすぎた（v14 は全物質を見ていた）。

- ただし表の中では水も L で数えることになる。この値は
  **量をそろえるための仮想の体積**（実際には 22.4 L/mol にならない）なので、
  **列見出しに ※ を付け、セルを薄く表示し、表の下に注記を出す**（`isVirtual()` / `virtualSubs()`）。
  黙って混ぜると「水も 22.4 L/mol」という誤解を植えるので、そこは必ず明示する
- **水の量そのものを問う問題では L を使えない**（`r16`: CH₄ 11.2 L → H₂O 何 g）。
  この場合だけ mol を経由する。境界がそのまま問題データとして残っている
- **画面の文言に mol を決め打ちしない**。`unitText(p)` / `divLabel(p)`（＝「mol ÷ 係数」
  または「L ÷ 係数」）を必ず通す。表の下の注記も「単位はすべて L」に変わる
- 表のセルの値は mol でないことがあるので、名前も `tableAnswer` / `checkTable` /
  `state.tableInput` にした（`molAnswer` のままだと嘘になる）
- **単位がそろうまで棒くらべを見せない**。候補倍率には変換後の値が出るので、
  先に見せると変換の答えが分かってしまう。代わりに「まず mol にそろえよう」と出す
- **単位を戻す段がある問題では、表のセルは途中の mol** になる。ここが合うと出口が開く
  （`checkMol` → `molLocked`）。1回の計算ごとに1つの入力、という原則は保つ
- 誤答の再現（`flippedStoich` / `wrongLimitAnswer`）も**答えの単位に直してから**比べる。
  mol のまま比べると採点が噛み合わない
- 段階は `steps: { in, limit, x, out }` で問題ごとに指定。省略した段は済んだ状態で見せる
- 候補倍率の式（`mol ÷ 係数`）は**必ず mol の値で書く**。与えられた量（g）で書こうとして
  `NaN` を出す不具合があった（`given` が `{v, q}` のとき値を直接読んでいた）
- 量を指定しない反応物は**問題文で「十分量の◯◯と反応させた」と明示する**
  （表に「十分量」と出るのに文に書いていない不備があった）

- **答えの単位が mol の問題では帯が出ない**。表のセルがそのまま解答になる
- 「使われた量」を問うときは**変化量の行に答えのセットが来る**が、
  符号（−）はセルの外に出し、学習者は正の数をそのまま入れられるようにした
- 倍率は答えではなく途中の値なので、**割り切れないときは桁を足して … を付ける**
  （丸めた値を断定しない。分数と小数の対照表と同じ流儀）
- **係数を求めさせる問題は作らない**（ion-equation の担当）。回帰テストで固定してある

## 中和滴定モード（M4・v17）

`titration.html` + `titration.js`。**公式 `c₁V₁n₁ ＝ c₂V₂n₂` を入口にしない**。
それでは代入作業になり、「方程式を解くのではなく比例で理解する」という目的に反する。
核心は **H⁺ と OH⁻ が結びついて過不足なく消える**こと（＝ ユーザーの言う
「H⁺ の授受ではなく、H⁺ と OH⁻ が結びつく」）。**量関係はブロックで見せる**。

```
酸　 H₂SO₄   0.10 mol/L × 10.0 mL  価数 2   ███████│███████   H⁺  0.00200
                                            ＝
塩基 NaOH    0.10 mol/L × 20.0 mL  価数 1   ██████████████    OH⁻ 0.00200
              つり合う条件：H⁺ の物質量 ＝ OH⁻ の物質量
```

- **ブロックは価数のぶんだけ分かれる**。H₂SO₄ は1粒から H⁺ を2個出すので、
  同じ mol でもブロックは2倍の長さになる。**数えるのは粒ではなく H⁺ の数**
- **左右のブロックの全長が等しい**ことがつり合い。回帰テストで実測して固定してある
- つり合いが決まる前は、未知側のブロックを**点線の枠＋「?」**で描く
  （長さはつり合いで決まるので、決まった瞬間に相手と同じ長さで現れる）
- 学習の流れ: 既知側の H⁺（OH⁻）の量を出す（`steps.equiv`。ここに
  **mL → L の 1000 で割る**が入る）→ つり合いで同じ量が相手に移る（自動）→
  未知の体積または濃度を求める。他モードと同じ「1回の計算ごとに1入力」
- **公式は正解後のまとめに置く**:「まとめると `c₁V₁n₁ ＝ c₂V₂n₂`。
  上でやったことをそのまま式にしただけ」。順序を逆にしない
- 誤答は2つの定番を名指しする（`gradeTitration`）:

| status | 誤り | 指導 |
|---|---|---|
| `valence` | 価数を無視した（`c₁V₁ ＝ c₂V₂` とやった） | 「1粒から H⁺ を2個出します。数えるのは粒ではなく H⁺ の数」 |
| `unit` | mL と L を直し忘れた（1000倍・1000分の1） | 「濃度は mol/L なので体積は L にそろえます」 |

- 問題は8問。1価どうしの導入 → 濃度を問う（滴定の本来の目的）→ **価数2が効く**（核心）
  → 塩基が2価で問われるのが酸の側 → **弱酸でもつり合いは同じ**（強弱は無関係）
- `n`（価数）は**データに手書きする**。式から導くこともできるが、
  「何価か」は覚える知識であり、そこを問う単元ではないため

## 熱化学モード（M5・v18）

`thermo.html` + `thermo.js`。レンズは**エネルギー図の高さ**。
このアプリの通し筋である「**何かが同じ**」（倍率が同じ／H⁺ ＝ OH⁻）を、ここでは
**どの経路を通っても高さの差は同じ**（ヘスの法則）が担う。

```
  エネルギーが高い ↑
    ┈┈┈┈┈┈┈┈┈┈┈  C(固) ＋ O₂(気)          0     ← 基準（先頭の準位）
       │      │
       │−394  │      CO(気) ＋ ½O₂(気)
       │      ▼ ?  ─────────────────     −111    ← 問われている矢印は赤の点線
       ▼   ▲ −283
    ───────────────  CO₂(気)              −394
```

- **ΔH ＝（到達点の高さ）−（出発点の高さ）**。矢印の向きがそのまま符号の意味になる
  （`to` の側に矢じりを付ける）。**逆向きにたどれば符号が反転する**
- **準位の高さは手書きしない**。与えられた熱化学方程式から**伝播させて**決める
  （`thermoResolve`。先頭の準位を基準 0 とする）
- 学習者は**準位を図に置く**のが仕事（`steps.levels`）。置く順は
  **決まる順**（基準から伝播する順）にする — データの並び順で聞くと、
  根拠がまだ無い準位を先に問うことになる（h2 で CO₂ より先に CO を聞く不具合があった）
- **結合エネルギーの問題は反応物を基準 0 にする**（教科書の図と同じで、原子が上・生成物が下）。
  原子を基準にすると全部が負になって図が読みにくい
- **答えの矢印は答えるまで `?` のまま**。図が答えを先に言わないようにする
- **差が小さい準位は引き離す**（`MIN_GAP`）。黒鉛とダイヤモンド（差 2 kJ に対して
  全体 396 kJ）は比例のままだと2本が重なり、「図で分かる」利点が消える。
  ただし**縮尺を崩したら図にそう書く**（黙って崩さない。差の大きさを誤読させないため）
- **入力のマイナス記号をそろえる**（`normNum`）。表示は −（U+2212）を使うので、
  それをそのまま打ち返されても `parseFloat` が通るようにしておく
- 誤答は2つの定番を名指しする: `sign`（符号だけ逆 → 図の上下で説明する）／
  `addsub`（引くところを足した）
- 問題は6問。逆向きの符号反転 → **ヘスの法則**（CO の生成熱）→ 生成熱から燃焼熱 →
  **結合エネルギー**から反応熱 → その逆問題 → 同素体（差が小さい例）

  **左端に手が届かなくなる**（右にしか送れない）
- **タップ標的は 36px 以上**を目安に保つ。ただし分数の分子・分母だけは

  モーダルは回帰テストの iframe を止めてしまううえ、押し間違いも取り返せない
- **回帰テストは進捗を壊す／進捗に壊される**。`test.html` は本番と同じオリジンなので、
  走らせると学習者の進捗が書き換わり、逆に**残っていた進捗があるとテストが落ちる**
  （q1 を解いた人の環境では「桁ちがいでは正解にならない」が `state.solved.q1` を見て失敗する）。
  **iframe が読み込まれる前**に控えを取って消す必要があるので `test.html` の `<head>` でやり、
  `finish()`（`restoreProgress`）で書き戻す

## モジュール構成

| ファイル | 責務 |
|---|---|
| model.js | 純ロジック。問題データ・倍率（V/H）・推奨判定・有効数字・採点・対照表・天秤・反応。**DOM 非依存** |

| app.js | 比例式モードの UI。表の描画・矢印・倍率入力と自動転記・単位4択・メッセージ生成 |
| balance.js | 天秤モードの UI（SVG の数直線・皿・支点・腕） |
| stoich.js | 反応の量的関係モードの UI（3行表・過不足の棒くらべ・限定反応物のえらび） |
