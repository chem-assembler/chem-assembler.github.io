# 設計メモ: イオン反応式を主にする／反応を2本に分ける

対象は錯イオン・両性水酸化物。2026-07-27 のユーザー指示にもとづく設計。
実装は本メモを正として進め、決まったことは DEVELOPMENT.md のチェックリストに反映する。

## 1. 何が問題か

現在 reactions.json にあるのは**まとめ版だけ**で、しかも1本に混ぜすぎている。

| 現在 | 問題 |
|---|---|
| `complex-cuoh2-nh3`: CuSO₄ ＋ NaOH ＋ NH₃ → [Cu(NH₃)₄](OH)₂ ＋ Na₂SO₄ | 反応物3つ。**NaOH と NH₃ を1本の式に混ぜるのは一般的でない**（実験手順としてはあり得るが、反応式としては書かない） |
| `amphoteric-aloh3-naoh`: AlCl₃ ＋ 4NaOH → Na[Al(OH)₄] ＋ 3NaCl | 分割版が無く、「少量で沈殿・過剰で再溶解」の2段が式として見えない |
| `amphoteric-znoh2-naoh`: 同上 | 同上 |

## 2. 目標の構成

### 銅(Ⅱ)イオン — NaOH 版と NH₃ 版を**別に**作り、相互に遷移できるようにする

**NaOH 版（1段階）**

```
Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓（青白色）
```
過剰に加えても溶けない（Cu(OH)₂ は両性ではない）。ここが Al・Zn との対比になる。

**NH₃ 版（2段階）**

```
1段（少量）  Cu²⁺ ＋ 2NH₃ ＋ 2H₂O → Cu(OH)₂↓ ＋ 2NH₄⁺
2段（過剰）  Cu(OH)₂ ＋ 4NH₃ → [Cu(NH₃)₄]²⁺ ＋ 2OH⁻
```

1段目は「アンモニアが塩基として働く理由」を見せる必要があるので、**2本の足し合わせ**として提示する
（酸化還元モードの半反応式×倍率と同じ操作）。

```
  NH₃ ＋ H₂O → NH₄⁺ ＋ OH⁻      ×2   ← 弱塩基の電離。OH⁻ の出どころ
  Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓            ← 沈殿の本体（NaOH 版と同じ式）
  ────────────────────────────
  Cu²⁺ ＋ 2NH₃ ＋ 2H₂O → Cu(OH)₂↓ ＋ 2NH₄⁺
```

**この形にする理由**: 沈殿そのものは `Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓` で、OH⁻ がどこから来たかによらない。
イオン反応式を標準にすると **NaOH 版と NH₃ 版が文字どおり同じ式**になり、両者を行き来させる意味が立つ。
分子式で書くと `CuSO₄＋2NaOH→…` と `CuSO₄＋2NH₃＋2H₂O→…` になって同じ反応に見えない。

### 両性水酸化物 — 分割版とまとめ版の**両方**を持つ

```
分割  Al³⁺ ＋ 3OH⁻ → Al(OH)₃↓        Al(OH)₃ ＋ OH⁻ → [Al(OH)₄]⁻
まとめ Al³⁺ ＋ 4OH⁻ → [Al(OH)₄]⁻
Zn:   Zn²⁺ ＋ 2OH⁻ → Zn(OH)₂↓        Zn(OH)₂ ＋ 2OH⁻ → [Zn(OH)₄]²⁻   ／ まとめ 4OH⁻
```

「少量なら沈殿・過剰なら溶ける」は**2本に分けて初めて式として見える**。まとめ版は
「結局いくつ OH⁻ が要るか」を答える形として残し、分割版とリンクする。

## 3. 必要になる仕組み（4つ）

### (a) イオン反応式を主にできるようにする

いまは分子式が主で、イオン反応式は `netIon`（クリア後に出る従の表示）。
ステージに `primary: "ionic"` を持たせ、**反応式パネルの項そのものをイオン種にする**。

- 係数パズルの判定は `checkStageCoeffs` がそのまま使える（`compareSides` は原子だけでなく
  **電荷も保存を見ている**ため、イオン式でも正しく判定できる）
- 分子式の併記は残す（入試では分子式を書かせることもあるため）。主従が入れ替わるだけ
- 影響範囲: `buildEquationUI` / `renderTally` / 数合わせビュー（項の分解が既に `partsOf` 経由なので、
  イオン種はそれ自身に分解される＝そのまま動く見込み）

### (b) 沈殿を反応物として投入できるようにする

2段目はどれも **沈殿から始まる**（Cu(OH)₂・Al(OH)₃・Zn(OH)₂）。
いまは反応物を投入すると必ず電離するので、`SOLID_SPECIES` の種は電離させず
**沈殿として底に置く**投入経路を足す（`dissociateMolecule` で分岐し、mode を "sink" にする）。

**副産物**: 設計時点では索引に「準備中（参照のみ）」で出ていた `complex-agcl-nh3`
（AgCl ＋ 2NH₃ →[Ag(NH₃)₂]Cl。ハロゲン化銀の識別）も同時に遊べるようになる
（v89 で実現。なお `playable` フィールドは v164 で廃止し、ステージの実在から導出している）。

### (c) NH₃ ＋ H₂O → NH₄⁺ ＋ OH⁻ の表現

DEVELOPMENT.md の M4 で「溶媒の水を要する」として残していた宿題。ここで回収する。

- ルール案: `{ find: ["NH3"], solvent: "H2O", make: ["NH4+", "OH-"], kind: "ionize" }`
- ビーカーでは、溶媒層から薄い H₂O の粒を1個わかせて NH₃ とくっつけ、NH₄⁺ と OH⁻ に分ける
  （水が「無限にある背景」ではなく、反応に参加した1個だけが見える）
- 原子の保存検査（監査・テスト）は、わかせた H₂O を投入分に加えて数える必要がある。
  **`solvent` で消費した数を記録する**カウンタを足す

### (d) 反応どうしのリンク

データに関係を持たせ、インデックスとステージ画面から行き来できるようにする。

```jsonc
"steps":     ["id1", "id2"],   // まとめ版 → 分割版（この2本に分けて書ける）
"combined":  "id",             // 分割版 → まとめ版
"variantOf": "id"              // NaOH 版 ⇄ NH₃ 版（同じ沈殿を別の試薬で）
```

## 4-2. 塩の加水分解と、電離度・pH をどこまでやるか（2026-08-09 決着）

M4 の残りだった2件のうち、**加水分解は実装した**（v165 酢酸ナトリウム＝塩基性／
v166 塩化アンモニウム＝酸性）。ここでは残る「電離度・pH の扱い」の結論を書く。

### 加水分解で新しくできた道具: `per`（何個に1個が変わるか）

加水分解は**相手を待たない**反応で、ここが (c) の `WATER_IONIZATION` と決定的に違う。
弱電解質も弱塩基も「相手が来たときだけ分かれる」が、加水分解は相手がいなくても
勝手に少しだけ進む。しかも進むのはごく一部（0.1 mol/L の酢酸ナトリウムで1万個に1個ほど）。

そこで rule に `per` を持たせ、**per 個につき1個だけ**を分ける。あわせて評価も分けた
（`evaluateHydrolysis`）。既存の「ちょうど反応しきったらクリア／余ったら足す」を
そのまま当てると**嘘になる**からで、残っているイオンは足りないのではなく、それが正しい姿。
メッセージは必ず「残り N 個はそのまま」を言い、矢印は ⇄ にしてある。

**この `per` が、電離度をこのアプリで扱うための土台になる。**

#### `per` は画面の個数であって、式の係数ではない（v185 で作り直した）

per は**誇張**である。実際は1万個に1個ほどしか進まないところを、粒で見えるように5個に1個にしている。
ところが v182 までは、その per 個を**人が ＋ で並べてから**でないと何も起こらず、
投入数はビーカーの上に 25px の太字で出ていた（「5 CH₃COONa」）。
結果、**「5個入れて初めて正解」＝ 係数は5** と読まれた
（ユーザーの申し立て:「31 酢酸5分子で正解にするのは微妙。反応式の係数は１」）。

**per 個を並べる操作そのものに学びは無い。** 伝えたいのは
「入れたもののごく一部しか変わらない」ことだけで、そこは per 個入っていれば見える。
そこで v185 から:

- **`prefillPartial`（app.js）が、ステージを開いた時点で per 個を置く。**
  個数は `sampleInputs`（＝ per）から導く。ここに数を書くと per を変えたとき黙ってずれる
- **画面の個数と式の係数を、言葉で3か所切り離す** ——
  ビーカー上の数のすぐ下（`.addedNote`「画面に置いた数（式の係数ではない）」）／
  導入文（「見せるための誇張で、反応式の係数とは別もの」）／
  係数を入れる案内（「ビーカーに置いた個数ではなく、左右がつり合う数を入れる」）
- **「ちょうど反応しきった」の緑（`.addedFormula.matched`）は当てない。**
  あれは「この個数比が係数の比」という合図で、per のステージでは嘘になる
- **＋ボタンは残す。** 倍入れれば2個目が変わる（`floor(total/per)`）ので、
  誇張であることを自分で確かめられる

⚠ **誇張であることは、どのステージも doneNote で必ず言う**（テストが `誇張` と `個に1個` を見張る）。
塩化アンモニウム側だけこの一文が無く、背中合わせの酢酸ナトリウム側と食い違っていたので v185 で足した。
**アプリが置くようにしたぶん、置かれた数が「本当の割合」と読まれる危険はむしろ増える**ので、
ここは弱めてはいけない。

### 電離度 α — ion で扱う。別ステージとして立てた（v167・実装ずみ）

α は「入れた分子のうち何個が分かれたか」＝**粒の数そのもの**なので、
数式ではなく画で見せられる。このアプリの土俵で、`per` がそのまま使えた。

**現行の弱酸ステージ（v38 酢酸×NaOH）には足さず、別ステージにした。** あちらは
「分子のまま溶け、中和のときだけ電離して補う（ルシャトリエ）」を見せる筋書きで、
そこへ常時の微小電離を混ぜると主筋がぼやける。かわりに、v38 が**電離を省いている**ことを
新ステージの doneNote で明かす。省略を回収しないと「酢酸は中和されるまで電離しない」と
覚えてしまうので、これは単なる補足ではなく必要な後始末。

実装で分かったこと2つ:

- **仕組みの名前が狭かった。** 加水分解と電離は化学としては別物だが、画面の上でやることは同じ
  （相手を待たず per 個に1個・残りはそのまま・矢印 ⇄・「ちょうど反応しきる」評価は当てない）。
  そこで `hydrolysisRule` を `partialRule`／`PARTIAL_KINDS`（hydrolysis・ionization）に広げた。
  **共通なのはそこまで**で、「加水分解で」なのか「電離して」なのか、見どころが液性なのか
  電離度なのかは kind で分ける
- **模範投入数を `answer` に手書きしていたのをやめた。** 加水分解の2ステージは
  `answer[0]` に per と同じ数を書いていたが、これは per を変えたときに片方だけ古くなって
  「模範どおり入れたのに何も起きない」になる。`sampleInputs(stage)` で per から**導く**ようにし、
  式を molecular / ionic に持つステージは top-level の `answer` を持たないことをテストで固定した
  （＝ answer は常に「反応式の係数」だけを意味する）

### pH の計算 — ion では扱わない（ratio 側の仕事）

pH ＝ −log[H⁺] は**計算**であって、粒を見て分かるものではない。
リポジトリの役割分担は「**ion は見る、ratio は計算する**」で、ratio はすでに
中和滴定を持っている。ion に対数の計算器を作るのは、この分担を崩すだけで得がない。

ただし現状は**どちらのアプリにも pH が無い**（ratio の収録は mol 計算・平均原子量・
反応の量的関係・中和滴定・熱化学の5つ）。**「ion がやらない」＝「ratio がもう持っている」
ではない**ので、ratio 側の宿題として残ることをここに明記しておく。
できたときの横断リンクは、既存どおり**式の照合**で自動的につながる（対応表は書かない）。

### 分子反応式を書かない反応がある（`noMolecular`）

塩化アンモニウムの加水分解は、この設計で初めて**分子反応式を持たない**ステージになった。
教科書の NH₄Cl ＋ H₂O ⇄ NH₃·H₂O ＋ HCl には NH₃·H₂O が要るが、(c) で決めたとおり
このアプリは **NH₃ と H₂O を別々に扱う**。水を外した NH₄Cl ⇄ NH₃ ＋ HCl は加熱の式で、
水の中では起きない。そこで切り替えボタンを出さず、**なぜ無いか**を画面に出す。

副作用として、式がイオンだけになるぶん登場種の導出が「NH₄Cl」を拾えず、
**入れる物質の名前で索引を引けなくなる**。reactions.json に `reagents`
（ビーカーに入れる試薬）を足し、導出側がそこも見るようにして塞いだ。

# 6. 右（係数）を本体にする（2026-09-07・レーン `ion-tidy`）

イオン反応モードの画面を整理する。ユーザーの指示は3つ。

> イオン反応　左がわの模式図／最小公倍数でないときに、インストラクションが必要／
> 酸と塩基の比はあっているが、もっと簡単な整数比にできる

> そもそも左の係数合わせ　と　右の係数合わせ　で内容がかぶっているので
> 右のコンテンツをメインにし、正解後にアニメーションで確認　という　オプションの位置づけにするのがよいかも

> 化学反応式を完成させよう／分子反応式／イオン反応式／係数を１つ入れた段階でイオンのグラフィックを表示

## 6-1. 「左の係数合わせ」と「右の係数合わせ」は何と何か

画面には**数を決める場所が4つ**ある。

| # | どこ | 何を動かすか | 出る条件 |
|---|---|---|---|
| ① | ビーカーの「＋ 試薬」ボタン | `addedCount`（投入した分子の数） | 常に |
| ② | 反応式のステッパー `− ？ ＋` | `coeffs`（反応式の係数） | 常に |
| ③ | 中和のブロック模式図の「＋」 | `coeffs`（②と同じ配列） | `protonSchema` があるとき |
| ④ | 価数＝高さのブロックの一覧 | `coeffs`（②と同じ配列） | `ionBlockPairOf` が拾う5ステージ |

③④は**②と同じ数**を指しているので、かぶっているのは「①と②」。
これがユーザーの言う「左の係数合わせ／右の係数合わせ」で、**同じ比を2回決めさせている**。
しかも `maybeClear()` は `reactionDone && coeffOk` ＝ **両方そろわないとクリアにならない**ので、
かぶりは見た目だけでなく、進行の条件そのものだった。

## 6-2. 決め（★ ここがこの節の結論）

| | いつ出るか |
|---|---|
| **イオンのグラフィック**（何個あるかが見える**静止**の図） | 係数を**1つ**入れた時点から |
| **アニメーション**（組み変わって生成物ができる**動き**） | いつでも押せるが、**正解後に「確かめる」として誘う** |
| **クリアの条件** | **係数だけ**（`coeffOk`）。ビーカーの実験は要求しない |

★ **本体は②（反応式の係数）**。①は「答え合わせの実験」に降りる。

⚠ **①を消さない。** ＋ボタンも ⚡反応させる もそのまま残す。
ポータルの札が「水の中でイオンがどう組み変わるかを見ながら、反応式の係数を自分で決める」と
書いているとおり、ビーカーはこのアプリの看板そのもので、**変えるのはどちらが主役かだけ**。

## 6-3. 「係数を1つ入れた段階でイオンのグラフィックを表示」とは、数合わせ帯のこと

ユーザーがこの言葉を書いた画面は「化学反応式を完成させよう／分子反応式／イオン反応式」——
**右のパネル**である。右のパネルで「係数を入れると出るイオンの図」は**粒で見る数合わせ**
（`buildRecombine`・`#recombineWrap`）で、そこには

```
左辺の係数を入れると組み変えを試せる（右辺はあとからでもよい）
```

と出たまま**左辺の係数が全部そろうまで1粒も描かれない**。
発注書の言う「全部そろうまで待たない」はここを指している。

**直し**: 左辺の係数が**1つでも**入っていれば、入っているぶんの列を描く。
未入力の列は見出しを「？」のまま残す（＝**あと何を入れればよいかが図で分かる**）。
⇄ の釦は左辺がそろうまで押せないままにする —— **図（静止）と動き（アニメ）を分ける**のが 6-2 の決めで、
半端な係数で組み変えを走らせると `simulateFormation` が「0 個できた」を返して、
足りないのか間違いなのかが読めなくなる。

### ⚠ 実際には違っていた点 ―― イオン反応式のときは数合わせ帯が出ない

`onCoeffChange` が `recombineWrapEl.hidden = eqMode === "ionic"` にしている。
理由はコード側のコメントどおりで、この帯は「イオンを組み替えて**分子の**生成物をつくる」見方だから。
したがって **イオン反応式で解くステージ（primary: "ionic" の14本）では、この直しは効かない。**
そこで出る静止の図は ④価数ブロック（5本）だけで、**錯イオン・再溶解の9本には図が無い**。

ここは**この版では埋めない**。埋め方は「帯をイオン反応式の項でも組む」だが、
`simulateFormation` が `eqOf(stage)`（分子式）を決め打ちしていて、
既存の回帰テスト（「イオン式のとき数合わせが出てしまう」）とも正面からぶつかる。
**ユーザーに諮る**（→ §6-7）。

## 6-4. 「最小公倍数でないときのインストラクション」は**ビーカー**に無かった

同じ状態に対して画面は3か所でものを言う。

| どこ | 2:2 を入れたとき（正解は 1:1） |
|---|---|
| 反応式（`eqMsg`） | 「つり合っているけれど、係数がすべて 2 で割り切れる。2:2:2:2 → 1:1:1:1 に直そう」💡橙 |
| 中和模式図（`schematicMsg`） | 「つり合ってはいるけれど、同じ組み合わせを 2 回くり返しているだけ…」💡橙 |
| **ビーカー（`msg`）** | **「ちょうど反応しきった！ 投入した数は HCl : NaOH ＝ 2 : 2。この比が係数のヒント。」** ✓緑 |

★ **3つめが穴。** ビーカーは 2:2 を**緑の成功**として返し、しかも
「この比が係数のヒント」と**そのまま書き写すよう勧めている**。勧められたとおり
2:2:2:2 と入れると、右のパネルが 💡 で「2 で割れる」と言う ＝ **アプリが自分で誘導して自分で止める**。

ユーザーの「左がわの模式図／最小公倍数でないときに、インストラクションが必要／
酸と塩基の比はあっているが、もっと簡単な整数比にできる」はここを指している。

**直し**: `evaluateReactionInner()` の「ちょうど反応しきった」で、投入比が最簡でなければ
`simplestRatioAdvice`（`schematic.js`。他の2か所と同じ道具）を通し、
**「比は合っている」と認めたうえで「係数にするときは割る」**まで言う。
⚠ 色は緑（`ok`）のまま。ちょうど反応しきったのは事実で、実験としては成功しているため
—— **ここを赤や橙にすると「2個ずつ入れたのが間違い」に読める**。言い足すのは
「図の個数」と「式の係数」の**あいだの一手**であって、実験の否定ではない。

## 6-5. ステッパー（②）とブロック（④）をどう畳むか

DESIGN_ion_blocks.md §5 が「消すかどうかは、あとの『イオン反応モードの整理』レーンが決める」と
残していた宿題。**結論: ②を唯一の入力にし、④は「触れる図」にする。**

- **②のステッパーは残す。** ④が出るのは40ステージ中5本だけなので、④を主入力にすると
  残り35本と操作が変わる。**同じ画面で入力の形が変わるほうが害が大きい。**
- **④の一覧（`#blocksPalette` の「＋ Ba²⁺」「− 1つ戻す」）は出さない。**
  イオン反応モードでは**選択肢が片側1種ずつしかない**ので、この一覧は
  「押すと1増える釦」＝②の複製でしかない。図の下に釦の列がもう1つ並ぶ見た目そのものが、
  ユーザーの言う「かぶっている」の一部だった。
- **図そのものは触れるままにする。** 列を押せば積み、ブロックを押せば減る
  （後者は既にある）。**「価数を高さにしたブロックをつくり、高さ合わせをする」**という
  ユーザーの言葉は、釦ではなく**図を直接動かすこと**を指しているとみる。
- ⚠ **`blocks.js` の一覧の仕組みは消さない。** `paletteEl` を渡さなければ出ないだけにする。
  酸化還元⑥（余ったイオンから塩を組む）では**イオンを選ぶ**ことに意味があり、そこでは要る。

## 6-6. 「分子反応式／イオン反応式」は切り替えのまま（並べない）

ユーザーは2回とも「化学反応式を完成させよう／分子反応式／イオン反応式」と**並べて**書いた。
実機で見比べて、**切り替えのまま**にした。理由:

1. **並べると①②のかぶりを作り直すことになる。** 2つの式は同じ反応の2つの姿で、
   係数は別（s5 は分子 1:1:1:2、イオン 1:1:1）。両方に `− ？ ＋` を出せば
   **同じ反応に対する係数パズルが画面に2つ**並ぶ ＝ この節がやめようとしていることそのもの。
2. **もう一方を「解いた形」で並べると答えを渡す。** 片方の係数はもう片方の係数からほぼ決まる。
3. 分子反応式を持たないステージ（`noMolecular` の塩化アンモニウム）があり、
   「並べる」は全ステージには成り立たない。
4. **正解後には既に両方が見えている** ——「この反応の本質（イオン反応式）」の1行がそれ。

その代わり、**2つあることが読み取れない**という指摘は受け止める（ボタンが2つ並ぶだけで、
何の2択かが書いていない）。`#eqMode` に見出しを1つ足して「同じ反応の2つの書き方」と示す。

## 6-7. ユーザーに決めてもらうこと

- **イオン反応式で解く14ステージに、係数と連動する静止の図をどこまで用意するか**（§6-3）。
  いまは価数ブロックの5本だけ。残り9本（錯イオン・沈殿の再溶解）は図なしのまま。
- **ビーカーを係数に連動させるか**（＝係数を入れるとビーカーに試薬が落ちる）。
  この版では**しない**。①の手入力とぶつかり、既存の回帰テスト 108 か所が
  「＋を押してから反応させる」で書かれているため。連動させるなら、
  ビーカーが「自分で入れる場」から「係数の鏡」に変わるので、遊び方パネルの4ステップから書き直しになる。

# 7. ビーカーを「数える場」から「見て確かめる場」に変える（2026-09-08・レーン `ion-beaker`）

§6-7 で「ユーザーに諮る」と残した2つめ（ビーカーを係数に連動させるか）に、ユーザーが直接答えた。

> ビーカー内でイオンの数を数えるのは難しいと考えます。
> 数合わせはイオンの整列に任せ、ビーカーは正解時に実際の水溶液中の様子（沈殿する、電離している、
> 気体発生する）を把握することを目的とするのがよいと考えています。
> 係数合わせが正解したときに、その係数に合わせたアニメーションが自動的に再生される、
> もう一度再生するボタンを用意する、オプションで、別な係数比を試すことも可能、というのはどうでしょうか

## 7-1. 決め

| | v202（いま） | この版 |
|---|---|---|
| 数を合わせる場所 | ビーカーの ＋ でも、右の係数でも | **イオンの整列（右のパネル）だけ** |
| ビーカーの仕事 | 自分で入れて反応させる実験台 | **正解した係数どおりの姿を見て、水の中で何が起きるかをつかむ** |
| 動き出すきっかけ | 人が ⚡反応させる を押す | **係数が合った瞬間に自動で再生**＋「▶ もう一度再生」 |
| 別の比を試す | 既定の道 | **オプション**（`<details>` に畳む。取り上げはしない） |

★ §6-2 は「①（＋ボタン）を答え合わせの実験に降ろす」までだった。ここはその続きで、
**ビーカーの目的そのものを言い直す** —— 見るのは「何個入れたか」ではなく
**「沈殿したのか・電離したままなのか・気体になって出ていったのか」**。

## 7-2. 「係数に合わせた」を何から出すか —— `sampleInputs` のまま

⚠ **入れる数を新たに書かない。** クリアの条件は「原子と電荷がつり合い、かつ最簡整数比」なので、
**正解した時点で投入すべき数は一意に決まる** ＝ `sampleInputs(stage)`（分子式の左辺の係数。
加水分解・電離は `per`）。ユーザーの言う「その係数に合わせた」はこれで満たされる。

⚠ **イオン反応式で解いた場合、入力欄の数はそのまま使えない**（s5 は分子 1:1:1:2 / イオン 1:1:1 で、
ビーカーに入れるのは分子のほう）。だから「入力欄の数を読む」ではなく「正解から導く」が正しい。

## 7-3. 自動再生の作法（★ 消してよい画面と、消してはいけない画面）

`playCoeffAnimation()` ＝ **ビーカーだけを初期化** → `sampleInputs` ぶん入れる → `doReact()`。
係数・クリア状態は触らない（`resetBeaker()` を `initStage()` から切り出す）。

- **自動で走るのは、係数が合った最初の1回だけ**（`autoPlayed`）。
- ⚠ **すでに実験した人（`reactionDone`）の画面は勝手に消さない。** 自動再生を見送り、
  釦（「▶ もう一度再生」）だけを出す。**自分の実験を横から消されるのがいちばん困る**ので、
  ここは「自動が親切」より「勝手に消さない」を採る。
- 釦の名は状態で変える —— まだ走っていなければ「▶ 係数どおりに再生」、走ったあとは「▶ もう一度再生」。
- 置き場所は**ビーカーの上**（クリアの帯は右のパネルにあり、見る場所と離れている）。
  クリアの帯の「▶ ビーカーで確かめる」は**同じ関数を呼ぶ**ので、どちらから入っても同じ。

## 7-4. ＋ボタンは「オプション」に畳む（消さない）

★ ユーザーは「オプションで、別な係数比を試すことも可能」と書いた ＝ **手で入れる道は残す**。
`#toolbar` の中に `<details class="freeTry">` を置き、**＋ボタン・⚡反応させる・ドラッグの案内**を
その中へ移す。既定は閉じ。**既定の顔に出るのは「▶ 再生」と「↺ やり直す」の2つだけ。**

⚠ **セレクタは変えない**（`#toolbar .add` / `#toolbar .react`）。畳んだ `<details>` の中でも
`click()` は届くので、既存の回帰テスト 100 か所以上がそのまま意味を保つ。
**畳んだこと自体を検査するテストを1本足す**（否定対照つき）。

## 7-5. 「何が起きたか」を読み取れるようにする（★ ここが仕事の中心）

いまの結びは **「ちょうど反応しきった！ 投入した数は AgNO₃ : NaCl ＝ 1 : 1。この比が係数のヒント。」**
—— **数の話**である。係数がもう決まっている画面では、この一文は用済みで、しかも
「ビーカーで数を決める」という古い目的をまだ名乗っている。

2つ直す。

1. **結びを状態の話にする。** `observationText()` が、反応後の粒から
   **沈殿・気体・電離したまま残っているイオン・できた水**を読んで1文にする。
   ⚠ 手で書かない（ステージごとに書くと、ルールを変えたとき黙って古くなる）。
   気体の空間（燃焼）のステージでは「水の中」と言わない。
2. **「この比が係数のヒント」は係数がまだ決まっていないときだけ言う**（`!coeffOk`）。
   §6-4 で足した「比は合っているが最簡でない」の言い足しも同じ条件に入る
   —— 正解したあとに「係数のヒント」と言うのは**もう終わった仕事の案内**。

さらに、粒の一覧（`#ionCounts`）を**状態で3つに分ける**:
「沈殿（水に溶けない）」「溶けている（イオン）」「気体（空気中へ）」。
★ 図の粒を数えなくても、**どの物質がどの状態にいるか**が札の並びで読める。

## 7-6. 遊び方（4ステップ）を書き直す

★ 古くなるので必ず書き直す。順は「係数を入れる → 粒で数える → 自動で再生される → 別の比を試す」。

## 7-7. 単原子イオンの電荷が二重に出ている（ユーザー指摘・実機で確認）

> 単原子イオンでは、化学式の右上の電荷と、イオンの円につく電荷がかぶっています。
> どちらかだけに揃えたほうがよいのではと考えます

**実機（ヘッドレス）で全 40 ステージを反応させ、ビーカーの粒の `<text>` を全部拾って確かめた。**
二重になっていたのは **`COMPOSITION` の枠つきの粒**（`makeParticleEl` の compositionLayout 枝）だけ:

| 種 | 枠の中の名札 | 外枠のバッジ |
|---|---|---|
| `NH₄⁺` | NH₃ / **H⁺** | **＋** |
| `[Cu(NH₃)₄]²⁺` | **Cu²⁺** / NH₃×4 | **2+** |
| `[Ag(NH₃)₂]⁺` | **Ag⁺** / NH₃×2 | **＋** |
| `[Al(OH)₄]⁻` | Al³⁺ / OH⁻×4 | − |
| `[Zn(OH)₄]²⁻` | Zn²⁺ / OH⁻×4 | 2− |

上の3件は**同じ電荷が同じ大きさで2回**出る（中心が単原子イオンで、配位子が中性だから
全体の電荷＝中心の電荷）。ユーザーの言う「単原子イオン」と正確に符合する。
コードのコメントは「外枠にバッジが無い位置なので重複しない」と言っていたが、**沈殿（電荷0）でしか成り立っていなかった。**

**二重でなかった場所**（見たが該当しなかった）: ふつうの粒（`stripCharge` 済み。`Ca²⁺` → 円に「Ca」＋バッジ「2+」）／
房表示の多原子イオン（原子記号＋バッジ）／`#ionCounts` の札／粒で見る数合わせ帯（`buildRecombine`。名札だけでバッジ無し）／
価数ブロック（`blocks.js`。名札だけ）／中和の模式図（`schematic.js`。バッジを付けない）。

### 直し —— **バッジに揃える**（アプリがすでに選んでいるほう）

枠の中の構成イオンも、外の自由なイオンと**同じ書き方**にする ＝ 右肩の電荷を外し、**小さいバッジ**を付ける。

- ★ **意図（何イオンかを読ませる）は潰れない。** むしろ、さっきまで水に浮いていた `Cu²⁺`
  （円＋バッジ）と、錯イオンの中心に収まった `Cu²⁺` が**同じ姿**になる ＝ 同じものだと分かる。
  いままでは自由なときは「Cu ＋バッジ」・枠の中では「Cu²⁺」と、同じイオンを2通りに書いていた。
- 外枠のバッジは**大きいまま**残す（全体の電荷）。大きさで「部分」と「全体」が分かれる。
- ⚠ 沈殿（電荷0の□枠）も同じ直しを当てる。**枠の中だけ別の書き方**にすると、
  直した理由（書き方を1つにする）がそこで破れる。
