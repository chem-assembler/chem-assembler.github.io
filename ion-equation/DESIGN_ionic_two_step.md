# 設計メモ: イオン反応式を主にする／反応を2本に分ける

対象は錯イオン・両性水酸化物。2026-07-27 のユーザー指示にもとづく設計。
実装は本メモを正として進め、決まったことは DEVELOPMENT.md のチェックリストに反映する。

## 1. 何が問題か

現在 reactions.json にあるのは**まとめ版だけ**で、しかも1本に混ぜすぎている。

| 現在 | 問題 |
|---|---|
| `complex-cuoh2-nh3`: CuSO₄ ＋ NaOH ＋ NH₃ → [Cu(NH₃)₄](OH)₂ ＋ Na₂SO₄ | 反応物3つ。**NaOH と NH₃ を1本の式に混ぜるのは一般的でない**（実験手順としてはあり得るが、反応式としては書かない） |
| `amphoteric-aloh3-naoh`: AlCl₃ ＋ 4NaOH → Na[Al(OH)₄] ＋ 3NaCl | 分割版が無く、「少量で沈殿・過剰で再溶解」の2段が式として見えない |
| `amphoteric-znoh2-naoh`: 同上 | 同上 |

## 2. 目標の構成

### 銅(Ⅱ)イオン — NaOH 版と NH₃ 版を**別に**作り、相互に遷移できるようにする

**NaOH 版（1段階）**

```
Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓（青白色）
```
過剰に加えても溶けない（Cu(OH)₂ は両性ではない）。ここが Al・Zn との対比になる。

**NH₃ 版（2段階）**

```
1段（少量）  Cu²⁺ ＋ 2NH₃ ＋ 2H₂O → Cu(OH)₂↓ ＋ 2NH₄⁺
2段（過剰）  Cu(OH)₂ ＋ 4NH₃ → [Cu(NH₃)₄]²⁺ ＋ 2OH⁻
```

1段目は「アンモニアが塩基として働く理由」を見せる必要があるので、**2本の足し合わせ**として提示する
（酸化還元モードの半反応式×倍率と同じ操作）。

```
  NH₃ ＋ H₂O → NH₄⁺ ＋ OH⁻      ×2   ← 弱塩基の電離。OH⁻ の出どころ
  Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓            ← 沈殿の本体（NaOH 版と同じ式）
  ────────────────────────────
  Cu²⁺ ＋ 2NH₃ ＋ 2H₂O → Cu(OH)₂↓ ＋ 2NH₄⁺
```

**この形にする理由**: 沈殿そのものは `Cu²⁺ ＋ 2OH⁻ → Cu(OH)₂↓` で、OH⁻ がどこから来たかによらない。
イオン反応式を標準にすると **NaOH 版と NH₃ 版が文字どおり同じ式**になり、両者を行き来させる意味が立つ。
分子式で書くと `CuSO₄＋2NaOH→…` と `CuSO₄＋2NH₃＋2H₂O→…` になって同じ反応に見えない。

### 両性水酸化物 — 分割版とまとめ版の**両方**を持つ

```
分割  Al³⁺ ＋ 3OH⁻ → Al(OH)₃↓        Al(OH)₃ ＋ OH⁻ → [Al(OH)₄]⁻
まとめ Al³⁺ ＋ 4OH⁻ → [Al(OH)₄]⁻
Zn:   Zn²⁺ ＋ 2OH⁻ → Zn(OH)₂↓        Zn(OH)₂ ＋ 2OH⁻ → [Zn(OH)₄]²⁻   ／ まとめ 4OH⁻
```

「少量なら沈殿・過剰なら溶ける」は**2本に分けて初めて式として見える**。まとめ版は
「結局いくつ OH⁻ が要るか」を答える形として残し、分割版とリンクする。

## 3. 必要になる仕組み（4つ）

### (a) イオン反応式を主にできるようにする

いまは分子式が主で、イオン反応式は `netIon`（クリア後に出る従の表示）。
ステージに `primary: "ionic"` を持たせ、**反応式パネルの項そのものをイオン種にする**。

- 係数パズルの判定は `checkStageCoeffs` がそのまま使える（`compareSides` は原子だけでなく
  **電荷も保存を見ている**ため、イオン式でも正しく判定できる）
- 分子式の併記は残す（入試では分子式を書かせることもあるため）。主従が入れ替わるだけ
- 影響範囲: `buildEquationUI` / `renderTally` / 数合わせビュー（項の分解が既に `partsOf` 経由なので、
  イオン種はそれ自身に分解される＝そのまま動く見込み）

### (b) 沈殿を反応物として投入できるようにする

2段目はどれも **沈殿から始まる**（Cu(OH)₂・Al(OH)₃・Zn(OH)₂）。
いまは反応物を投入すると必ず電離するので、`SOLID_SPECIES` の種は電離させず
**沈殿として底に置く**投入経路を足す（`dissociateMolecule` で分岐し、mode を "sink" にする）。

**副産物**: 設計時点では索引に「準備中（参照のみ）」で出ていた `complex-agcl-nh3`
（AgCl ＋ 2NH₃ →[Ag(NH₃)₂]Cl。ハロゲン化銀の識別）も同時に遊べるようになる
（v89 で実現。なお `playable` フィールドは v164 で廃止し、ステージの実在から導出している）。

### (c) NH₃ ＋ H₂O → NH₄⁺ ＋ OH⁻ の表現

DEVELOPMENT.md の M4 で「溶媒の水を要する」として残していた宿題。ここで回収する。

- ルール案: `{ find: ["NH3"], solvent: "H2O", make: ["NH4+", "OH-"], kind: "ionize" }`
- ビーカーでは、溶媒層から薄い H₂O の粒を1個わかせて NH₃ とくっつけ、NH₄⁺ と OH⁻ に分ける
  （水が「無限にある背景」ではなく、反応に参加した1個だけが見える）
- 原子の保存検査（監査・テスト）は、わかせた H₂O を投入分に加えて数える必要がある。
  **`solvent` で消費した数を記録する**カウンタを足す

### (d) 反応どうしのリンク

データに関係を持たせ、インデックスとステージ画面から行き来できるようにする。

```jsonc
"steps":     ["id1", "id2"],   // まとめ版 → 分割版（この2本に分けて書ける）
"combined":  "id",             // 分割版 → まとめ版
"variantOf": "id"              // NaOH 版 ⇄ NH₃ 版（同じ沈殿を別の試薬で）
```

## 4-2. 塩の加水分解と、電離度・pH をどこまでやるか（2026-08-09 決着）

M4 の残りだった2件のうち、**加水分解は実装した**（v165 酢酸ナトリウム＝塩基性／
v166 塩化アンモニウム＝酸性）。ここでは残る「電離度・pH の扱い」の結論を書く。

### 加水分解で新しくできた道具: `per`（何個に1個が変わるか）

加水分解は**相手を待たない**反応で、ここが (c) の `WATER_IONIZATION` と決定的に違う。
弱電解質も弱塩基も「相手が来たときだけ分かれる」が、加水分解は相手がいなくても
勝手に少しだけ進む。しかも進むのはごく一部（0.1 mol/L の酢酸ナトリウムで1万個に1個ほど）。

そこで rule に `per` を持たせ、**per 個につき1個だけ**を分ける。あわせて評価も分けた
（`evaluateHydrolysis`）。既存の「ちょうど反応しきったらクリア／余ったら足す」を
そのまま当てると**嘘になる**からで、残っているイオンは足りないのではなく、それが正しい姿。
メッセージは必ず「残り N 個はそのまま」を言い、矢印は ⇄ にしてある。

**この `per` が、電離度をこのアプリで扱うための土台になる。**

#### `per` は画面の個数であって、式の係数ではない（v185 で作り直した）

per は**誇張**である。実際は1万個に1個ほどしか進まないところを、粒で見えるように5個に1個にしている。
ところが v182 までは、その per 個を**人が ＋ で並べてから**でないと何も起こらず、
投入数はビーカーの上に 25px の太字で出ていた（「5 CH₃COONa」）。
結果、**「5個入れて初めて正解」＝ 係数は5** と読まれた
（ユーザーの申し立て:「31 酢酸5分子で正解にするのは微妙。反応式の係数は１」）。

**per 個を並べる操作そのものに学びは無い。** 伝えたいのは
「入れたもののごく一部しか変わらない」ことだけで、そこは per 個入っていれば見える。
そこで v185 から:

- **`prefillPartial`（app.js）が、ステージを開いた時点で per 個を置く。**
  個数は `sampleInputs`（＝ per）から導く。ここに数を書くと per を変えたとき黙ってずれる
- **画面の個数と式の係数を、言葉で3か所切り離す** ——
  ビーカー上の数のすぐ下（`.addedNote`「画面に置いた数（式の係数ではない）」）／
  導入文（「見せるための誇張で、反応式の係数とは別もの」）／
  係数を入れる案内（「ビーカーに置いた個数ではなく、左右がつり合う数を入れる」）
- **「ちょうど反応しきった」の緑（`.addedFormula.matched`）は当てない。**
  あれは「この個数比が係数の比」という合図で、per のステージでは嘘になる
- **＋ボタンは残す。** 倍入れれば2個目が変わる（`floor(total/per)`）ので、
  誇張であることを自分で確かめられる

⚠ **誇張であることは、どのステージも doneNote で必ず言う**（テストが `誇張` と `個に1個` を見張る）。
塩化アンモニウム側だけこの一文が無く、背中合わせの酢酸ナトリウム側と食い違っていたので v185 で足した。
**アプリが置くようにしたぶん、置かれた数が「本当の割合」と読まれる危険はむしろ増える**ので、
ここは弱めてはいけない。

### 電離度 α — ion で扱う。別ステージとして立てた（v167・実装ずみ）

α は「入れた分子のうち何個が分かれたか」＝**粒の数そのもの**なので、
数式ではなく画で見せられる。このアプリの土俵で、`per` がそのまま使えた。

**現行の弱酸ステージ（v38 酢酸×NaOH）には足さず、別ステージにした。** あちらは
「分子のまま溶け、中和のときだけ電離して補う（ルシャトリエ）」を見せる筋書きで、
そこへ常時の微小電離を混ぜると主筋がぼやける。かわりに、v38 が**電離を省いている**ことを
新ステージの doneNote で明かす。省略を回収しないと「酢酸は中和されるまで電離しない」と
覚えてしまうので、これは単なる補足ではなく必要な後始末。

実装で分かったこと2つ:

- **仕組みの名前が狭かった。** 加水分解と電離は化学としては別物だが、画面の上でやることは同じ
  （相手を待たず per 個に1個・残りはそのまま・矢印 ⇄・「ちょうど反応しきる」評価は当てない）。
  そこで `hydrolysisRule` を `partialRule`／`PARTIAL_KINDS`（hydrolysis・ionization）に広げた。
  **共通なのはそこまで**で、「加水分解で」なのか「電離して」なのか、見どころが液性なのか
  電離度なのかは kind で分ける
- **模範投入数を `answer` に手書きしていたのをやめた。** 加水分解の2ステージは
  `answer[0]` に per と同じ数を書いていたが、これは per を変えたときに片方だけ古くなって
  「模範どおり入れたのに何も起きない」になる。`sampleInputs(stage)` で per から**導く**ようにし、
  式を molecular / ionic に持つステージは top-level の `answer` を持たないことをテストで固定した
  （＝ answer は常に「反応式の係数」だけを意味する）

### pH の計算 — ion では扱わない（ratio 側の仕事）

pH ＝ −log[H⁺] は**計算**であって、粒を見て分かるものではない。
リポジトリの役割分担は「**ion は見る、ratio は計算する**」で、ratio はすでに
中和滴定を持っている。ion に対数の計算器を作るのは、この分担を崩すだけで得がない。

ただし現状は**どちらのアプリにも pH が無い**（ratio の収録は mol 計算・平均原子量・
反応の量的関係・中和滴定・熱化学の5つ）。**「ion がやらない」＝「ratio がもう持っている」
ではない**ので、ratio 側の宿題として残ることをここに明記しておく。
できたときの横断リンクは、既存どおり**式の照合**で自動的につながる（対応表は書かない）。

### 分子反応式を書かない反応がある（`noMolecular`）

塩化アンモニウムの加水分解は、この設計で初めて**分子反応式を持たない**ステージになった。
教科書の NH₄Cl ＋ H₂O ⇄ NH₃·H₂O ＋ HCl には NH₃·H₂O が要るが、(c) で決めたとおり
このアプリは **NH₃ と H₂O を別々に扱う**。水を外した NH₄Cl ⇄ NH₃ ＋ HCl は加熱の式で、
水の中では起きない。そこで切り替えボタンを出さず、**なぜ無いか**を画面に出す。

副作用として、式がイオンだけになるぶん登場種の導出が「NH₄Cl」を拾えず、
**入れる物質の名前で索引を引けなくなる**。reactions.json に `reagents`
（ビーカーに入れる試薬）を足し、導出側がそこも見るようにして塞いだ。
