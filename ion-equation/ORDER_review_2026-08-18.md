> 金属樹では通常イオン反応式で済ませるので④ではこの機能は不要です。

### N の着地（v184）と、H を直す側への申し送り

大きさは **`style.css` の `--now-size`（16px）ただ1つ**が持つ。使い方は2通り:

- **HTML の札** … `class="nowLabel"`（行いっぱいの帯にするなら `nowBanner` も足す）。
  index の 🎯 目標がこれ
- **SVG の見出し**（H はこちら） … `class="nowLabel"` を付ければ CSS が
  `font-size="11"` の presentation attribute に勝つ。ただし `figRecombineRow` は
  `capY` / `yTop` を数で置いて行送りを自分で計算しているので、
  **`nowLabelPx()`（schematic.js。redox.html も読んでいる）から px の数を読んで詰め直すこと**。
  クラスだけ付けると文字が大きくなったぶん粒に食い込む

色は触っていない（`.goal.acid` の暖色を巻き添えにしないため）。
H 側で色を変えたくなったら、同じように**より詳細度の高い規則を後ろに足す**形にすること。

### O の実態（統合レーンが調査）

**意図的な設計だった。** `model.js` のコメント:

> 加水分解は平衡で、**入れた塩のごく一部しか進まない**（0.1 mol/L の酢酸ナトリウムなら**1万個に1個**ほど）。
> 全部が加水分解する画を出すと嘘になるので、`rule.per` で「**5個に1個だけ分かれる**」とし、
> 残りがもとのイオンのまま残ることを画面に残す。

式は `ionic.answer = [1,1,1,1]`（係数1）で、`per: 5` は**画面の個数**。
**式の係数と、画面に置く個数が別物**という設計。

⚠ **ご指摘のとおり「5個で正解」と言われると係数が5に見える。**
**分けて見せるべき**（式の係数は 1／画面の個数は「見えるようにするための誇張」）。

⚠ **「模型は勝手に増やしてよい」に統合レーンも賛成。**
5個並べる作業自体に学びはなく、**「1万個に1個」を伝えるのが目的**なので、
**アプリが最初から多めに置いておく**方が筋。
