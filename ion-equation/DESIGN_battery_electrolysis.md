# B3: 電池・電気分解モードの設計（2026-08-04）

M5.5 の設計書。ユーザーとの合意: **操作の核は「電極の選択＋倍率合わせ」**。
2枚の金属板を自分で選び（イオン化傾向の差 → どちらが負極かを発見）、
既存の倍率合わせで e⁻ を回す。M5.5 の「イオン化傾向の予想モード」はこの中に吸収する。

収録範囲はダニエル電池（核）・電気分解・実用電池（鉛蓄・燃料＝第2弾）・
電気分解の量的計算（ratio 連携）。**実装順ではなく設計の範囲**。実装は §7 の順で刻む。

## 0. 設計の前提（守ること）

- **モデルは既存の枠を流用する**。半反応式（`HALF_REACTIONS`）× 倍率（`checkRedoxMultipliers`）
  → e⁻ 打ち消し（`combineHalves`）の3点セットは B3 でも無改修が原則。
  拡張は「データ追加」と「アニメ新規」に閉じる（redox-solution のときと同じ切り方）
- **判定は個数のみ**（e⁻ プール・待ちイオン・析出数）。座標は見た目専用
- **判断できない反応は候補に出さない**。電極の組み合わせで挙動が確言できないもの
  （合金・不動態・過電圧が効く系）は最初から選択肢に置かない
- 依存の向きは **ion-equation → ratio の一方向**のまま。量的計算は ratio 側に問題を持たせ、
  ion 側は「式の照合」で往復リンクを張るだけ（v110 の仕組みそのまま）

## 1. なぜ「電極の選択」が操作の核になるか

紙の学習で電池が難しいのは、覚えることが分業されているからではなく、
**「どちらの金属が溶けるか」を決める原理（イオン化傾向）と、
「e⁻ がどちらへ流れるか」（回路）と、「両極で何が起きるか」（半反応式）が
別々の章に見えている**からである。

このアプリの型は「操作 → 発見」。電極を**選ばせる**と、この3つが1本につながる:

1. 板を2枚選ぶ（例: Zn と Cu）
2. **イオン化傾向の大きいほうが e⁻ を出して溶ける**（＝負極）ことをアニメで発見
3. 同じ2枚でも**組み合わせを変えると負極が入れ替わる**（Cu は Zn と組めば正極、
   Ag と組めば負極）——この「相対性」が予想モードの本体
4. 倍率合わせは既存の型のまま: 負極の半反応式 ×a、正極 ×b、e⁻ が合えば電流が続く

## 2. 学習ループ（ダニエル電池・核）

1. **2枚の板を選ぶ** — 電極候補パレット（Mg・Zn・Fe・Cu・Ag）から2枚をスロットへ。
   同じ金属2枚も選べる（→ 電流が流れないことも発見のうち）
2. **予想** — 「どちらの板が溶けると思う？」を板のタップで宣言（宣言するまで再生できない）
3. **▶ つないでみる** — e⁻ が導線を通って流れるアニメ。
   - 予想が当たり: 負極の板から e⁻ が導線を**上って**正極側へ。負極が溶け、正極に析出/泡
   - 同じ金属2枚: e⁻ が動かない。「差がないと流れない」を画で見せる
   - 予想が外れ: e⁻ が予想と逆へ流れ、「イオン化傾向は Zn ＞ Cu。出しやすいほうが出す」
4. **倍率合わせ** — 既存 UI そのまま。Zn_ox ×1 ⇄ Cu_red ×1（ダニエル）、
   組み合わせによっては 1:2（Zn×Ag⁺）で e⁻ の数合わせが再登場する
5. **足し合わせ表示** — combineHalves の結果＋**電池式** `(−) Zn | ZnSO₄ aq | CuSO₄ aq | Cu (+)`
6. クリア = 予想的中（または2回目で修正）＋倍率が最簡整数比

### セパレータ（素焼き板・塩橋）の扱い

イオンの移動（SO₄²⁻ が負極側へ、Zn²⁺ が増える）は**アニメでは描くが、操作にはしない**。
「なぜ仕切りが要るか」は発展の読み物（折りたたみ）で1枚。
操作を電極選択と倍率に絞るのは、中和の「投入量」・酸化還元の「倍率」と同じく
**1モード1操作**の原則による。

## 3. モデル（model.js への追加。すべて純ロジック＋機械検証）

### 3-1. イオン化傾向の序列（**新設しない**。M6-A で実装済みのものを参照する）

> **【2026-08-08 修正】** この節は当初 `IONIZATION_SERIES` を B3 で新設する前提で書かれていたが、
> **M6-A（v147）が既に `model.js` に実装済み**で、しかも梯子（`REDOX_LADDER_ACID`）から
> 金属の対だけを抜き出して**導出**している。`DESIGN_redox_matching.md` §2-3 の
> 「原理データを二重に持たない。先に実装されたほうが元データを置き、あとから来たほうが参照する」
> に従い、**B3 は参照する側**。別に配列を持つと、順位を直したときに片方だけ古くなって黙って食い違う。
> 現在値は `["Mg","Al","Zn","Fe","H","Cu","Ag"]`（イオン化傾向の大きい順）で、
> 画面で「下半分は覚えているイオン化傾向そのもの」と言い切る根拠として M6 のテストが固定している。

B3 が新しく持つのは、**原理データではなく「電極として言い切れる範囲」の絞り込み**だけ:

```js
/* 電極として選べる金属。序列（IONIZATION_SERIES）とは別に持つ絞り込み。
   H … 金属でないので板にならない（序列には「境目」として載っている）
   Al … 表面のち密な酸化被膜のせいで板として素直に負極にならない（§0 のとおり候補に出さない） */
const BATTERY_ELECTRODES = ["Mg", "Zn", "Fe", "Cu", "Ag"]; // 大 → 小
```

- 負極の決定: `negativeOf(m1, m2)` = **序列**で先に出るほう。同じなら null（電流なし）
- 金属 → 半反応式: `halfOfMetal(metal, kind)`。命名の規則（"Zn"→"Zn_ox"）ではなく
  **対（couple）で引く**（H⁺/H₂ の還元式が `H_red` のように、id が元素名と一致しない対がある）
- **機械検証**（実装済み）: 電極候補が全部序列に載っていること・並びが序列どおりであること・
  H と Al が候補に入らないこと・**序列の側からは H と Al が消えていないこと**（B3 が元データを
  書き換えていないことの検査）・梯子を動かすと導出も動くこと（＝どこにも複製が無いことの検査）

### 3-2. 電池ステージ（新規）

```js
const BATTERY_STAGES = [
  { id: "b1", title: "ダニエル電池", metals: ["Zn", "Cu"],
    // 電解液は**役ではなく金属で引く**（下の【修正】を見よ）
    electrolyte: { Zn: "ZnSO4", Cu: "CuSO4" },
    intro: "…" },
  // b2: 金属の選択課題（metals を固定せず、パレットから2枚選ぶ出題。answer は選択に依存）
];
```

> **【2026-08-08 修正・実装 v158】** 2点だけ設計から変えた。
> 1. **`answer` と `cellDisp` はデータに持たず導く**（`composeStage` / `cellNotation`）。
>    「ステージに ox/red を直書きしない」と同じ理由で、電極を選び直したら倍率も電池式も
>    ついてこないと嘘になる。導出値はテストで文字列ごと固定してある。
> 2. **`electrolyte` のキーを役（neg/pos）から金属（Zn/Cu）へ**。役で持つと
>    「Zn が負極」をデータ側が先に決めてしまい、負極を `negativeOf` が決めるという核と食い違う。

> **【2026-08-08 追記・実装 v161】** b2（電極を選ぶ）で決めたこと。
> - **電解液は既定表（`ELECTRODE_ELECTROLYTE`）から引く**。b2 は組み合わせが決まらないので、
>   ステージ側に持たせようがない。ステージが明示していればそちらが勝つ（b1 は硫酸塩で固定）
> - **候補に出す相手は `batteryPartnersOf` が決める**。正極側の還元の式を収録していない組
>   （Mg×Zn・Mg×Fe・Zn×Fe）は §0 に従って選べなくする。「起きない」のではなく「扱わない」
> - **同じ金属2枚は選べるまま**にする。差がないと流れない、は言い切れる結論なので候補に残す
> - **相対性は先に言葉で言わず、遊んだ記録（`roleLog`）から出す**。両方の役をやった金属が
>   出たときだけ「発見」の帯が出る。現在の収録だと、これができるのは **Cu だけ**
>   （Zn²⁺/Fe²⁺ の還元式が無いため）
- 半反応式は**金属名から引く**（負極 = `Zn_ox`、正極 = 相手イオンの `Cu_red`）。
  ステージに ox/red の id を直書きしない——**電極を選び直したら式も差し替わる**のが核なので、
  式の解決は `halvesForPair(m1, m2)` に一本化する
- 倍率判定・足し合わせは `checkRedoxMultipliers` / `combineHalves` をそのまま呼ぶ
  （REDOX_STAGES と同じ形 `{ ox, red, answer }` に正規化してから渡す）

### 3-3. 電気分解（新規・電池の「逆向き」として同じ部品で）

電気分解は**外から e⁻ を押し込む**だけで、半反応式の文法は同じ。

```js
const ELECTROLYSIS_STAGES = [
  { id: "e1", title: "塩化銅(Ⅱ)水溶液の電気分解",
    cathode: "Cu_red",           // 陰極: Cu²⁺ + 2e⁻ → Cu（既存）
    anode:   "Cl_ox",            // 陽極: 2Cl⁻ → Cl₂ + 2e⁻（新規追加）
    answer: [1, 1],
    intro: "電源が e⁻ を押し込む。陰極に銅、陽極に塩素。" },
  { id: "e2", title: "水の電気分解（希硫酸）",
    cathode: "H_red",            // 既存
    anode:   "H2O_ox",           // 2H₂O → O₂ + 4H⁺ + 4e⁻（新規追加）
    answer: [2, 1] },
];
```

> **【2026-08-08 修正・実装 v162】** 3点だけ設計から変えた。
> 1. **`answer` はデータに持たず導く**（`electrolysisStageOf` が `composeStage` を呼ぶ）。
>    b1・b2 と同じ理由。導出値はテストで文字列ごと固定してある（e1 = 1:1、e2 = 1:2）。
>    ※ この設計書の `answer: [2,1]`（e2）は「陰極, 陽極」の順で書かれていた。
>    正規化したステージは既存の `{ ox, red, answer }` と同じ **[酸化側, 還元側]** の順なので、
>    実装では **[1, 2]**（陽極 ×1・陰極 ×2）になる。値そのものは同じ。
> 2. **`Cl2/Cl-` を梯子（`REDOX_LADDER_ACID`）に載せない**。電気分解は電源が押し込む反応で、
>    起こるかどうかは酸化還元の強さ比べでは決まらない。載せると自由組み立てモードが
>    「Cl⁻ は誰と反応するか」を勝手に答えてしまう。梯子は「載っている対に半反応式があること」
>    しか要求しないので、片方向の登録で足りる（テストで固定）。
> 3. **`H2O_red` は入れていない**（NaCl 水溶液の陰極用・第2弾のまま）。
>
> **HALF_REACTIONS への追加**（原子・電荷保存は既存テストが機械検証する）:

| id | 半反応式 | kind | e⁻ |
|---|---|---|---|
| `Cl_ox` | 2Cl⁻ → Cl₂ ＋ 2e⁻ | oxidation | 2 |
| `H2O_ox` | 2H₂O → O₂ ＋ 4H⁺ ＋ 4e⁻ | oxidation | 4 |
| `H2O_red` | 2H₂O ＋ 2e⁻ → H₂ ＋ 2OH⁻ | reduction | 2 |（NaCl 水溶液の陰極用・第2弾）

- 用語の切り替え: 電池は**負極/正極**、電気分解は**陰極/陽極**。
  データ属性は `cathode/anode` に統一し、**表示名だけ**モードで変える
  （負極=酸化 ⇄ 陰極=還元 という対応の混乱こそが頻出のつまずきなので、
  画面には常に「e⁻ が入ってくる極 / 出ていく極」の矢印を添える）
- **電極の選択問題は電気分解では出さない**（Pt/C の不活性電極前提。
  陽極が溶ける系＝銅の精錬は第2弾の読み物で扱い、操作にはしない）

### 3-4. 実用電池（第2弾・データだけ先に設計）

| id | 負極 | 正極 | 備考 |
|---|---|---|---|
| 鉛蓄電池 | Pb ＋ SO₄²⁻ → PbSO₄ ＋ 2e⁻ | PbO₂ ＋ 4H⁺ ＋ SO₄²⁻ ＋ 2e⁻ → PbSO₄ ＋ 2H₂O | **両極とも PbSO₄ になる**のが見どころ。充電は矢印を逆再生 |
| 燃料電池（リン酸形） | H₂ → 2H⁺ ＋ 2e⁻ | O₂ ＋ 4H⁺ ＋ 4e⁻ → 2H₂O | 倍率 2:1。「燃焼と同じ式・別経路」を C 群（燃焼）と対で見せられる |

- 鉛蓄電池は電極選択の枠に乗らない（Pb と PbO₂ は「選ぶ」対象ではない）ので、
  **ステージ固定・充放電の切り替え**という別 UI。ここが第2弾に回す理由
- 充電（電気分解として逆回し）は、電池⇄電気分解の対比の総仕上げに使える

### 3-5. 量的計算（ratio 連携・ion 側は式を持つだけ）

- **ファラデー定数・電気量（C = A×s）・mol 換算は ratio 側の問題**として持つ
  （ratio の設計思想「倍率が同じ」で解ける: 電気量 → e⁻ の mol → 係数比 → 析出量）
- ion 側は電気分解ステージの**イオン反応式**を出すだけ。ratio に同じ式の問題が増えれば、
  既存の `buildCrossAppIndex`（式の正準形での照合）が**自動で**往復リンクを張る。
  **対応表は書かない**（v114 で決めた方式のまま）
- ratio 側に Faraday の単位（C/mol）を足す必要がある。ratio の `QUANTITIES` 拡張として
  ratio 側の設計に1節を足す（このファイルでは範囲外・依存の向きを守る）

# B3-2: 電池と電気分解をモードに割り、電気分解に「何が反応するか」を足す（2026-09-07）

ユーザーの指示（原文）:

> 電池　と　電気分解　はモードを分ける
> 電気分解はまず、何が反応するか　を考えさせるものをつくる
> 反応する物質の優先順位を確認できるように／最終的に何にでも対応できるようにする／推奨で始めて様子をみてからでもよい

## 8. なぜ1枚を2枚に割るのか

§3-3 は「半反応式の文法だけが同じ」と書いたうえで、**1つのページに4ステージを並べていた**。
そろえること自体は正しかった（起きていることは同じで名前だけが違う、を絵で言う）が、
**入口としては1枚に混ざっている**のが問題だった:

- ステージの帯が `1 2 3 4` で、1〜2 が電池・3〜4 が電気分解。**帯の番号からは境目が見えない**
- `<title>` も modeTag も「電池と電気分解」。ハブ・ポータル・索引のどこから来ても
  「いま電池をやるのか電気分解をやるのか」が、開いてから帯を押すまで決まらない
- そして今回いちばん効くのが**段の数がモードで違う**こと。電気分解には
  「まず、何が反応するか」という**電池には存在しない段**が要る（§9）。
  1枚に同居させると、その段は「電池のときだけ消える段」になり、画面の骨格が2通りになる

**割るのは入口（ページ）だけで、エンジンは割らない。** §3-3 の

## 9. 「まず、何が反応するか」の段（新規・電気分解だけ）

### 9-1. 何を教える段なのか

★ **電極に来たイオンが、そのまま反応するとは限らない。**

- 陰極 … Cu²⁺・Ag⁺ は析出する。**Na⁺・K⁺・Ca²⁺・Mg²⁺・Al³⁺ は析出せず、H₂O が還元されて H₂**
- 陽極 … Cl⁻・I⁻ は Cl₂・I₂ に、OH⁻ は O₂ に。**SO₄²⁻・NO₃⁻・PO₄³⁻ は酸化されず、H₂O が酸化されて O₂**

つまずくのは「イオンが2種いるのに、水が割り込む」ところ。だから段の作りは
**「溶けているイオンを並べ、そこに H₂O を必ず1枚混ぜて、どれが反応するかを選ばせる」**。

### 9-2. 順位表は「覚える表」ではなく「確かめる表」

⚠ **順位を暗記させない。** 酸化還元モードの「自由に組み合わせる」が、
選んだあとに `▸ 梯子の全体を見る` で確かめる作りになっている（`redox.js` の
`buildLadderFull` / `renderWhy`）。**同じ流儀にそろえる**:

1. 選ぶ（陰極でどれ／陽極でどれ）
2. 当たり外れと、その1行の理由（「Na⁺ は水より下 ＝ 水溶液では還元されない」）
3. `▸ 反応する順番の表を見る` を押すと、はじめて順位表の全体が開く（既定は閉じたまま）

### 9-3. データの形（model.js・純ロジック）

**画面に表を手書きしない。** 表は1つのデータで、判定も表示もそこから導く。

```js
const ELECTRODE_PRIORITY = {
  cathode: [ /* 上ほど「先に還元される」 */
    { id: "noble-cation", label: "イオン化傾向が H₂ より小さい金属のイオン",
      members: ["Ag+", "Cu^2+"], half: { "Ag+": "Ag_red", "Cu^2+": "Cu_red" } },
    { id: "acid-h",  label: "酸の H⁺",  members: ["H+"],  half: { "H+": "H_red" } },
    { id: "water",   label: "水 H₂O",   members: ["H2O"], half: { "H2O": "H2O_red" } },
    { id: "active-cation", label: "イオン化傾向が大きい金属のイオン（K〜Al）",
      members: ["K+","Ca^2+","Na+","Mg^2+","Al^3+"], half: null },   // ← half が無い＝反応しない
  ],
  anode: [ /* 上ほど「先に酸化される」 */ … ],
};
```

- **`half` を持たない段が「反応しない」の唯一の表現**。真偽値を別に持たない
  （持つと、式を足したのに「反応しない」が残る、が起こる）
- 判定は `electrolysisPick(kind, solution)` 1本。
  溶液 → `DISSOCIATION` でイオンに開き、**そこへ必ず `H2O` を足して**、
  上から見て「その極の符号に合う・表に載っている・`half` を持つ」最初のものを採る
- 返り値は `{ sp, half, tier, rows }`。`rows` が**そのまま順位表の描画データ**になる
  （どの段にいま何がいるか・どれを採ったか・どれを飛ばしたか）
- ステージの `anode` / `cathode` は**残す**が、**`electrolysisPick` の結果と一致することを
  回帰テストが見張る** ＝ 表とステージが食い違ったら赤くなる。
  （データを消して導出だけにしなかったのは、既存テストが `st.anode` を見ているのと、
  「この電気分解では何が起きるか」を読むのにデータ1行のほうが速いため）

### 9-4. 収録（白金／炭素電極の水溶液・6件）

★ 選び方の条件は **「陽イオンがそのまま反応する／しない」×「陰イオンがそのまま反応する／しない」の
4通りが全部出ること**。

| id | 溶液 | 電極 | 陰極 | 陽極 | 4通りの型 |
|---|---|---|---|---|---|
| e1 | CuCl₂ aq | C | Cu²⁺ → Cu | 2Cl⁻ → Cl₂ | **する × する** |
| e2 | 希 H₂SO₄ | Pt | 2H⁺ → H₂ | H₂O → O₂ | する × しない |
| e3 | NaCl aq | C | **H₂O → H₂**（Na⁺ は不可） | 2Cl⁻ → Cl₂ | **しない × する** |
| e4 | CuSO₄ aq | Pt | Cu²⁺ → Cu | **H₂O → O₂**（SO₄²⁻ は不可） | **する × しない** |
| e5 | Na₂SO₄ aq | Pt | **H₂O → H₂** | **H₂O → O₂** | **しない × しない** |
| e6 | NaOH aq | Pt | **H₂O → H₂** | 4OH⁻ → O₂ | しない × する |

- 「する」の中身は析出とはかぎらない（e2 の H⁺ は気体になる）。だから軸の名前は
  **「そのまま反応するか」**にしてある。析出／気体の別は生成物の性質から画が決める
- **e5 だけ、足し合わせた式に H⁺ と OH⁻ が残る**（6H₂O → O₂ ＋ 2H₂ ＋ 4H⁺ ＋ 4OH⁻）。
  `combineHalves` は同じ種しか打ち消さないので当然だが、**これは誤差ではなく実際に起きること**
  ——陽極のまわりは酸性に、陰極のまわりは塩基性になる。かき混ぜれば H⁺ と OH⁻ が
  結びついて水に戻り、教科書の 2H₂O → 2H₂ ＋ O₂ になる。ステージに `sumNote` を持たせて
  足し合わせの下で断る（**黙って出さない**）
- HALF_REACTIONS への追加は2本だけ: `H2O_red`（2H₂O ＋ 2e⁻ → H₂ ＋ 2OH⁻・§3-3 の宿題）と
  `OH_ox`（4OH⁻ → O₂ ＋ 2H₂O ＋ 4e⁻）。**どちらも梯子には載せない**（`Cl_ox` と同じ理由）
- **銅電極（電解精錬）は入れない**（§10）

### 9-5. 段の並び（電気分解のページ）

```
1 何が反応する？   ← 新規（electrolysis.js）。答えるまで下の段は出ない
2 電源につなぐ     ← 図・アニメ（cell.js。旧 stepPredict）
3 両極の半反応式と倍率
4 足し合わせて e⁻ を消す
```

- `cell.js` は「先に済ませる段」を1つだけ差し込める口（`window.CellPreStep`）を持つ。
  無ければ今までどおり ＝ **電池のページは1文字も変わらない**
- 足し合わせの見出し番号は `#calcSheet` の `data-step-no` で決める（電池 3・電気分解 4）

## 10. 「電極そのものが反応する」枠を、あとから足すのに要るもの

ユーザーの「最終的に何にでも対応できるようにする」に対する宿題の目録。
今回は入れていないが、**入れるときに何が要るか**をここに書いておく。

対象は銅の電解精錬（陽極 Cu → Cu²⁺ ＋ 2e⁻）・水酸化ナトリウムの製造（陽イオン交換膜法）・
めっき。共通するのは **「陽極が溶ける」＝ 電極が反応物になる**こと。

1. **順位表にもう1段いる**。いまの `ELECTRODE_PRIORITY.anode` は
   「液に溶けているものの順位」しか持っていない。電極が溶ける系では
   **陰イオンより先に電極が酸化される**ので、表のいちばん上に
   `{ id:"active-electrode", label:"電極そのもの（Cu・Ag など不活性でない電極）" }` が要る。
   ここに載せると `electrolysisPick` の走査は今のままでよい（上から見るだけ）
2. **候補に電極を混ぜる**。`electrolysisCandidates` はいま `DISSOCIATION[solution] ＋ H2O` だけ。
   ステージの `electrode` が不活性（C・Pt）でなければ、その金属を候補に足す
   ＝ **「何が反応するか」の問いに電極そのものが並ぶ**（これが体験の核になる）
3. **`INERT_LOOK` の対になる `ACTIVE_LOOK` と、陽極が痩せる絵**。いまの図は電極を
   反応に参加しない棒として描いている（`class="plateBody inert"`）。
   溶ける陽極は、電池の負極の板と同じ描き方（`METAL_STYLE`）に寄せられる
4. **陽極泥（不純物）を描くかどうかの判断**。電解精錬の見どころは
   「Ag・Au は溶けずに沈み、Fe・Zn は溶けたまま析出しない」＝ **イオン化傾向の応用**で、
   これは順位表の話に戻る。**ただし §0「判断できない反応は候補に出さない」に触れる**
   （どこまで言い切るかを先に決める必要がある）
5. **半反応式は追加が要らない**。`Cu_ox`（Cu → Cu²⁺ ＋ 2e⁻）も `Cu_red` も既にある。
   足りないのは表と絵だけ、というのが今回いちばん確かめられたこと

## 11. ポータルの並び（単元順）

「やりたいことから入る」の札を、ユーザーの決定どおり単元で束ねて並べ直す。

| 単元 | 札 |
|---|---|
| ① 化学反応式の係数合わせ | 🧪 無機の沈殿と錯イオン形成 ／ ⚗️ 中和で沈殿ができる式 |
| ② 酸と塩基 | ⚗️ 中和と弱酸の遊離の仕組み |
| ③ 酸化還元 | 🔢 酸化数 → ⚡ 半反応式 → ⚖️ 液性 → 🎓 組み立て → ⚗️ 自分で選ぶ → 🔋 電池 → ⚡ 電気分解 |
| （単元の外） | 🔎 反応インデックス |

★ ③ の中は **部品 → 組み立て → 応用** の順（酸化数・半反応式・液性が部品、組み立てと
自分で選ぶが組み立て、電池と電気分解が応用）。これは発注書の並びをそのまま採った。

★ **中和は ① と ② の両方に出す**（ユーザー決定「両方にあってもよい」）。
ただし**同じ札を2枚並べない**。着目点が違うことが札から読めるようにする:

- ② の札 …「中和と弱酸の遊離の**仕組み**」＝ H⁺ と OH⁻ が結びつく、を見る
- ① の札 …「中和で**沈殿ができる**式」＝ 硫酸 × 水酸化バリウム（s8）に直接入る。
  同じ反応でも **BaSO₄ ができることに着目すると係数合わせの問題になる**、を札の文で言う

ユーザーの言葉:「BaSO4 は出題の仕方による／Ba(OH)2 と H2SO4 の中和に着目するなら酸塩基／
BaSO4 の生成に着目するなら沈殿」——**同じ反応が2つの単元に出る**のは、
このアプリではもともと `CURRICULUM`（重なる分類）が扱ってきたことで、
札の側でもそれを見せる、というだけの話。
