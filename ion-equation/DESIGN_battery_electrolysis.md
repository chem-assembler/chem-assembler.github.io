# B3: 電池・電気分解モードの設計（2026-08-04）

M5.5 の設計書。ユーザーとの合意: **操作の核は「電極の選択＋倍率合わせ」**。
2枚の金属板を自分で選び（イオン化傾向の差 → どちらが負極かを発見）、
既存の倍率合わせで e⁻ を回す。M5.5 の「イオン化傾向の予想モード」はこの中に吸収する。

収録範囲はダニエル電池（核）・電気分解・実用電池（鉛蓄・燃料＝第2弾）・
電気分解の量的計算（ratio 連携）。**実装順ではなく設計の範囲**。実装は §7 の順で刻む。

## 0. 設計の前提（守ること）

- **モデルは既存の枠を流用する**。半反応式（`HALF_REACTIONS`）× 倍率（`checkRedoxMultipliers`）
  → e⁻ 打ち消し（`combineHalves`）の3点セットは B3 でも無改修が原則。
  拡張は「データ追加」と「アニメ新規」に閉じる（redox-solution のときと同じ切り方）
- **判定は個数のみ**（e⁻ プール・待ちイオン・析出数）。座標は見た目専用
- **判断できない反応は候補に出さない**。電極の組み合わせで挙動が確言できないもの
  （合金・不動態・過電圧が効く系）は最初から選択肢に置かない
- 依存の向きは **ion-equation → ratio の一方向**のまま。量的計算は ratio 側に問題を持たせ、
  ion 側は「式の照合」で往復リンクを張るだけ（v110 の仕組みそのまま）

## 1. なぜ「電極の選択」が操作の核になるか

紙の学習で電池が難しいのは、覚えることが分業されているからではなく、
**「どちらの金属が溶けるか」を決める原理（イオン化傾向）と、
「e⁻ がどちらへ流れるか」（回路）と、「両極で何が起きるか」（半反応式）が
別々の章に見えている**からである。

このアプリの型は「操作 → 発見」。電極を**選ばせる**と、この3つが1本につながる:

1. 板を2枚選ぶ（例: Zn と Cu）
2. **イオン化傾向の大きいほうが e⁻ を出して溶ける**（＝負極）ことをアニメで発見
3. 同じ2枚でも**組み合わせを変えると負極が入れ替わる**（Cu は Zn と組めば正極、
   Ag と組めば負極）——この「相対性」が予想モードの本体
4. 倍率合わせは既存の型のまま: 負極の半反応式 ×a、正極 ×b、e⁻ が合えば電流が続く

## 2. 学習ループ（ダニエル電池・核）

1. **2枚の板を選ぶ** — 電極候補パレット（Mg・Zn・Fe・Cu・Ag）から2枚をスロットへ。
   同じ金属2枚も選べる（→ 電流が流れないことも発見のうち）
2. **予想** — 「どちらの板が溶けると思う？」を板のタップで宣言（宣言するまで再生できない）
3. **▶ つないでみる** — e⁻ が導線を通って流れるアニメ。
   - 予想が当たり: 負極の板から e⁻ が導線を**上って**正極側へ。負極が溶け、正極に析出/泡
   - 同じ金属2枚: e⁻ が動かない。「差がないと流れない」を画で見せる
   - 予想が外れ: e⁻ が予想と逆へ流れ、「イオン化傾向は Zn ＞ Cu。出しやすいほうが出す」
4. **倍率合わせ** — 既存 UI そのまま。Zn_ox ×1 ⇄ Cu_red ×1（ダニエル）、
   組み合わせによっては 1:2（Zn×Ag⁺）で e⁻ の数合わせが再登場する
5. **足し合わせ表示** — combineHalves の結果＋**電池式** `(−) Zn | ZnSO₄ aq | CuSO₄ aq | Cu (+)`
6. クリア = 予想的中（または2回目で修正）＋倍率が最簡整数比

### セパレータ（素焼き板・塩橋）の扱い

イオンの移動（SO₄²⁻ が負極側へ、Zn²⁺ が増える）は**アニメでは描くが、操作にはしない**。
「なぜ仕切りが要るか」は発展の読み物（折りたたみ）で1枚。
操作を電極選択と倍率に絞るのは、中和の「投入量」・酸化還元の「倍率」と同じく
**1モード1操作**の原則による。

## 3. モデル（model.js への追加。すべて純ロジック＋機械検証）

### 3-1. イオン化傾向の序列（新規・これが B3 の唯一の新しい「原理データ」）

```js
/* イオン化傾向の序列。**電極に選べる金属だけ**を持つ（Li〜Au の暗唱表を再現しない）。
   値は序列の index であって電位ではない（電位差の定量は扱わない。§6 の非目標）。 */
const IONIZATION_SERIES = ["Mg", "Zn", "Fe", "Cu", "Ag"]; // 大 → 小
```

- 負極の決定: `negativeOf(m1, m2)` = 序列で先に出るほう。同じなら null（電流なし）
- **機械検証**: 序列の全金属に `〜_ox` の半反応式と、対になる `〜_red` が存在すること。
  REDOX_STAGES / BATTERY_STAGES から参照される金属が序列に載っていること

### 3-2. 電池ステージ（新規）

```js
const BATTERY_STAGES = [
  { id: "b1", title: "ダニエル電池", metals: ["Zn", "Cu"],
    electrolyte: { neg: "ZnSO4", pos: "CuSO4" },   // 各槽の電解液（表示と電池式に使う）
    answer: [1, 1],
    cellDisp: "(−) Zn | ZnSO₄ aq | CuSO₄ aq | Cu (+)" },
  // b2: 金属の選択課題（metals を固定せず、パレットから2枚選ぶ出題。answer は選択に依存）
];
```

- 半反応式は**金属名から引く**（負極 = `Zn_ox`、正極 = 相手イオンの `Cu_red`）。
  ステージに ox/red の id を直書きしない——**電極を選び直したら式も差し替わる**のが核なので、
  式の解決は `halvesForPair(m1, m2)` に一本化する
- 倍率判定・足し合わせは `checkRedoxMultipliers` / `combineHalves` をそのまま呼ぶ
  （REDOX_STAGES と同じ形 `{ ox, red, answer }` に正規化してから渡す）

### 3-3. 電気分解（新規・電池の「逆向き」として同じ部品で）

電気分解は**外から e⁻ を押し込む**だけで、半反応式の文法は同じ。

```js
const ELECTROLYSIS_STAGES = [
  { id: "e1", title: "塩化銅(Ⅱ)水溶液の電気分解",
    cathode: "Cu_red",           // 陰極: Cu²⁺ + 2e⁻ → Cu（既存）
    anode:   "Cl_ox",            // 陽極: 2Cl⁻ → Cl₂ + 2e⁻（新規追加）
    answer: [1, 1],
    intro: "電源が e⁻ を押し込む。陰極に銅、陽極に塩素。" },
  { id: "e2", title: "水の電気分解（希硫酸）",
    cathode: "H_red",            // 既存
    anode:   "H2O_ox",           // 2H₂O → O₂ + 4H⁺ + 4e⁻（新規追加）
    answer: [2, 1] },
];
```

**HALF_REACTIONS への追加**（原子・電荷保存は既存テストが機械検証する）:

| id | 半反応式 | kind | e⁻ |
|---|---|---|---|
| `Cl_ox` | 2Cl⁻ → Cl₂ ＋ 2e⁻ | oxidation | 2 |
| `H2O_ox` | 2H₂O → O₂ ＋ 4H⁺ ＋ 4e⁻ | oxidation | 4 |
| `H2O_red` | 2H₂O ＋ 2e⁻ → H₂ ＋ 2OH⁻ | reduction | 2 |（NaCl 水溶液の陰極用・第2弾）

- 用語の切り替え: 電池は**負極/正極**、電気分解は**陰極/陽極**。
  データ属性は `cathode/anode` に統一し、**表示名だけ**モードで変える
  （負極=酸化 ⇄ 陰極=還元 という対応の混乱こそが頻出のつまずきなので、
  画面には常に「e⁻ が入ってくる極 / 出ていく極」の矢印を添える）
- **電極の選択問題は電気分解では出さない**（Pt/C の不活性電極前提。
  陽極が溶ける系＝銅の精錬は第2弾の読み物で扱い、操作にはしない）

### 3-4. 実用電池（第2弾・データだけ先に設計）

| id | 負極 | 正極 | 備考 |
|---|---|---|---|
| 鉛蓄電池 | Pb ＋ SO₄²⁻ → PbSO₄ ＋ 2e⁻ | PbO₂ ＋ 4H⁺ ＋ SO₄²⁻ ＋ 2e⁻ → PbSO₄ ＋ 2H₂O | **両極とも PbSO₄ になる**のが見どころ。充電は矢印を逆再生 |
| 燃料電池（リン酸形） | H₂ → 2H⁺ ＋ 2e⁻ | O₂ ＋ 4H⁺ ＋ 4e⁻ → 2H₂O | 倍率 2:1。「燃焼と同じ式・別経路」を C 群（燃焼）と対で見せられる |

- 鉛蓄電池は電極選択の枠に乗らない（Pb と PbO₂ は「選ぶ」対象ではない）ので、
  **ステージ固定・充放電の切り替え**という別 UI。ここが第2弾に回す理由
- 充電（電気分解として逆回し）は、電池⇄電気分解の対比の総仕上げに使える

### 3-5. 量的計算（ratio 連携・ion 側は式を持つだけ）

- **ファラデー定数・電気量（C = A×s）・mol 換算は ratio 側の問題**として持つ
  （ratio の設計思想「倍率が同じ」で解ける: 電気量 → e⁻ の mol → 係数比 → 析出量）
- ion 側は電気分解ステージの**イオン反応式**を出すだけ。ratio に同じ式の問題が増えれば、
  既存の `buildCrossAppIndex`（式の正準形での照合）が**自動で**往復リンクを張る。
  **対応表は書かない**（v114 で決めた方式のまま）
- ratio 側に Faraday の単位（C/mol）を足す必要がある。ratio の `QUANTITIES` 拡張として
  ratio 側の設計に1節を足す（このファイルでは範囲外・依存の向きを守る）

## 4. 画面（battery.html + battery.js 新規。model.js / style.css / header-ui.js 共用）

- redox.html の隣に置く**新ページ**。redox.js への相乗りはしない
  （ビーカー1槽 vs 2槽＋導線で描画の前提が違いすぎる。schematic.js の共用は可）
- 構成: 上段 = 2槽のビーカー＋導線＋（電気分解では電源マーク）の現象アニメ／
  下段 = 数合わせビュー（既存共通基盤。項 → イオン＋e⁻ 粒）
- 電極パレットは**タップ標的 32px 以上**・ヘッダーは既存の帯（`.hscroll`）を使い増段しない。
  375px でヘッダー 120px 以下・横スクロールなしを `tools/check-mobile.mjs` で守る
- e⁻ の粒は**導線の中を**流す（redox の「板の上にたまる」と描き分ける。
  電池で最も誤解されるのは「電流の向きと e⁻ の向き」なので、導線上に両方の矢印を常設）
- `window.BatteryEq.advance(ms)` フック（redox と同じ流儀）で UI テスト駆動

## 5. 検証（test.html への追加）

- モデル: 序列と半反応式の整合／`negativeOf` の全組み合わせ（5C2=10 ＋ 同種5）／
  電気分解ステージの保存則／combineHalves の結果が釣り合うこと（既存の仕組みに乗る）
- UI: 電極選択 → 予想 → 再生 → 倍率 → クリアの一連／同じ金属2枚で「流れない」／
  予想が外れたときの矢印逆転／用語（負極⇄陰極）の表示切り替え
- 監査（audit.js）: 全電極ペア×倍率のファズ（原子の保存・アニメが止まらない）

## 6. 非目標（やらないと決めたこと）

- **電位・起電力の定量**（標準電極電位の数値、ネルンスト式）— 序列の「差」までにする。
  高校範囲でも数値は要求されないうえ、数値を出すと序列暗記が電位暗記にすり替わる
- **過電圧・分極・局部電池** — 確言できない挙動は候補に出さない原則のとおり
- **ボルタ電池** — 分極の説明なしには「なぜすぐ止まるか」が嘘になる。
  歴史の読み物としてなら第2弾で1枚
- 塩橋/素焼き板の**操作化**（§2）・電極選択の電気分解版（§3-3）

## 7. 実装の刻み（1歩=1コミットの目安）

1. モデル: IONIZATION_SERIES＋negativeOf＋halvesForPair＋機械検証（画面なし）
2. battery.html の骨格＋電極パレット＋予想 UI（アニメなし・判定だけ）
3. e⁻ が導線を流れるアニメ＋倍率合わせの接続（b1 ダニエルが遊べる）
4. b2 電極選択課題（パレット自由選択・相対性の発見）
5. 電気分解 e1・e2（電源マーク・用語切り替え）
6. portal / library / ハブ単元表への接続（u-battery 単元を CURRICULUM に追加）
7. ratio 側の電気量問題（別レーン・ratio の設計に従う）→ 横断リンクは自動
8. 第2弾: 鉛蓄・燃料・充放電切り替え
