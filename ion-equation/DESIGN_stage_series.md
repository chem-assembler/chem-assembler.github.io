## 1. 症状

| モード | 画面 | ステージ数 | 帯に出るもの |

## 2. ⚠ 先に確かめたこと（索引を新設する前に）

このアプリには**すでに索引が2つある**。3つ目を作らないために、まず両方を読んだ。

### 2-1. `portal.html`（☰ 単元から入る）＋ `CURRICULUM`

- **正体**: 科目（化学基礎／化学）→ 単元（14 個）→ ステージ、の3段ツリー。
  所属は `STAGE_TAGS`（イオン反応）と id 直指定（酸化還元・液性）から `stagesOfUnit()` が引く。
- **良いところ**:
  - 所属を**データから導いている**（ステージを足してもタグさえ付ければ勝手に増える）
  - 「全ステージがどこかの単元に入る」を**機械で見張っている**（tests.js）
  - 単元 id がそのままアンカーで、ハブから `portal.html#u-gas` で着地できる
- **⚠ 系列としては使えない理由（決定的）**:
  **`CURRICULUM` は「重なる分類（cover）」であって「分け方（partition）」ではない。**
  - `s8`（硫酸 × 水酸化バリウム）は `u-neutral` と `u-precip` の**両方**に出る
  - `s11`（酸性塩をつくる）は `u-neutral` と `u-salt` の**両方**に出る
  - `cu-nh3-step1` は `u-precip`・`u-complex` の**両方**に出る
  ＝ 「このステージは何の仲間か」を**1つ**答えられない。
  帯や見出しに札を1枚だけ貼りたいときに使えるのはこれではない。
  - さらに 14 単元は**粒が細かすぎる**。ユーザーが言っているのは「酸塩基・沈殿・燃焼」の
    5 個ぐらいの粒で、単元はその下の刻み。
- **もう1つの穴**: `CURRICULUM` は **電池・電気分解の4ステージを含んでいない**
  （`stagesOfUnit` が `ion` / `redox` / `condition` の3モードしか引かない）。
  62 のうち 58 しか単元から辿れない。

### 2-2. `library.html`（🔎 反応インデックス）

- **正体**: `reactions.json`（56 件）の**辞書引き**。物質名で検索し、
  「反応の型」「塩の分類」「難易度」で絞り込む。隣のアプリ（比例式でみる化学計算）へも渡す。
- **⚠ 系列としては使えない理由**: **粒度も母数も違う。**
  - 母数が**反応**（56 件）であってステージ（62 個）ではない。
    まだ遊べない参照だけの反応も載るし、逆に電池・電気分解・液性のステージは載っていない
  - 「反応の型」（中和／沈殿／気体発生／酸化還元／錯イオン生成／分子反応）は系列に近いが、
    これも1反応が1型で、**ステージ番号とは結びついていない**
  - こちらは「式から引く」道具で、「順番に練習する」道具ではない

### 2-3. 発注書 F の `isOrganicStage`（v187）

- **正体**: `ORGANIC_OXIDANTS` に酸化される側の半反応式が載っているかで、
  酸化還元ステージ 8〜12 を「有機（発展）」と判定する。
- **手本にする**: 一覧を手で並べず、**すでにあるデータから導いている**。系列も同じ流儀にする。
- **⚠ ただし軸が違う**: これは**難度**の軸（基礎／発展）で、**系列**（酸塩基・沈殿…）とは直交する。
  有機の酸化は「発展」だが、系列としては**酸化還元**そのもの。**片方に寄せてはいけない。**

### 2-4. 判断 — **新設は「区分の情報」だけ。索引のページは新設しない**

| | 決定 |
|---|---|
| 索引の**ページ** | **新設しない。** `portal.html` に区画を1つ足して育てる |
| `library.html` | **触らない。** 目的（式から引く辞書）が違う |
| `CURRICULUM` | **残す。** 教科書の単元＝重なってよい分類として、そのまま育てる |
| **系列** | **新設する**（`STAGE_SERIES`）。ただし所属は `STAGE_TAGS` から導く |

**系列を新設する理由は1つだけ**: **既存の分類はどれも「重なる」ので、
「このステージは何の仲間か」に1つで答えられない。**
帯・見出し・索引に札を1枚貼るには、重なりのない分け方（partition）がいる。
`CURRICULUM` を partition に作り替えると、
「s8 は中和の単元にも沈殿の単元にも出てほしい」という今の良さが壊れる。
**だから2つを別のものとして持ち、役割を書き分ける。**

| | 系列（新） | 単元（`CURRICULUM`・既存） |
|---|---|---|
| 分け方 | **重ならない**。1ステージ＝1系列 | **重なる**。1ステージが複数の単元に出る |
| 粒 | 5 個 | 14 個 |
| 母数 | **62 ステージ全部**（電池・電気分解も含む） | 58 ステージ |
| 使いみち | 「いま何の仲間を練習しているか」 | 「教科書のこの単元をやりたい」 |

## 3. 系列（5 本）

⚠ **番号は変えない。** ユーザーは「31」「18-21」「34-」と通し番号で呼んでいる。
系列は**番号の上に重ねる**だけで、並べ替えはしない。

| id | 名前 | 入るもの | 件数 |
|---|---|---|--:|
| `sr-acid-base` | 酸と塩基 | 中和・弱酸の遊離・加水分解・電離平衡 | 19 |
| `sr-precipitate` | 沈殿と溶解 | 沈殿・錯イオン・両性水酸化物・沈殿の再溶解 | 14 |
| `sr-molecule` | 分子の組み換え | 燃焼・化合（イオンにならない反応） | 7 |
| `sr-redox` | 酸化還元 | 酸化還元モード全部＋液性モード全部 | 18 |
| `sr-cell` | 電池・電気分解 | 電池モード全部 | 4 |

合計 62。

### 3-1. どうやって決めるか（データから導く）

**手で id を並べた一覧は作らない。** 判定は次の1本だけ:

```
seriesOfStage(mode, stage)
  1. STAGE_SERIES を**上から順に**見る
  2. その系列が modes に mode を持っていれば、それに決まる（redox / condition / cell）
  3. その系列の tags のどれかが STAGE_TAGS[stage.id] にあれば、それに決まる（ion）
  4. どれにも当たらなければ null を返す ＝ テストが赤になる
```

- イオン反応モードは **`STAGE_TAGS` の再利用**。系列のための札を新しく貼らない。
  `STAGE_TAGS` は既に `CURRICULUM` が使っていて手入れされている表なので、
  「系列だけ更新し忘れる」経路がそもそも生まれない。
- 他の3モードは**どの配列に入っているか**で決まる。ここは導出というより事実そのもの。
- **並び順が優先順位**。重なったときは上の系列が勝つ（下記 3-2）。

### 3-2. ⚠ 唯一の重なり: ステージ 8（`s8` 硫酸 × 水酸化バリウム）

`s8` はタグが `中和 / 沈殿 / 正塩` で、**中和と沈殿が同時に起きる**（題も「中和＋沈殿」）。
化学として本当に両方なので、これは分類のミスではなく**事実の重なり**。

**決定: 酸と塩基に入れる。**
理由は、7（硝酸 × 水酸化カリウム）と 8 が並んでいるのは中和の練習の流れの中であり、
沈殿そのものを見せる回は 4・5・9 が別に用意されているから。
沈殿ができることは題（「中和＋沈殿」）と単元（`u-precip` にも出る）が受け持つ。

⚠ **ここは規則で決めている**（`STAGE_SERIES` の並び順）**のであって、s8 を名指ししていない。**
将来「中和かつ沈殿」のステージが増えても同じ扱いになる。

### 3-3. どこにも入らなかったステージ

**なし**（62 / 62）。ただし電池・電気分解の4本は「タグから導いた」のではなく
「電池モードのステージだから」で入っている（3-1 の 2.）。

## 4. 難度の軸（基礎／発展）との同居

⚠ 発注書の指示: **系列と難度は別の軸。喧嘩させないこと。**

**両方を同時に見せる。寄せない。**

- **系列 = 区画（行のまとまり）**。索引ではステージが系列ごとの箱に入る
- **難度 = 札（チップの上のバッジ）**。`isOrganicStage()` が真のステージに「有機（発展）」を貼る

酸化還元の系列を開くと、14 本のうち 8〜12 の 5 本にだけ札が付いている ＝
「同じ酸化還元の仲間だが、ここから先は発展」が一目で分かる。
系列を「基礎の酸化還元」「有機の酸化」に割らないのは、
**割ると 8〜12 が酸化還元の仲間から抜けてしまう**から（有機の酸化は酸化還元そのもの）。

⚠ **札の文字は `redox.js` の `ORGANIC_TAG` と1文字も違えない。**
`redox.js` は別レーンが触っているので**参照しに行かず**、索引側で同じ文字列を持ち、
**両者が一致することをテストで見張る**（食い違ったら赤）。

## 5. 出すところ

⚠ このレーンが触ってよいのは `portal.html` / `portal.js` / `model.js` の区分部分 /
`style.css` の追加規則だけ（`app.js`・`redox.js`・`header-ui.js` は別レーンが作業中）。
そのため**今回入れるのは索引ページの区画まで**。

### 5-1. `portal.html` — 「系列から入る」区画（今回）

役割カードの下、単元ツリーの**上**に置く。上から「やりたいこと → 仲間 → 教科書の単元」と
粒が細かくなっていく並びになる。

- 系列ごとに箱を1つ。箱の見出しに**系列名＋件数**、下に一言の説明
- 中はステージのチップ。チップには**アプリの帯と同じ番号**と**ステージ名**を出す
  —— 番号とステージ名が並ぶ場所は、今までどこにも無かった（帯は番号だけ、
  ☰一覧はモードを開かないと見えない）。「31 を見て」と言われたときにここで引ける
- 発展のステージには札を1枚（4章）
- 系列 id はそのままアンカー（`portal.html#sr-precipitate` で着地できる。単元と同じ流儀）

⚠ **電池・電気分解のチップだけは、ステージを名指しできない。**
`battery.js` は URL パラメータを見ていない（`app.js` の `?rxn=`、`condition.js` の `?s=` に当たるものが無い）。
当面は**モードのページへ送り、番号は出す**（「4 を押す」が分かる）。
battery.js に `?s=` を足すのは別レーンの領分なので、宿題として DEVELOPMENT.md に残す。

### 5-2. 将来（このレーンの外）

- **帯の番号を系列で色分けする**（`app.js` / `redox.js` の `buildStageNav`）。
  F の `organic` 印と同じ作りで乗せられる
- **☰ 一覧を系列ごとに区切る**（`header-ui.js`）。
