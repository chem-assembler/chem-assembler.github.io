# 価数＝高さのブロック（DESIGN_ion_blocks.md）

2026-09-07・レーン `ion-blocks`。**共有部品を1つ作る**ための設計書。
実装は `model.js`（純ロジック）＋ `blocks.js`（描画）＋ `tests.js`（回帰）。

---

## 0. なにを作るか（ユーザーの言葉）

> ⑥追加
> 右辺で余ったイオン同士を組み合わせる
> まだ作っていないが、イオン結晶の組成式を作らせる要領
> ②のようにブロックパズル的に数合わせさせるのがよさそう
> イオンの一覧から陽イオンと陰イオンを選んで並べ・高さがそろえば１つの化学種

> 化学反応式を完成させよう
> − 1 ＋ Ba²⁺ ＋ − 1 ＋ SO₄²⁻ → − 1 ＋ BaSO₄
> 価数を高さにしたブロックをつくり、高さ合わせをする

> イオン反応　左がわの模式図
> 最小公倍数でないときに、インストラクションが必要
> 酸と塩基の比はあっているが、もっと簡単な整数比にできる

この3つは**同じ1つの部品**を指している。

- 「高さ ＝ 価数」…… 3価の陽イオンは3段の高さのブロックになる。
- 「そろえる」…… 陽イオン側の総高さと陰イオン側の総高さを等しくする。
  等しい ＝ 電荷が打ち消し合う ＝ **中性の化学種が1つできる**。
- 「最小公倍数でないとき」…… そろっていても最簡とは限らない。
  Fe³⁺ 4個（12）と SO₄²⁻ 6個（12）はそろっているが、2で割れる。
  **ここを「まだ違う」と叱らず、「合っているが、もっと簡単にできる」と言い分ける**のが要点。

## 1. 三値であること（この設計のいちばんの決め）

判定は ○ / × の二値ではなく**三値**にする。

| 状態 | 例（Fe³⁺ と SO₄²⁻） | 言うこと |
|---|---|---|
| **そろっていない** `short` | 陽 1個(3)・陰 1個(2) | 「まだそろっていない。陰イオン側があと1ぶん低い」 |
| **そろったが最簡でない** `reducible` | 陽 4個(12)・陰 6個(12) | 「**高さはそろっています。でも、もっと簡単な整数比にできます**（4 : 6 → 2 : 3）」 |
| **そろった（最簡）** `simplest` | 陽 2個(6)・陰 3個(6) | 「そろった！ Fe₂(SO₄)₃」 |

⚠ 二値だと `reducible` が「×（違う）」に落ちる。
そこで学習者は**そろえ直そうとする**が、そろっているので何をしても直らない。
やることは「割る」であって「積み替える」ではない —— それを言えるのが三値の値打ち。

（同じ言い分けは既に `checkStageCoeffs` と `simplestRatioAdvice` が持っている。
新しい考え方ではなく、**ブロックの側にも同じ口を付ける**という話。）

## 2. 表を手で書かない

- **高さは `SPECIES[sp].charge` の絶対値**。価数表を新設しない。
- **最簡の組は `saltUnit(cation, anion)`**（電荷の最小公倍数から出る。既にある）。
- **組成式は `SALT_FORMULA`**（既にある）。無い対では組成式を出さない（呼び出し側が渡すことはできる）。
- 電荷 0 のもの（H₂O・CO₂・I₂・析出した金属）は**組ませない**。`ionBlockRole` が `null` を返す。

⚠ `bottlePlan` まわりのロジックは1行も変えない。触るのは
**`SALT_FORMULA` に `Ba^2+|SO4^2-` → `BaSO4` の1行を足すこと**だけで、
これは既存の機械検査（tests.js の「BOTTLE: 塩の組成が電荷から導け、組成式の原子数と一致する」）が
そのまま検算する ＝ 釣り合わない塩を足しても黙って通らない。

## 3. 純ロジック（model.js）

```
ionBlockHeight(sp)            → 数（価数＝電荷の絶対値）。イオンでなければ 0
ionBlockRole(sp)              → "cation" | "anion" | null
ionBlockCheck(c, a, cn, an)   → 三値の判定（下の形）
ionBlockPairOf(stage)         → { cation, anion, product } | null
```

`ionBlockCheck` の返り値:

```js
{
  kind: "invalid"|"empty"|"short"|"reducible"|"simplest",
  ok,                  // kind === "simplest"
  balanced,            // 高さがそろっている（reducible も true）
  cation, anion, cn, an,
  cHeight, aHeight,    // 1個あたりの高さ（＝価数）
  cTotal, aTotal,      // 積んだ高さの合計
  diff,                // cTotal - aTotal（正なら陽イオン側が高い）
  unit,                // saltUnit の {cn, an}（＝最簡の組）
  times,               // そろっているとき最簡の何倍か（1 なら最簡）。そろっていなければ null
  formula,             // SALT_FORMULA から引ける組成式の種。無ければ null
  message              // 日本語の判定文（三値ぶん言い分ける）
}
```

⚠ **判定は個数だけで行う。** 座標・ピクセルは見た目専用（このリポジトリの設計原則）。
`cTotal = cn * cHeight`、`aTotal = an * aHeight` の2つの積だけで三値が決まる。

`times` の出どころ:
`cTotal === aTotal` なら、その合計は必ず lcm(|q⁺|,|q⁻|) の倍数になる（両方の価数の公倍数だから）。
だから `times = cTotal / lcm` で、`times === 1` が最簡。**gcd を別に取らなくてよい。**

## 4. 描画（blocks.js・新ファイル）

`schematic.js` の流儀（DOM を作る関数だけを置き、化学の判断は持たない）に合わせる。

- 左に陽イオンの列、右に陰イオンの列。**共通の底辺から上へ積む。**
- 1ブロックの高さ ＝ 価数 × `unitPx`。ブロックの中に1段ごとの仕切り線を引く
  ＝ **高さが数えられる**（「3価」と字で書くだけにしない）。
- 各列の天井に破線を1本ずつ、図の幅いっぱいに引く。
  - **そろっていない**…… 破線が2本に割れて見える。その隙間を斜線で塗り「あと N」と書く。
  - **そろった**…… 破線が1本に重なり、緑になって「そろった」と出る。
    ★ **判定文を読む前に、線が1本か2本かで分かる**。これが図の値打ち。
  - **最簡でない**…… 線は1本（そろっている）が、色を橙にして「割れる」と伝える。
    ⚠ ここを赤（×）にしない —— そろっているのは事実なので。
- ブロックを押すと1つ減る。イオン一覧のボタンを押すと1つ積む。
  一覧で別のイオンを選ぶと、その列は選び直し（個数は1に戻る）。
- 色は呼び出し側の `look(sp) → { color, darkText, label }` に委ねる（`drawBlockSchematic` と同じ約束）。

### フック

```js
window.IonBlocks = {
  create(opts) → instance,   // 呼ぶたびに1つ作る
  last(),                    // 直近に作った instance（UI テストの入口）
  all(),                     // 生きている instance の配列
};
```

`instance`:

```js
instance.pick(side, sp)   // side: "cation" | "anion"
instance.add(side, n=1)
instance.remove(side, n=1)
instance.set({ cation, anion, cn, an })
instance.reset()
instance.state()          // ionBlockCheck の返り値 ＋ { cations, anions, unitPx }
instance.render()
```

`window.RedoxEq` と同型 ＝ **UI テストが iframe 越しに駆動できる**。

## 5. 組み込み（この版では1か所だけ）

イオン反応モードの「化学反応式を完成させよう」の下に**併置**する。

- 出す条件は**ステージ id で見張らない**（次にステージが増えたとき守られない）。
  `ionBlockPairOf(stage)` が「イオン反応式が 陽イオン ＋ 陰イオン → 中性の1種」の形だと言い、
  かつイオン反応式モードで、かつ**中和の模式図（`protonSchema`）が出ていない**とき。
  ⚠ 1つのステージに2つの図を並べない（`bottleStepOf` が `molecularEq` を避けているのと同じ決め）。
- ⚠ **いまのステッパー（`− 1 ＋`）は消さない。** ブロックと係数は**双方向**にする:
  ステッパーを動かせばブロックが積み替わり、ブロックを積めば係数が入る。
  **同じ数を2つの見え方で指している**ことが分かるのが、この版で見せたいこと。
  消すかどうかは、あとの「イオン反応モードの整理」レーンがユーザーの指示で決める。

該当するのは `s4`（Ag⁺＋Cl⁻→AgCl）・`s5`（Ba²⁺＋SO₄²⁻→BaSO₄）・
`amphoteric-al-step1`（Al³⁺＋3OH⁻→Al(OH)₃）など。
★ **Al のステージが 3 : 1 になる**ので、「高さがそろう」の値打ちがそこで見える。

## 6. あとで使う2か所（このレーンでは作らない）

1. **酸化還元モードの⑥**（`redox.js`・別レーン）……
   右辺で余ったイオンから塩を組ませる。`ionBlockPairOf` の代わりに
   「余ったイオンの一覧」を `cations` / `anions` に渡し、`formula` は `SALT_FORMULA` から出る。
2. **イオン反応モードの整理**（`app.js`・別レーン）……
   ステッパーとブロックのどちらを残すかを決める。

## 7. やらないこと

- 3種以上のイオンを同時に組ませない（1陽 × 1陰だけ）。
  複塩・錯塩はこの図法の外（`bottlePlan` が「陰イオンが2種以上」を断っているのと同じ理由）。
- 高さの単位を「電子1個」と言い切らない。ここで揃えているのは**電荷**であって、
  半反応式の e⁻ の授受（`schematic.js` の図）とは別の話。図を似せても言葉は分ける。
